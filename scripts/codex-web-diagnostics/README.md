# 网页桥接诊断补丁

为 Codex Web GPT（网页桥接工具）的 #358（文字块冲突）、#359（完成信号缺失）和 #360（发送超时）增加取证。只记录，不改变发送、正文匹配、完成判定或报错结果；故障本身仍需根据复现记录修复。

## 适用范围

- `codex-chatgpt-web` 6.1.2，Windows x64（64 位系统）。
- 目标：该版本的 `app/browser-helper.cjs`。
- 原文件 SHA-256（文件指纹）：`3d0f23940ce651968a45538fc0afcea2260a8bbafd94f1244515e41085d1a656`。
- 需要 Python（脚本运行工具）3.10 或以上；不安装依赖。
- 文件指纹不同、其他补丁已修改文件、软件名称或版本不匹配时停止，不能强行套用。

`conflict-diagnostic.js` 保存诊断代码，`conflict-diagnostic-v1.js` 用于识别最早的单问题补丁，`patch.py` 通过固定文件指纹和原始备份识别上一版三问题补丁，并负责应用、检查和撤回。补丁仅面向上述已核对的打包文件。

## 三类故障的取证位置和判断方法

### #358：已发送文字块冲突

在正文一致性检查抛错处记录 `markdownConflict.detail`（文字块冲突详情）：当前块、已发送块和相邻块的顺序、类型、来源范围、字符数、匿名内容与链接指纹；匹配依据、相同标识/类型/文字的候选数，以及最后待发送块。链接变化另外细分为网址协议、站点、路径、查询参数名称/内容和片段是否改变，记录两侧长度与是否截断，不记录地址本身。可据此区分真实改写、块移动、来源范围重叠、错误候选，以及仅链接参数变化。完整匿名匹配证据仅在冲突时计算，正常轮询只保存必要的块引用和选择结果。若修复必须查看私密正文或具体网址，须经用户允许另行取证。

另有 `markdownConflict.reconciliation`（完整匹配证据，格式版本 1）：保留最近一次正常匹配、首次冲突和本次最终冲突。每份状态保存当前段落、已输出段落和待输出段落的匿名输入，以及原程序实际返回的逐步选择。每步包含当前编号、候选编号与数量、选中编号、匹配依据、是否重复选中旧段落。前后状态使用同一轮专用密钥，可判断旧段落是否仍在原位、后续同文段落是否再次匹配它，以及标识是否变化。

每组最多保留 2000 个段落，每段最多 2000 个链接，每份状态最多 4000 步；候选编号最多保留 100 个并附实际总数。输入截断标记 `replayable=false`（不能完整重放），轨迹与候选截断分别标记，采集失败也明确报告。三个状态不构成完整网页历史。取证失败不改变原匹配算法的结果。

在仓库根目录离线重放：

冲突发生时还会立即写入同目录的 `reconciliation-live.json`（匹配冲突即时证据），不依赖最终网页取证。下面的重放命令也支持该文件。

```powershell
node scripts/codex-web-diagnostics/replay.cjs '失败日志文件的绝对路径'
# 可选第三个参数：lastConsistent、firstConflict、finalConflict（默认）。
```

重放运行仓库保存的 6.1.2 原始匹配代码，输出一致性、错误原因、待输出数量及对应表；拒绝缺失或截断的输入。匿名数据保留文字相同关系、空白判断及链接顺序，但不能重建回答。后续可据此对照候选修复，检查重复短句、真实移位、改写和标识变化。

### #359：页面已有回答但没有完成信号

在 60 秒停滞、任务完成和任务失败处记录 `completionDiagnostic`（完成判定详情）：回答字符数及匿名指纹、最后变动时间；目标回答是否为最新回答、每个回答块和整页的完成按钮数量；目标回答、相邻容器及整页按钮的控件结构。候选控件记录标签、角色、`data-testid`（测试标识）、类名、属性名称、五层父控件、是否在当前回答附近、是否可见或禁用，以及现有选择器是否命中。只有固定名单内的通用按钮名称和控件标识会原样记录；未知名称仅记录本轮匿名指纹与长度，不记录回答文字。若选择器完全没有命中，额外搜索整页并优先保留靠近回答的按钮。各候选集合都记录总数与保留数，避免截断被误当成“没有控件”。弹窗结构也保留。按钮远离回答、名称被隐私过滤或页面无法读取时，仍可能需要另行取证，日志会明确给出缺口。

### #360：发送超时或是否送达不明

在寻找输入框、等待发送按钮可见、按钮启用轮询、发送就绪、输入框基线、发送激活、按键开始与返回、登录/订阅检查、限流检查、工具回复读取、外部进度等待、网页读取、页面重新绑定、网页确认或确认失败处记录 `sendDiagnostic`（发送过程详情）：每一步的开始、结束或失败及耗时，按钮是否启用、提示词长度与匿名指纹，输入框剩余字符数、用户/助手轮数、停止按钮数、外部进度版本和确认送达所用证据。保留关键步骤的首次和末次时间，并保留最近 40 个详细事件，避免轮询刷掉最初的按键证据。按钮轮询期间约每秒落盘一次，启用或失败时立即落盘。可区分各步骤卡住的位置。网页连续无响应时，日志不能代替网页确认“消息必然未送达”；仍不得盲目重发。

第四版不再依赖最终网页取证：每个发送步骤开始、完成或失败后，立即同步更新本次目录内的 `send-N-live.json`（第 N 段发送的最新状态）。分段发送各自保留文件；准备发送时的网页取证本身也记录开始与结束。每份文件有时间、进程号、任务标识、记录序号，以及首末里程碑和最近 40 个发送事件。

`turn-live.json`（任务最新状态）独立记录阶段开始/结束/失败、超时预算与已用时间、取消、页面关闭/崩溃、浏览器断开、处理进程传输失败、正常退出和清理入口，并附带当前发送状态。阶段超时在取消操作前写入，任务异常在等待故障检查或读取页面之前写入，因此页面无响应或关闭也能留证。事件监听在任务清理时解除。

文件通过同目录临时文件再替换，写入失败保留上一份有效记录，并在原生错误输出中提示一次；之后成功写入会包含累计失败次数。记录不包含原始错误文字、提示词或网页正文。频繁步骤采用固定大小的最近事件列表，任务生命周期记录单独保留，避免被发送轮询挤掉。同步小文件写入会增加磁盘开销。强制杀进程只能保证此前成功写入的步骤仍可读取，不能凭空记录终止原因；不保证断电或系统崩溃后的持久性。

每次冲突、发送或回答使用随机密钥生成 HMAC（带密钥的内容指纹），不保存密钥。完整匹配证据在同一轮的三个状态间共用匿名密钥；其它指纹只能在该次记录内比较，不能跨任务追踪，也不能通过猜测短句直接反推内容。不保存提示词、回答正文、完整页面、链接地址或登录信息。仅限固定名单内的通用界面按钮名称可以原样记录；控件结构不保存原始网页标记。

诊断生成失败时保留原错误；冲突记录标记 `detailCaptureFailed`（详细记录失败），完成记录标记 `diagnosticFailureKind`（诊断失败类型）。记录仍有少量计算及磁盘写入开销，不能承诺零风险。

## 应用与撤回

先确认没有运行中的任务；不要与启动、升级或另一份补丁脚本同时操作。脚本不会启停进程，也不能替用户确认任务空闲。

持久应用时，应修改安装目录中的程序文件及同包的校验清单。以下命令在本仓库根目录的 PowerShell（命令窗口）中执行。根据实际安装位置调整目标。

```powershell
$diagnosticRoot = "$env:LOCALAPPDATA\Programs\Codex Web GPT\resources\runtime"
$diagnosticTarget = "$diagnosticRoot\app\browser-helper.cjs"
$diagnosticManifest = "$diagnosticRoot\manifest.json"
$diagnosticBackup = "$env:USERPROFILE\.codex-chatgpt-web\diagnostic-backups\6.1.2-package-browser-helper.original"
$diagnosticManifestBackup = "$env:USERPROFILE\.codex-chatgpt-web\diagnostic-backups\6.1.2-package-manifest.original"

$diagnosticArgs = @('--target', $diagnosticTarget, '--backup', $diagnosticBackup, '--manifest', $diagnosticManifest, '--manifest-backup', $diagnosticManifestBackup)
python scripts/codex-web-diagnostics/patch.py check @diagnosticArgs
python scripts/codex-web-diagnostics/patch.py apply @diagnosticArgs
python scripts/codex-web-diagnostics/patch.py check @diagnosticArgs

# 撤回；保留两份备份，以便核对及再次应用。
python scripts/codex-web-diagnostics/patch.py restore @diagnosticArgs
```

检查不写文件；应用前保存原件和原始清单，重复应用不叠加；撤回同时恢复两份文件。若目标、清单或备份有其他修改，脚本停止。备份必须在运行包目录外。

**启动器会在下次启动时校验安装目录和版本目录，并从安装目录同步运行包。**本补丁更新安装包清单里的目标文件指纹和包标识，使启动器的原生校验通过。软件升级后须重新核对版本；旧补丁不能直接套用新版本。

补丁只能影响之后从磁盘加载的新浏览器处理进程；已经运行的进程不会自动更新。**启动器由用户在任务空闲时自行重启，代理不得代为重启。**随后只读核对运行目录与实际进程，并通过下一次任务的诊断记录确认生效。

## 收集证据

先查看同一任务目录的 `turn-live.json` 和 `send-N-live.json`，其 `schemaVersion=4`（第四版日志格式）证明即时记录代码已执行。第三版开始包含发送确认前每项检查的计时；文字冲突和完成判定格式仍为第三版。再查看原生诊断文件顶层的 `markdownConflict`（正文冲突）、`completionDiagnostic`（完成判定详情）或 `sendDiagnostic`（发送过程详情）。若即时文件缺失，先核对实际进程加载版本和原生错误输出中的写入失败提示；不要把字段缺失解释成网页正常。

默认诊断目录：`%USERPROFILE%\.codex-chatgpt-web\diagnostics\browser-turns\<本次任务目录>\`。保留该目录及对应的原生活动日志；不要把实际日志提交到仓库。当前工具会轮换清理旧诊断目录，应及时保存到仓库忽略的 `.local/codex-web-diagnostics/` 或其他本地位置。

9 月 27 日现场的磁盘启动器日志没有包含本次错误，活动界面内存日志有记录。代码对日志写入异常不作上报，但这不能证明现场具体是哪一种写入错误。本补丁把新增信息附加到已经能够写出的原生任务诊断文件，不修改启动器日志系统。

## 验证

统一通过仓库 Build and Verify（构建与验证）入口执行：

```powershell
# 可选：明确提供未修改的官方程序文件，且同目录有官方 package.json。
$env:CODEX_WEB_DIAGNOSTICS_REFERENCE = '官方运行包\app\browser-helper.cjs'
build-and-verify verify --project .
Remove-Item Env:CODEX_WEB_DIAGNOSTICS_REFERENCE
```

检查项 `verify.codex-web-diagnostics` 覆盖应用、重复应用、从旧补丁升级、撤回、不兼容拒绝、备份保护、写入失败、原版与补丁版的判定对照、诊断故障隔离、隐私和记录条数边界。提供原文件时，还会从真实脚本入口对官方程序副本应用、升级和撤回，并检查完整程序语法。

临时目录中的验证不等于客户端真实任务验证。安装与真实客户端验证须另行确认；未复现的网页现场原因仍然未知。
