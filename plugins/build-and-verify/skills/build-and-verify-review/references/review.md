# Review（审查）

比较生态识别候选与已有 `build.checks`（构建检查项）和 `verify.checks`（验证检查项）。完整性只表示可发现入口是否被配置覆盖，不表示测试用例覆盖全部业务行为。

## Static Evidence（静态证据）

先只读取仓库文件、已有配置和可用的 `.build-and-verify/runs/performance-report.json`（性能报告）。动态扫描命令的范围判断和候选命令探测完全复用 `../build-and-verify-init/references/config-draft.md`（配置草案规则）。

## Reasonableness Checks（合理性检查）

逐项检查：

1. 命令来源：command（命令）是否来自真实仓库入口；来源消失时标记失效。
2. 构建或验证分组：打包或构建入口属于 `build.checks`；测试、代码检查、类型检查和规格校验属于 `verify.checks`。
3. 重复关系：相同入口、等价命令或有明确证据完全包含的检查项标记重复；不能确认脚本内部行为时不得建议删除。
4. paths（受影响路径）：是否覆盖命令来源、相关源码、测试和配置；可能漏跑时给出证据和修正值。
5. paths（受影响路径）和 inputs（缓存输入）：是否覆盖命令来源、依赖清单、相关源码、测试和配置；动态扫描命令的实际读取范围必须同时覆盖两者。不足以正确失效缓存时给出修正值；若完整范围会让复合检查在不相关变更时运行，应建议拆分专用检查。无匹配通配符 inputs（缓存输入）（含 `*`、`?` 或 `[`）是 Future Input（未来输入），报告 `当前无匹配但合法`；不含通配符的 paths（受影响路径）或 inputs（缓存输入）缺失（指向缺失文件或目录）时报告 `字面路径不存在，可能存在拼写错误`；无匹配通配符 paths（受影响路径）保持原有无匹配提示，不得称 Future Input（未来输入）。
6. 副作用风险：发布、部署、推送、删除、移除或迁移入口标记风险。
7. 废弃字段：旧 `parallel`（并行字段）建议迁移为 `checkParallel`（检查项间并行）。

不修改仓库脚本，不修改测试代码，不自动调整并行数、超时或完整验证预算。

## Result Groups（结果分组）

每项必须归入缺失、错误、重复、缓存或风险之一，并展示 source（来源）、现有值、证据、建议值、confidence（置信度）和默认选择状态。

## Confidence（置信度）

- High（高）：明确入口且无风险。遗漏项默认进入草案，但仍允许用户拒绝。
- Medium（中）：用途、分类或覆盖关系需要确认。默认不进入草案。
- Low（低）：来源弱、分类不确定或含副作用风险。仅提示风险，除非用户明确选择，否则不得进入草案。

## Confirmation（确认）

1. 展示全部结果，让用户逐项接受或拒绝。
2. 只合并用户接受的增加、删除、重新分组、paths（受影响路径）、inputs（缓存输入）和废弃字段迁移建议。
3. 展示最终配置差异并等待整体写入确认；沉默、拒绝或未完成确认时不得修改配置。
4. 写入后 `verify --full`（完整验证）失败时不得自动回滚：配置或命令错误生成新草案，真实仓库失败保留配置并报告。
