# Data Store（数据存储）

只保存已有记录，不运行模拟、不收集额外数据。所有任务共用调用方明确配置的项目级数据根目录，不按任务创建独立数据中心。

## 运行准备

需要 Python（编程语言）3.10 以上和本技能 `requirements.txt` 中固定的 DuckDB（分析查询引擎）。缺依赖时明确报告；安装到用户环境前取得授权。无需源码仓库、PyArrow（列式处理库）、服务或持久数据库。

入口是本技能 `scripts/data_store.py`，按实际安装目录解析，不能固定指向开发源码。下面 `<skill>` 是安装后的技能目录，`<data>` 是共享数据根目录。

## 接入项目

安装插件后，由代理从本次加载的技能入口取得 `<skill>` 的实际目录，直接调用随包脚本；不要猜缓存路径，不要另写定位程序。

`python <skill>/scripts/project_binding.py connect --project <repo>`

脚本把仓库共用入口 `<repo>/.local/skills/data-store` 直接连接到自身所在技能目录。Windows（视窗系统）使用一级目录联接，其他系统使用符号链接；不复制源码、不移动数据、不安装第三方定位工具。所有接入该项目的工具和独立命令统一使用这个入口，数据根仍由调用方明确配置。首次接入时，代理修改现有调用方一次，使其使用共用入口；不能再固定用户目录或文件缓存版本。

检查：`python <skill>/scripts/project_binding.py check --project <repo>`。它只核对项目入口与技能目录的连接关系，不验证业务身份、对象复用、读取次数或性能；通过此检查不代表项目接入完成。

切换来源或升级后，从新加载的技能目录执行：`python <skill>/scripts/project_binding.py update --project <repo> --from <old-skill>`。先记录旧入口的实际目标，`--from` 必须与它相符。新位置由脚本自身确定，不由调用方传入。普通目录、文件或重定向的父目录占位时拒绝操作并保留内容；切换失败恢复旧入口，无法恢复时明确给出保留位置。

新机器、新工作树需要重新接入一次。接入后，正常调用不查询客户端安装状态，也不逐次启动定位进程；长时间运行的工具继续使用已经加载的实现，更新入口后重新启动该工具。独立命令直接使用 `<repo>/.local/skills/data-store/scripts/data_store.py`。该目录只保存本机接入关系，不提交到版本管理。

### 调用方接入契约

- 先声明每类资料的业务身份、可变性、解释版本和复用有效范围，例如一次任务、阶段或进程。不可变资料在完整身份及解释版本相同时复用已取得的对象；完整身份须覆盖会改变内容的来源、输入和业务对象，不能只凭文件名或记录键判定相同。可变资料按项目的可信权威版本核验后复用；同键原子替换不代表内容永久不变。项目须说明版本依据、核验方式与代价，以及版本变化、显式失效、范围结束时如何停止复用；不能为省一次读取跳过必要核验。
- 优先复用下面已有的 `read_key`（按键读取）、`read_keys`（批量按键读取）、`columns`（字段选择）、`filters`（记录筛选）和显式表范围查询。已知键时不扫描历史分片；只需少数字段时不先加载完整报告；同批已知键优先批量读取。有效身份或版本未变时复用已加载的对象，不在同一有效范围内为不同消费步骤反复加载等价资料。版本核验、失效、失败确认和恢复所需的重复访问可以保留，须在项目证据中说明原因。
- 大对象沿用现有数值及结构化类型，在实际消费边界需要时才转换；避免数值列表与内存对象间无谓往返、完整复制和重复扫描。按实际所需字段与批量消费游标，不为检查摘要再次取得完整对象，不改变既有数值和嵌套结构的查询语义。
- 需要后续恢复的结果先用现有原子写入保存权威资料，确认成功后才发布其引用。检查点、诊断和恢复记录优先保留逻辑表、键及必要的身份和版本，不保存多份等价完整业务结果；恢复通过公开接口按引用读取。缺失、明确损坏和暂时不可用继续区分，不能吞错、静默补算或替换业务结果；重试、失效和恢复遵循项目已明确的策略。

数据存储层提供类型、点读、字段选择和原子发布；业务身份、权威版本、对象何时复用以及更新和恢复语义由调用项目负责。本契约不增加存储接口或常驻缓存。

## 写入

`python <skill>/scripts/data_store.py --root <data> write measurements batch_01`

从标准输入接收一个非空 JSON（数据交换格式）记录数组。记录在内存中转换为有类型的 Parquet（列式文件），仅 Parquet 持久化，内部压缩为 Zstd（压缩算法）。表名和记录键是逻辑身份，不区分大小写并统一为小写，不能传路径。

可使用 `--schema '{"label":"VARCHAR","score":"DOUBLE"}'` 明确字段及 DuckDB 类型；同一表应使用一致类型。未声明类型时使用 DuckDB 原生类型推断。文本数字不自动转换；嵌套对象和数组使用 STRUCT/LIST（结构体/列表）。字段结构不适合推断时提供明确类型，不静默回退到 JSON 文本列。调用方可以为单个元数据字段显式选择 JSON 类型，但业务适配不得把完整结果塞进不透明 JSON 列或另存完整副本。

同一表、同一记录键会原子替换完整记录组，其他键保留；调用者为每个正常批次选择稳定且唯一的键。单个写入处理调用者已经限定大小的一批记录。临时写入失败不会覆盖旧分片；不做备份、迁移或写后哈希回读。

Python 调用：`write(root, table, key, rows, schema=None)`；schema 是可选关键字参数，返回写入记录数。字段、类型和表名均由调用者定义，技能不绑定任何业务模型。

## 查询

`python <skill>/scripts/data_store.py --root <data> query 'SELECT label, score FROM measurements WHERE score > ?' --tables '["measurements"]' --parameters '[10]' --batch-size 1000`

只接受一条 SELECT（只读查询），必须通过 `--tables` 明确声明本次使用的非空逻辑表列表，只准备这些表的已完成分片。名称按原有大小写规则去重，不自动补表或回退全库。命令按指定批量读取并逐行输出 JSON，不先生成完整结果列表，不自动安装扩展。

Python 调用：`query(root, sql, parameters=None, *, tables)`，`tables` 必须是非空 `list/tuple`（列表或元组），返回 DuckDB 游标；使用 `fetchmany(1000)` 分批读取，并用上下文管理器或 `close()` 关闭。漏传、空值、非法名称和非只读语句在枚举目标目录前失败。声明不存在或没有已完成分片的表不会登记视图，可以通过 `information_schema.tables`（系统表目录）检查不存在；普通目标查询返回引擎缺表错误。不要让业务调用者直接读取 Parquet 路径。结果在查询启动后按当次执行读取；跨键批量事务及并发同键写入协调由调用方负责，不属于本技能。

调用方加载模块时必须确认 `DATA_STORE_API_VERSION == 2`（数据存储接口能力版本为二），缺少或不匹配时明确要求同步技能后重启，不能静默接受旧能力，也不在每次查询时检查安装状态。该能力常量不代替正式发行版本。

查询和点读仅把选定业务分片加入显式文件白名单，关闭外部访问与自动扩展，并锁定配置。表目录和分片不能通过链接重定向到其他位置。保留 DuckDB 原有临时溢写目录及内存策略；引擎自动许可该目录，它是明确的临时文件例外，不是任意 SQL（查询语言）的绝对文件安全沙箱。人工查询仍可能读取该临时目录中的文件；正常业务调用不能把临时目录作为业务数据源。不新增目录管理、清扫或查询解析器。

内部根据声明表的读取计划自动选择工作线程：预计不超过512行且能明确识别的复杂字段读取使用一个线程，其他读取使用引擎默认。`_READ_CHOICES`（读取调优选择）最多记住128条配置选择，只缓存调参判断。每次查询或点读都新建内存 DuckDB 连接、检查选定文件并读取当次数据；内存连接不是长期缓存，不保存报告、模型或已加载的业务对象。调用者无需提供调优参数；无法明确识别时保持默认。

### 已知记录键的点读

`python <skill>/scripts/data_store.py --root <data> read-key measurements batch_01 --batch-size 1000`

Python 调用：`read_key(root, table, key, columns=None, filters=None)`。表和键与 `write` 使用同一逻辑身份，默认返回该键的完整记录组游标，仍用 `fetchmany` 和上下文管理器关闭。只打开目标分片，不枚举其他表或历史分片；通用 `query` 仍支持显式声明表范围内的多表读取。

数据根存在但目标键不存在时抛出 `MissingKeyError`（继承 `FileNotFoundError`）；明确的 Parquet 文件头或页脚损坏抛出 `CorruptDataError`。整个数据根不可用、权限、锁、磁盘及无法确定为内容损坏的查询错误原样传播，调用方不能把所有读取失败当作无效数据而静默重算。点读不做完整哈希复核或第二次完整报告读取；业务身份与成绩核验仍由调用者负责。

### 多个已知记录键与指定字段

`python <skill>/scripts/data_store.py --root <data> read-keys measurements batch_01 batch_02 --columns '["label", "score"]' --batch-size 1000`

Python（编程语言）调用：`read_keys(root, table, keys, columns=None)`；`columns` 是可选关键字参数，仅接受顶层字段名列表。省略时读取完整记录。一次连接只打开指定键；键按原有大小写规则去重，跨键返回顺序不作保证。指定字段直接由查询引擎读取，不先返回完整报告再取字段。

空键列表、空字段列表、重复字段（包括仅大小写不同）和未知字段明确报错；字段名按名称处理，不能传查询表达式。目标缺失、明确损坏和暂时读取故障分别报告，不静默跳过失败目标。结果仍使用游标逐批读取并关闭，保留结构化类型和按字段名合并的规则。

两种点读都可使用 `filters={"label": "002"}`，命令行对应 `--filters '{"label":"002"}'`，由查询引擎在指定记录组中筛选。只接受非空的顶层字段与单个值的映射，多个条件同时满足才返回；值为 `None` 时匹配空值。字段按名称处理，值单独传入，不能传查询表达式。可以同时指定 `columns`，省略筛选时仍返回完整组。

## 接入完成证据

接入项目须通过其现有真实用户入口验证以下内容，不能仅以调用了统一接口或项目连接检查通过作为完成依据：

1. 记录入口、实际调用路径、数据规模、完整身份与权威版本依据、复用有效范围，以及各阶段预期的访问次数与所取字段；区分首次读取、范围内复用、版本核验和必要重读。
2. 通过该入口执行真实存储接口并记录实际操作、目标键和字段，核对次数与结果一致性。可在项目测试中用轻量转发计数，仍调用原接口，只保留必要元信息，不记录或复制完整大对象参数。接口调用次数不等于物理 I/O（输入输出）次数，也不能单独证明读取成本。
3. 覆盖同身份或同版本复用、身份或权威版本变化后的更新、失效后的重新读取，以及失败和恢复路径；确认旧对象不会误用、权威写入失败不会发布新引用、按引用能恢复一致结果，且缺失、损坏和暂时故障不会被静默补算掩盖。
4. 使用项目已有测量方式，对代表实际成熟使用规模的记录量、字段宽度、嵌套或数值大对象给出耗时和内存成本证据，同时核对结果正确性。小样例只证明基本功能，不能替代真实规模证据；根据项目目标和测量结果判断是否可接受，不设未经测量的通用固定秒数门槛，不要求为一次接入运行全量搜索或大量随机样本。
