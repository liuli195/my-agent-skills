# 逐插件切换来源

## 账号双对象与 Claude（代码助手）联合切换

统一入口为本技能 `scripts/plugin_sync.py`（同步脚本），首票仅验证一个用户指定的代表插件，不批量操作。脚本不发布、不创建或更新云端对象。DEV（开发）和 RELEASE（发布）的原始远端对象标识、预期版本、完整技能名以及 Claude（代码助手）来源信息均由输入清单提供，不把测试对象或插件名称写入逻辑。

- 先执行 `python <skill-root>/scripts/plugin_sync.py --manifest <mapping.json> --plugin <selected-key> --mode DEV --cwd <repo>`，只读核对两端状态。
- 用户明确授权精确对象、目标来源和本次卸载／安装、启停后，在同一命令添加 `--apply`（应用）。RELEASE（发布）回切使用同一入口及清单，仅改变 `--mode`（来源）。保存完整标准输出及标准错误，第一条 `before_switch`（切换前）事件在任何账号写操作前刷新输出，末条报告实际结果及恢复状态。
- `codexCommand`（代码代理命令）与 `claudeCommand`（代码助手命令）是可选的参数数组，默认分别为 `codex app-server --stdio` 和 `claude`。在可访问真实用户账号及缓存的本机执行。云端无法启动其服务器时报告阻塞，不宣称本机执行等于云端自身执行。
- 最小清单结构为 `plugins.<selected-key>.account.DEV/RELEASE`，每项含 `remotePluginId`（原始对象标识）、`version`（预期远端版本）、`skills`（发现接口返回的完整技能名数组）。`plugins.<selected-key>.claude.DEV/RELEASE` 每项含 `id`（插件加市场完整标识）、`version`（预期安装记录版本）、`scope`（已安装范围）。`readFromFolder`（源码读取目录）是可选的目录字符串，不是布尔值；有该目录时清单提供预期 `folderVersion`（源码实际加载版本），它可能不同于安装记录版本。禁用来源尚未加载时可不返回该版本：预检只核对安装及已知来源，目标启用后才验证实际目录和加载版本；恢复也在原来源重新启用后核验。没有目录覆盖时，字段可缺席或为空值，以安装版本为实际加载版本。原生条目有加载错误就停止，不把缺失加载版本当作已验证。两份 Claude（代码助手）来源需已原生安装，仅启停，不修改市场或配置文件；缺少来源即停止，不能把此限制声称为九项安装能力。
- 账号安装与卸载使用原始 `remotePluginId`（对象标识）。技能发现使用实际目录返回的 `id`（插件名加市场），两者不同，不能互换。安装前须恰好一个账号对象已安装且启用；Claude（代码助手）须恰好一个来源启用。双来源启用、未知版本或重复身份均停止。
- `account.DEV/RELEASE.resources`（资源）可声明数组，每项含 `skill`（所属完整技能名）、`path`（相对该技能目录的文件路径）及 `sha256`（预期文件摘要）。以实际发现的本机技能路径读取并核验；不接受父目录跳转、绝对资源路径或远端虚拟路径。代表插件验收须提供脚本与资源摘要；未提供时输出的空资源列表不构成资源已验证。
- 同一 app-server（应用服务器）进程中循环 `skills/list`（技能发现），强制刷新；目标完整技能集合启用、另一对象技能为零且无发现错误，才结束就绪等待。默认最多六十秒，不能固定睡眠后判成功。单次请求最多一百二十秒，就绪最多三百秒；整个命令与恢复共用十分钟上限，超限不再写入并报告真实未知状态。
- 账号卸载后先复查，再安装目标。Claude（代码助手）先停用原来源，再启用目标；恢复也必须在停用实际生效后才启用原来源。账号预检保留可安装性、安装策略及禁用原因，已知不可安装就停止。收到终局响应的失败才可查询状态并补偿；写请求超时、断连或尚无终局响应时，记录未决请求标识，停止后续账号写入与补偿并输出 `unknown`（未知）。一次列表读取不能证明后台写入已经终止，不能据此重新安装原来源或盲目重试。其他恢复失败再次只读查询，无法查询时明确报告未知，不声称原子切换。
- `switched`（已切换）只表示该进程观察到账号技能及 Claude（代码助手）原生状态符合目标；dot（云端助手）和 Codex（代码代理）新模型会话仍须另有真实证据。按用户本次要求，不再测试 Claude（代码助手）模型新会话。

## 既有本地市场操作说明

正式市场为 `my-agent-skills-marketplace`，开发市场为 `my-agent-skills-marketplace-dev`。两个市场同时保留；市场登记不等于插件已安装。

只处理用户确认的插件和来源；切换授权包含移除该插件旧来源并安装新来源，不包含移除市场、其他插件或 NPM（软件包管理器）工具。未确认时只检查。

1. 复用检查阶段的客户端。记录两个市场登记、该插件完整标识、版本、启用状态、实际安装路径和旧来源；Claude（代码代理）还须记录 scope（安装范围：用户、项目或本机项目）。保存客户端原始输出作为本次证据，不建立平行持久安装清单。
2. 确認目标市场包含该插件，读取对应版本与技能资源。目标缺失即停止。两来源同时安装时，列出全部标识，先由用户明确要保留的来源，不按短名猜测。
3. 按完整 `plugin@marketplace`（插件名加市场名）串行操作：Codex（代码代理）使用 `plugin remove <old-id> --json` 后 `plugin add <new-id> --json`；Claude（代码代理）卸载、安装及恢复都显式使用记录的 `--scope <scope>`，分别运行 `plugin uninstall <old-id>` 与 `plugin install <new-id>`。Claude 同市场操作也必须串行。保留原启用状态；客户端不能保持时明确报告，不擅自启用。
4. 重查两市场仍登记、仅目标来源安装、实际版本及路径正确、技能文件可读，其他插件未变化。数据中心还需从新技能入口调用 `project_binding.py` 检查／更新已接入项目；新机器按其说明接入，不自动扫描整盘找仓库。
5. 安装失败时，用已记录的完整旧标识恢复并复查原版本、路径及启用状态。若原版本已不可获得，明确报告实际恢复版本；恢复失败保留完整错误及下一步，不报切换成功。若项目接入未更新，明确报告旧入口及需要恢复或更新的项目。
6. 提醒用户开启新代理会话；已运行的业务工具更新入口后需重启。安装及文件发现通过不能替代新会话实际加载证明。开发源码变更后，按客户端现有刷新／更新命令操作，再检查真实安装内容；版本相同也不能仅看版本号报更新成功。

旧用户级目录联接仅在迁移得到精确删除授权后移除，先核对真实目标、确认市场安装资源可读及项目入口已接入。只删除链接本身，保留源码和数据；失败时可按已记录目标重建。
