# 本机插件来源切换

## 本机与云端边界

本机 Codex（代码代理）和 Claude（代码助手）保留原正式／开发双市场及下文原生切换路径，dot（云端助手）固定使用云端正式对象，双方不联动。本节只负责本机市场来源；个人账号对象的创建/更新及官方客户端安装/卸载另按cloud-account.md执行，不承担正式发布，不自动写本机配置。默认只读，修改须精确授权。

## 本机隔离同名账号来源

Codex（代码代理）使用官方完整来源标识控制启用状态。先只读记录账号及本机市场的完整标识、现有配置和覆盖优先级；不能按短名猜测，不能卸载远端对象或让本机跟随 dot（云端助手）。

代表插件的真实临时参数实验已证明以下参数数组可保持本机市场可用并禁用指定账号来源；替换占位符时使用实际发现的完整账号来源标识，不把任何插件名写入通用逻辑：

```text
['-c', 'plugins._default.enabled=true', '-c', 'plugins.<完整账号来源标识>.enabled=false']
```

参数数组的配置键内不加字面双引号。TOML（配置格式）文件的表名则正常引用完整标识：

```toml
[plugins."<完整账号来源标识>"]
enabled = false
```

在考虑默认允许前，必须检查既有默认值、所有显式覆盖及其他插件是否会因此改变；无法证明无关插件保持原状就停止。临时参数只证明该次进程，不能代表持久配置或全部九项已验收。本轮只提供流程，不自动写本机配置，不固定默认允许、批量禁用或新增配置修改器。任何后续持久修改须先取得精确配置授权，保存原内容及恢复办法，再通过新会话核对目标来源、无重复技能和资源；Claude（代码助手）仍独立走原市场流程。

## 既有本地市场操作说明

正式市场为 `my-agent-skills-marketplace`，开发市场为 `my-agent-skills-marketplace-dev`。两个市场同时保留；市场登记不等于插件已安装。

只处理用户确认的插件和来源；切换授权包含移除该插件旧来源并安装新来源，不包含移除市场、其他插件或 NPM（软件包管理器）工具。未确认时只检查。

1. 复用检查阶段的客户端。记录两个市场登记、该插件完整标识、版本、启用状态、实际安装路径和旧来源；Claude（代码助手）还须记录 scope（安装范围：用户、项目或本机项目）。保存客户端原始输出作为本次证据，不建立平行持久安装清单。
2. 确认目标市场包含该插件，读取对应版本与技能资源。目标缺失即停止。两来源同时安装时，列出全部标识，先由用户明确要保留的来源，不按短名猜测。
3. 按完整 `plugin@marketplace`（插件名加市场名）串行操作：Codex（代码代理）使用 `plugin remove <old-id> --json` 后 `plugin add <new-id> --json`；Claude（代码助手）卸载、安装及恢复都显式使用记录的 `--scope <scope>`，分别运行 `plugin uninstall <old-id>` 与 `plugin install <new-id>`。Claude 同市场操作也必须串行。保留原启用状态；客户端不能保持时明确报告，不擅自启用。
4. 重查两市场仍登记、仅目标来源安装、实际版本及路径正确、技能文件可读，其他插件未变化。数据中心还需从新技能入口调用 `project_binding.py` 检查／更新已接入项目；新机器按其说明接入，不自动扫描整盘找仓库。
5. 安装失败时，用已记录的完整旧标识恢复并复查原版本、路径及启用状态。若原版本已不可获得，明确报告实际恢复版本；恢复失败保留完整错误及下一步，不报切换成功。若项目接入未更新，明确报告旧入口及需要恢复或更新的项目。
6. 提醒用户开启新代理会话；已运行的业务工具更新入口后需重启。安装及文件发现通过不能替代新会话实际加载证明。开发源码变更后，按客户端现有刷新／更新命令操作，再检查真实安装内容；版本相同也不能仅看版本号报更新成功。

旧用户级目录联接仅在迁移得到精确删除授权后移除，先核对真实目标、确认市场安装资源可读及项目入口已接入。只删除链接本身，保留源码和数据；失败时可按已记录目标重建。
