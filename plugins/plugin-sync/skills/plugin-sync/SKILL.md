# 插件同步

## 运行前提

只核对本次目标客户端及其原生命令，整次操作复用同一目标。独立命令工具的额外前提只在选择该功能时按原入口核对。缺失只报告，由用户决定安装，不建立统一扫描器或安装器。

## 安全边界

- 默认只读。安装、更新、卸载、启停和来源切换须有用户对具体对象及动作的明确授权。
- 本机 Codex（代码代理）和 Claude（代码助手）保留原正式／开发双市场，dot（云端助手）固定云端正式对象，两者不联动切换。
- 不承担正式发布、不创建标签或推送。个人对象交付仅按官方Creator编排，安装/卸载仅走对应官方客户端；不修改请求之外的插件、市场及本机配置。
- 同一市场的 Claude（代码助手）操作串行；只使用当前仓库、用户提供路径或已确认的有限目录。用户级发现链接新增、改指或清理须核对具体授权。
- 修改前记录真实来源、版本、启用、范围、路径及恢复信息，失败只恢复本次已知变更，未知状态明确报告，不宣称跨端原子成功。

## 同一清单，本机管理

仓库两端市场和发布投影覆盖九项自有插件，沿用同一 `PLUGIN_REGISTRY`（插件发布登记）的身份、来源和依赖数据。安装和同步按清单及客户端能力处理，不根据插件名称分流；两个命令工具也走同一市场流程。软件包命令继续管理独立命令工具及自举，不拥有统一市场插件的启停或卸载权。

本机正式／开发市场来源独立于云端对象，不要求为每项建设双云端身份。新增清单项不需要新增名称条件分支。

## 工作流

1. 明确本机市场或独立命令工具目标，只处理获准范围。优先使用用户指定路径，再从 `PATH`（程序搜索路径）定位；必要时只读核对 `~/.codex` 或 `~/.claude`，整次复用同一客户端。
2. 读取 `references/check.md`，核对用户选择市场的全部请求插件，不排除命令工具插件；用 `references/status-taxonomy.md` 分类。
3. Codex（代码代理）安装更新读取 `references/update-codex.md`；Claude（代码助手）读取 `references/update-claude.md`。本机来源切换及同名账号来源隔离读取 `references/switch-source.md`，保留原双市场路径，只改授权目标。
4. 仅管理独立命令工具自身安装、诊断或更新时读取 `references/update-build-and-verify-runtime.md`，复用清单提供的原命令。这不代替插件同步，也不改变统一市场安装。
5. 修改后重跑相关只读检查，分别核对来源和资源。Codex（代码代理）需要新会话发现证据；Claude（代码助手）按用户要求只核对原生市场安装、启停、来源及文件，不擅自运行模型会话。

## 技能发现与报告

本机正式市场为 `my-agent-skills-marketplace`，开发市场为 `my-agent-skills-marketplace-dev`，两者同时保留；用户可指定其他市场。市场是本机发现入口，旧用户级链接仅用于迁移残留核对，不新建重复安装；没有替代发现及依赖验证前不清理。运行依赖、第三方技能或没有替代入口的开发技能须逐项报告，不静默跳过。

同名云端账号来源用 Codex（代码代理）官方完整来源标识配置隔离，不按短名禁用或卸载远端对象。先读取现有覆盖及对其他插件的影响，再取得精确修改授权；本轮只记录通用步骤，不自动写本机配置，不增加批量配置修改器。

报告已执行、真实证据、失败和未验证项。不要把安装、临时参数或命令工具更新成功写成新会话加载或正式发布成功。


## 个人云端正式对象

本技能统一编排正式个人插件的创建/更新及各端官方安装/卸载。先阅读 `references/cloud-account.md`（个人云端同步）。内容写入只调用宿主官方Creator（插件创建器）工具，不运行原生客户端服务发布命令、不实现另一套认证或上传接口。发布/打包仍由发布技能负责。宿主无所需工具时明确停止，不换写入通道。

本机原正式/开发双市场与完整来源隔离继续保留。个人对象保存、客户端安装、技能发现和实际运行分别核验；内容保存成功不自动代表后三项通过。每项名称与来源来自清单，不写插件名特例。
