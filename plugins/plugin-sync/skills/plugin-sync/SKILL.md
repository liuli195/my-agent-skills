# 插件同步

## 运行前提

同步脚本使用 Python（编程语言）标准库，不要求其他插件的 Python（编程语言）第三方库。只核对本次目标客户端：单端市场操作使用该端原生命令；双端来源切换使用清单指定的 Codex（代码代理）应用服务和 Claude（代码助手）命令及其登录状态，沿用原预检和失败停止行为。独立命令工具管理或源码打包的额外前提，仅在选择该功能时按其现有入口核对。缺失只报告，由用户决定安装，不建立统一扫描器或安装器。

## 安全边界

- 默认只读检查。安装、更新、卸载、启停和来源切换须有用户对具体对象与动作的明确授权。
- 不正式发布、不创建标签、不推送，不修改未纳入请求的第三方插件。
- 同一市场的 Claude（代码助手）修改串行执行。
- 只使用当前仓库、用户提供的路径或已确认的有限目录。用户级发现链接的新增、改指或清理须单独核对授权。
- 操作前记录实际来源、对象、版本和启用状态；部分失败停止扩展并恢复本次变更。恢复结果或状态未知须明确报告，不宣称三端原子切换。

## 同一清单与入口

仓库的两端市场和发布投影覆盖九项自有插件。发布登记 `release-flow`（发布流程）的 `scripts/release_flow.py` 中 `PLUGIN_REGISTRY`（插件清单）维护身份、来源、发布输入及共享依赖。安装和同步按清单项及客户端能力处理，不根据插件名称分流；两个命令工具也使用同一市场流程。包管理命令继续服务于独立命令工具安装和自举，不拥有统一市场插件的启停或卸载权。

逐插件来源映射提供 DEV（开发）与 RELEASE（发布）两个稳定对象的实际标识、版本、技能和资源校验信息。不能伪造未创建或未验证的对象标识。新增清单项不需要新增名称条件分支。

## 工作流

1. 定位客户端：优先使用用户指定路径，其次从 `PATH`（程序搜索路径）定位；关联状态不可用时只读核对客户端默认目录 `~/.codex` 或 `~/.claude`。整次检查与修改复用同一目标。
2. 读取 `references/check.md`，核对用户选择市场的全部请求插件，不排除任何命令工具插件；用 `references/status-taxonomy.md` 分类。
3. 用户授权安装或更新 Codex（代码代理）市场插件时，读取 `references/update-codex.md`。用户授权 Claude（代码助手）市场插件安装或更新时，读取 `references/update-claude.md`。只修改授权目标，保留其他市场和插件。
4. 用户请求账号私有对象保存或开发／发布来源切换时，读取 `references/switch-source.md`，使用其中同一脚本入口逐项串行处理清单。保存动作仅在快照内容、来源及精确对象获得授权后创建私有对象；已有对象更新须有同一真实标识的已核对私有创建记录；内容更新不修改分享权限，未知创建来源仍停止。个人对象未提供分享上下文时不检查工作区分享列表，创建请求完成与权限独立验证分别报告。已成功响应但后检失败时使用同一入口只读对账，仅在授权后改本地记录，不重发保存；不自动安装或正式发布；切换动作仍要求双对象及预安装来源。先验证一个代表对象，失败停止扩展，不批量创建，不根据包名猜测身份或自动重命名。
5. 用户仅请求独立命令工具自身安装、诊断或更新时，读取 `references/update-build-and-verify-runtime.md`，使用清单提供的包管理与命令能力。这不代替插件同步，也不改变统一市场安装。
6. 修改后重跑相关只读检查；核对唯一启用来源和实际资源。云端助手与 Codex（代码代理）需要新会话发现证据；Claude（代码助手）按用户要求仅核对原生市场安装、启停、来源和文件读取，不擅自运行模型会话。

## 技能发现与报告

统一市场是插件发现入口；旧用户级链接只用于核对迁移残留，不新建重复安装。对现有链接检查两端技能集和直接目标，不在依赖可用性验证前清理。运行依赖、第三方技能或没有替代入口的开发技能须逐项报告，不静默跳过。

默认市场为 `my-agent-skills-marketplace`，开发市场为 `my-agent-skills-marketplace-dev`；用户可指定别的市场。默认范围是选定市场的请求插件，不按插件名称例外处理。

简洁报告当前状态、实际证据、已执行动作、未验证项和下一步。不要把上传、安装、配置或命令工具更新成功写成新会话加载或正式发布成功。

## 离线开发包

维护源码时，复用仓库既有打包入口：`python plugins/tool-lifecycle/pack.py snapshots <output> --project <repo>`。此命令读取同一发布登记，为每个变化插件生成完整目录和 ZIP（压缩包），两个命令工具复用现有共享生命周期代码注入；不操作账号、不安装、不上传或创建正式标签。真实接口的 `pluginPath`（插件路径）须使用清单记录的目录，不传压缩包路径。账号用包须显式添加 `--account-mode DEV`（开发账号模式）或 `--account-mode RELEASE`（发布账号模式）：仅开发账号包的云端清单技术名及显示名投影为原名加 `-dev`（开发后缀），发布账号包保留原名；源码、逻辑键、代码助手市场及软件包名称不变。模式纳入输入摘要，快照记录 `accountMode`（账号模式）和 `packageName`（实际包名），保存时只核对已审阅产物，不临时改名。未指定模式的既有离线打包保持原行为，不能作为模式账号保存输入。

输出目录不得位于插件发布输入内。`snapshots.json`（快照清单）记录输入摘要、来源提交及未提交状态、版本、目录路径、完整产物摘要、耗时和大小。输入未变且旧压缩包及目录校验通过时复用原记录；共享依赖变化只重打受影响插件。构建失败保留上一次完整清单和可用产物，旧产物缺失或损坏则停止，不将半包作为成功结果。

云端清单保留源码已声明的作者和界面字段。缺省作者采用已核对仓库来源的所有者命名空间，缺省开发者跟随最终作者；缺省显示名采用插件名称，描述复用源码清单，类别复用发布登记，未声明能力标签时使用允许的空数组。产物按实际情况记录类别和能力标签来自源码还是缺省值，不伪造联系人、账号对象或能力。校验按官方[包提交错误契约](https://developers.openai.com/plugins/deploy/submission-errors)的字段类型和长度执行，不能冒充平台已实际接收。

先通过离线构建、产物入口冒烟和独立审查，再核对精确对象及动作安排部署和逐端实际加载。源码打包复用既有发布入口的环境前提，不把它扩散到普通同步功能。命令只报告已打包，运行环境验证仍待完成；不能以开发解释器的帮助入口通过证明目标环境依赖可用。目标插件按自身说明及声明核对直接前提，不自动安装、打包外部轮子或创建新隔离环境。离线包成功不代表九项十八对象或客户端已经可用。
