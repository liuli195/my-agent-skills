# 实施与验证

仅在`门禁一——开始开发`获得确认后加载此参考文档。

## MUST — 必须依赖

- 当前阶段必须按入口规则解析并加载、读取和实际使用 `subagent-policy`（子代理策略）、`tdd`（测试驱动开发）、`build-and-verify`（构建与验证）；选择子代理审查时使用 `code-review`（代码审查），选择 ChatGPT 网页审查时使用 `awehitch`（网页 ChatGPT 连接）。
- 任一依赖无法按入口规则唯一加载时立即停止，报告失败依赖、当前步骤和门禁一恢复位置；不得跳过或替代。

## 流程编排

1. 在任何实施写入前重新只读核对已登记的同一 Git（版本管理）工作树、门禁一已确认的非 `main` 分支、仅包含已登记需求产物的状态和固定基线；开发与验证期间沿用该工作树、分支和基线。首次委派前实际调用 `subagent-policy`，按所选角色准备模型、思考强度、读写边界和任务提示词；宿主无法提供指定模型或思考强度时，按该技能的回退规则处理。完成条件是工作树、分支、基线及主工作树未变化均有证据。
2. 对每个纵向票据，在红灯到绿灯循环前实际调用 `tdd`，再从门禁一绑定的目标产品最高层级真实用户入口开始：先写并运行最小可观察失败检查，再做最小实施修改，再重跑同一检查确认转绿；各票据按已确认的串行或并行安排推进。红灯到绿灯检查、最终冒烟和行为验收均使用同一入口；需求或接缝变化时返回需求路由。完成条件是每个票据都有可观察红证据、绿证据和范围归属。实施、返工和审查修复均不得修改或提交 `myspec/specs/`；规格候选只能保存在目标工作树 `.local/spec-work/`。
3. 按门禁一已确认的方式实施。串行时按票据依赖顺序由主代理或子代理开发；并行只能由子代理实施，主代理先确认票据无依赖、改动范围和测试资源互不冲突，无法证明独立的票据串行。需要子代理时，主 Agent（代理）按 `subagent-policy` 选择角色，使用固定模型和思考强度（宿主无法提供时按该技能的回退规则处理），并在提示词中写明任务、范围、读写边界、宿主资源和预期证据；使用宿主现有入口在单一已验证目标工作树中派发。共享 Git（版本管理）操作由主代理串行执行。返回报告作为线索，主代理逐票检查实际文件、差异、提交、分支、工作树和票据证据；选择每票审查时，先完成步骤 6 中该票的审查再验收该票，已运行的独立票据可继续实施。主代理验收每次实施、返工或审查修复返回的实际文件、提交与差异时，发现已跟踪或未跟踪的正式规格路径即判定 `REWORK_REQUIRED`，不得接受票据。完成条件是派发符合角色契约且实际结果满足票据。
4. 正式验证前实际调用 `build-and-verify`，运行 `build-and-verify verify --project <current-worktree> --base <fixed-baseline>`；正式验证的完成条件是结果为 `status: passed` 且 `checked` 非空，并且固定基线之后的实际差异、预期干净状态和主工作树未变化均有证据。
5. 通过门禁一绑定的目标产品入口执行最终真实入口冒烟，覆盖主要成功路径以及门禁一确认的风险所要求的失败或恢复路径；保留原始且已脱敏的事件、输出、退出码和 Git（版本管理）前后状态作为证据。完成条件是同一入口的行为验收和冒烟均通过。
6. 按门禁一已确认的时机审查：每票完成后审查该票，或全部票据完成后统一审查；选择每票审查时本步骤随步骤 3 逐票执行，正式验证后汇总审查证据。每票审查由主代理只暂存该票归属文件并串行提交，固定该票的起止提交范围；审查只读取该范围的已提交差异及 Git（版本管理）对象中的上下文，审查结束前不提交其他票，避免混入共享工作树中的未完成改动。选择子代理时，在独立审查前实际调用 `code-review`；选择 ChatGPT 网页时，实际调用 `awehitch` 进行网页审查。所选路径不可用时停留审查步骤，请用户重新选择，不擅自改用另一方式。全部完成后审查以全局固定基线限定实际差异和必要上下文；每票审查使用该票的起止提交，全局固定基线仍用于正式验证与最终核对。解决阻塞性发现后重跑受影响的检查和冒烟，并只审查修复差异。完成条件是不存在未解决的阻塞性审查发现。
7. 当工作树、分支和基线正确，差异只包含已批准票据，所有红绿检查通过，Build and Verify（构建与验证）为 `passed` 且 `checked` 非空，真实入口冒烟和行为验收通过，限定审查无阻塞项时，先运行固定基线后的正式规格差异检查：依次执行 Git（版本管理）命令 `git diff --name-only <fixed-baseline> -- myspec/specs/` 和 `git ls-files --others --exclude-standard -- myspec/specs/`。任一命令失败即停止。任一结果非空时逐项列出提前写入的文件，停留实施阶段，不准备门禁二，也不自动创建回退提交；结果均为空才可加载[规格与交付](delivery.md)并准备门禁二。检查、依赖加载或审查失败时，在同一门禁一授权下从准确失败步骤恢复。
