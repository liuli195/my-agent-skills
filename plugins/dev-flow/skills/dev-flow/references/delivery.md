# 规格与交付

仅在实施、验证和基于固定基线的限定审查全部验收通过后加载此参考文档。

## MUST — 必须依赖

- 当前阶段必须加载、读取并实际使用官方 MySpec（自有规格）路由和 `pr-flow-complete`（完成拉取请求流程）；需要规格变更时加载、读取并实际使用 `my-spec-add`（新增自有规格）。

## 流程编排

1. 按官方 MySpec 路由，根据已验证行为准备完整正式规格预览；重新核对预览、需求数量、验证证据、已知风险和准确交付动作。完成条件是预览完整、差异未提前应用且实施阶段证据可复核。
2. 在“核心摘要”中完整展示正式规格摘要、验证证据、已知风险和准确 PR（拉取请求）动作，明确当前是`门禁二——规格与交付`；完整展示当前门禁内容后，取得用户对当前门禁动作的明确授权；语义不明确时停留澄清。完成条件是记录一次门禁二授权或明确阻塞。
3. 门禁二授权后，重新核对被引用状态，通过 MySpec 应用并验证已批准规格，然后调用 `pr-flow-complete`。该次授权同时覆盖规格应用和选定完整交付；失败时保留现场并在原授权中恢复失败动作。完成条件是每个动作都有实际结果和恢复状态。
4. 只有门禁二授权后，完整 PR Flow（拉取请求流程）才执行分支切换、合并、基础分支同步和安全的非强制清理。交付和清理依据 Git worktree registration（Git 工作树登记）识别目标，而非名称、路径或宿主判断；危险操作保留安全边界。使用 `--remove-worktree`（删除工作树参数）时，primary worktree（主工作树）保留；完成后它在实际 target/base branch（目标/基础分支）的最新提交上检出该分支。registered linked non-primary worktree（已登记关联非主工作树）在活跃 Agent（代理）会话仍在其中时，以 detached HEAD（分离头）状态保留在该提交；外部调用时删除。切换提交前若活跃 cwd（当前工作目录）在目标提交中缺少未被 Git 忽略的路径，流程停止，并保持 `removeWorktreePending`（工作树删除待处理）和外部 `nextCommand`（下一命令）为空。完成条件是清理状态、工作树登记、实体路径、提交和分支证据一致。
5. 在触发交付的步骤中执行完成检查：报告规格有效性、已合并 PR、已同步基础分支、已删除分支以及工作树登记和实体目录结果。primary worktree（主工作树）的登记和实体目录仍存在、已在实际目标/基础分支最新提交、源分支已删除、状态为 `cleanup_complete` 且无 `removeWorktreePending` 或外部 `nextCommand` 时，报告安全保留主工作树；活跃会话中的关联工作树以 detached HEAD（分离头）指向该提交时同样报告成功保留。其他实体工作树目录报告准确路径、原因和证据并保留现场；针对该准确遗留项取得额外明确授权后才执行强制清理。完成检查不是第三个授权门禁，其他 PR Flow 停止状态保持可恢复。
