# 开发流程

这是一个纯 Skill（技能）路由。它固定依赖 `subagent-policy`、`codebase-design`、`grill-with-docs`、`domain-modeling`、`to-spec`、`to-tickets`、`tdd`、`build-and-verify`、`code-review`、MySpec（自有规格）和 PR Flow（拉取请求流程）。它组合仓库已有的 Skill（技能），而不复制其流程。

## MUST — 必须依赖

- 只在已登记的 Git（版本管理）工作树和有名称的非 `main` 功能分支中运行；首次委派前必须按 `subagent-policy`（子代理策略）验证宿主原生角色和适配器。
- 需求阶段依赖 `codebase-design`、`grill-with-docs`、`domain-modeling`、`to-spec` 和 `to-tickets`；实施阶段依赖 `tdd`（测试驱动开发）、`build-and-verify`（构建与验证）和 `code-review`（代码审查）；交付阶段依赖 MySpec（自有规格）和 PR Flow（拉取请求流程）。任一当前阶段依赖缺失或不可读，立即停在该阶段。
- 全流程固定为两个正式确认；确认后的动作及失败恢复持续使用原授权。门禁一授权前不写入、不派发可写任务、不切换工作树或分支。

## 流程编排

### 入口与需求阶段

1. 只读证明仓库根目录、Git 工作树登记、当前有名称的非 `main` 分支和干净起始状态；任一项无法证明，或角色/模型策略无法验证，在任何写入、可写派发或正式确认前停止。完成条件是这些证据、固定基线和真实阻塞项均已记录。
2. 阅读[需求](references/requirements.md)，完成需求路由和`门禁一——开始开发`。该阶段保持只读；门禁内容必须完整展示后，才判断当前上下文是否包含针对该门禁动作的明确授权。

### 实施与验证阶段

1. 取得门禁一授权后，阅读[实施与验证](references/implementation.md)，重新核对同一 Git 工作树、同一功能分支、干净状态和固定基线；开发与验证期间保持同一工作树和分支，不创建或切换它们。完成条件是工作树、分支和基线证据与门禁一一致。
2. 按票据顺序逐个实施；可写调用必须严格串行，只有工作树和分支稳定时只读调查或审查才可并行。功能、缺陷和集成行为使用 `tdd` 的 Red→Green（红灯到绿灯）循环，Build and Verify（构建与验证）必须基于固定基线且 `status: passed`、`checked` 非空，并执行门禁一绑定的真实用户入口冒烟。所有检查、行为验收和最终冒烟使用同一入口。完成条件是每张票据的红绿证据、正式验证和冒烟均可复核。
3. 仅审查固定基线之后的实际差异和必要上下文；实施、验证和限定审查的完成条件全部满足后，才进入交付阶段。检查或审查失败时，在同一已授权动作中恢复失败步骤，不重新请求门禁一。完成条件是实际差异无未解决阻塞项。

### 规格与交付阶段

1. 阅读[规格与交付](references/delivery.md)，完整展示正式规格预览、验证证据、风险和准确交付动作后，判断当前上下文是否明确授权`门禁二——规格与交付`动作。门禁二授权同时覆盖规格应用和选定的完整 PR Flow（拉取请求流程）；不得另行请求交付确认。完成条件是预览与动作完整且当前授权语义明确。
2. 只有门禁二授权后才可应用 MySpec、运行 `pr-flow-complete`、切换分支、合并、同步基础分支或执行安全清理。失败时保留现场，在同一授权中恢复失败动作。完成条件是规格有效且交付返回可核验结果或准确恢复状态。
3. 交付动作结束后，在触发它的交付步骤中执行完成检查，报告规格有效性、PR、基础分支、分支和工作树的实际证据；完成检查不是第三个授权门禁。完成条件是最终状态由证据明确为安全完成、活跃会话工作树保留或准确遗留项。

### 确认与输出规则

- 两个门禁都使用同一确认语义：完整内容展示后，上下文中明确授权当前门禁动作即可；“确认”“可以”“继续实施/交付”等自然表达可以作为示例，但不得要求固定口令。沉默、提问、修改需求、仅确认某个细节、以前门禁授权或含义不清都不能视为当前授权；不确定时停留并澄清。
- 正式确认恰好两次。确认在已确认动作及其失败恢复期间持续有效；恢复失败动作时不得再次请求同一确认。需求或测试接缝发生变化时，返回需求阶段，而不是静默扩大票据范围。

### 核心摘要

说明当前门禁、可观察结果、证据或阻塞项；需要授权时说明当前要授权的动作。

### 确认后进入的下一步

说明唯一的下一条路由。门禁确认后失败则恢复失败动作；完成检查报告最终状态、证据明确的活跃会话工作树保留结果或准确遗留项。
