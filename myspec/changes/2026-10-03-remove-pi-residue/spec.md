# 移除 Pi 支持并保持 Claude/Codex 工具链可用

**Status:** ready-for-agent

## Problem Statement

用户已经停止使用并卸载 Pi（编码助手），但仓库在删除旧专用插件后仍保留 Pi 开发依赖、宿主适配、安装步骤、生命周期处理和正式支持承诺。依赖更新因此继续把 Pi 及其整棵间接依赖树带回维护范围；只删除依赖声明会破坏仍借用 Pi 加载器的通用技能测试。

## Solution

在一项完整、可验证的变更中取消现行 Pi 支持，删除其独占依赖和适配路径，保留 Claude Code（编码助手）、Codex（代码代理）及与宿主无关的规格、构建、验证、拉取请求和发布能力。保留仍有价值的通用测试，不新增替代测试框架、迁移机制或状态机。

## User Stories

1. 作为仓库维护者，我希望安装开发依赖时不再安装 Pi，以免维护已经不用的编码助手。
2. 作为仓库维护者，我希望 Pi 独占的网络库及其它间接依赖随之消失，以免继续收到这棵依赖树的升级请求。
3. 作为工具使用者，我希望构建、验证和发布步骤不再安装或调用 Pi，以免后续流程重新引入它。
4. 作为 MySpec（自有规格）和 Build and Verify（构建与验证）使用者，我希望现有 Claude/Codex 初始化、诊断、更新及来源保护继续可用。
5. 作为工具使用者，我希望不带参数的 doctor（诊断）只检查工具自身，显式使用 --all（全部客户端）时才检查 Claude/Codex。
6. 作为曾中断更新的使用者，我希望旧记录包含 Pi 时沿用已有校验报错并保留原记录，避免重新安装 Pi、篡改其旧配置或偷偷跳过未完成步骤。
7. 作为技能维护者，我希望通用技能的内容、目录结构和规则断言继续验证，而不再依赖 Pi 的资源加载器。
8. 作为拉取请求流程使用者，我希望通用命令入口、工具链身份查询、检查门禁和安全清理保持原有行为。
9. 作为维护者，我希望现行文档和正式规格与支持范围一致，同时保留历史记录及 Claude/Codex 仍需的旧发行包识别。

## Implementation Decisions

- 复用现有共享生命周期模块，从同一实现中移除 Pi 的初始化、来源解析、诊断、刷新和更新分支；不复制两个工具的生命周期逻辑，不引入新模块或适配层。
- 移除 Pi 根开发依赖及仅服务于 Pi 包装器测试的 tsx（脚本执行器），由现有包管理器重新生成依赖锁定结果；删除已经失去用途的 Pi 专属依赖约束，保留 Node.js（脚本运行时）及 Python（工具实现语言）的通用能力。
- 移除 Pi 专属拉取请求适配器、包发现元数据、自动化安装步骤及对应发布模板，避免后续生成流程重新带回旧安装步骤。
- 两个工具的 doctor 默认只报告工具包、工具链身份和安装状态；--all 只汇总 Claude/Codex；已取消的 --pi（Pi 客户端选择）不再作为受支持入口。
- 旧未完成更新记录中的客户端白名单移除 Pi，复用已有 invalid_update_state（更新状态无效）失败路径；在安装新包或刷新客户端之前停止，不增加自动恢复、迁移或清理机制。诊断继续只读展示原有未完成记录。
- 保留 Claude/Codex 的来源诊断、旧来源识别、状态恢复和数据保护。仅用于识别其历史发行包的旧名称不等同于继续支持 Pi，不能机械删除。
- 删除 Pi 专项测试；通用技能内容与结构检查改用现有运行时的内建能力，保留原有有效断言。通用拉取请求命令和发布包验证继续复用现有入口。
- 现行支持说明与正式规格候选同步取消 Pi 契约。实施阶段只准备规格候选；正式规格在交付门禁批准后按既有规格工具原子应用。

## Testing Decisions

- 采用用户已确认的公开测试接缝：现有发布包安装后的 myspec（规格命令）与 build-and-verify（构建验证命令）。红灯到绿灯检查、行为验收和最终冒烟均从这些真实入口观察结果；安装与客户端边界沿用已有隔离测试设施。
- 验证无 Pi 环境下的包安装、无参数诊断、--all 诊断、Claude/Codex 初始化及更新；观察输出、退出状态和对外可见的安装结果，不测试新的内部接缝。
- 验证已取消的 Pi 参数被拒绝；旧未完成记录含 Pi 时使用原有失败路径，原记录及旧 Pi 配置保持不变；有效的 Claude/Codex 更新与来源保护不受影响。
- 验证重新生成的依赖树不含 Pi 及其独占 undici（网络库），并核对验证、发布和模板不再安装 Pi。
- 保留通用技能规则和目录契约检查、现有拉取请求命令检查以及共享工作树环境准备检查；仅删除已无产品用途的 Pi 专项覆盖。
- 正式验证使用现有 Build and Verify 固定基线快速验证，结果必须为 passed（通过）且 checked（已检查）非空。跨平台及完整检查使用仓库原有持续集成门禁；环境限制不视为通过，不削弱测试或门禁。
- 全票完成后按固定基线进行独立 Standards（规范）与 Spec（规格）两轴审查；修复阻塞项后重跑受影响检查与真实入口冒烟。

## Out of Scope

- 不升级 Pi，不合并已关闭的依赖更新请求。
- 不卸载或改动用户电脑上的软件、Pi 配置或其它个人数据。
- 不删除 Python、Node.js、Claude/Codex 支持或通用规格、构建、验证、拉取请求、发布能力。
- 不机械删除历史需求记录、历史研究文档或仍用于 Claude/Codex 兼容的旧发行包标识。
- 不扩大为测试框架重构、性能优化、依赖更新或新增迁移/恢复功能。
- 不混入另一项尚未交付的文档修正，不修改仓库规则或放宽检查门禁。
