# 02：一次性耗时诊断

**交付行为：** 用户临时取消本次总截止以查明慢检查，配置默认值不变，单项防挂和检查失败仍生效，运行过程中能看到每个检查的开始、结束、耗时与未完成状态；诊断结果不能作为正式验证通过。

**前置票据：** 01：本机一次验证预算硬截止；用户已确认一次性诊断和第一版不新造检查项选择器，门禁一已由父端转发确认。

**状态：** ready-for-agent。

- [ ] 提供一次性诊断参数，不创建新测试框架或检查项选择器，单项调试沿用测试框架原生能力。
- [ ] 最高真实命令入口先得到可重放失败，再以同一入口验证成功。
- [ ] 诊断仅本次取消总截止，不改配置默认，不取消单项超时、真实检查失败或断言失败。
- [ ] 实时逐项输出开始、结束和耗时，报告未完成检查；结果明确标记诊断，不冒充正式验证通过证据。
- [ ] 用测试框架已有计时能力观察子测试，不承诺通用运行程序自动解析所有子测试。
- [ ] 文档准确说明测试框架原生单项调试方式，不宣称插件提供未实现的选择器。
- [ ] 短合成案例验证临时诊断、真实错误和默认配置不变，测试位于统一测试目录。
- [ ] 同一真实入口冒烟通过，固定基线快速验证通过且检查项非空；提供准确提交供父端限定独立审查。

**推荐顺序与执行者：** 在第一张完成后，由用户指定的主实施者串行完成；两张涉及同一入口与调度，不能作为独立并行写入票据。
