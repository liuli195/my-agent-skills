# 01 提供可本地安装的 Pi Development Flow（Pi 开发流程）

- 状态：ready-for-agent
- 前置票据：无

## 用户结果

用户可以从用户级本地 Pi（编码代理）包启动一项 Development Flow（开发流程），按需完成需求确认、隔离实施、范围受控的审查、风险匹配验证、正式规格固化、PR（拉取请求）交付和安全清理；仓库验证规则同步允许用真实入口冒烟替代无条件完整端到端回归。

## 实现范围

- 使用 `writing-great-skills`（优秀技能编写）创建 Pi 专用编排 Skill（技能）。
- 提供可由 Pi 本地目录包发现的最小包元数据。
- 通过渐进式披露组织初始化、需求、实施、交付和恢复规则。
- 复用现有需求讨论、票据、子代理、测试驱动开发、代码审查、规格和 PR Flow（拉取请求流程）能力，不复制其正文。
- 更新仓库验证规则，使验证强度与风险和影响范围匹配。
- 增加真实 Pi 包资源加载检查，并注册到现有 Build and Verify（构建与验证）入口。

## 验收标准

- [x] Pi（编码代理）从本地包目录发现 `pi-development-flow`（Pi 开发流程），来源、名称和调用元数据正确。
- [x] 主 Skill（技能）只保留入口、阶段、门禁和完成条件，并按条件加载五个参考文件。
- [x] 新变更和恢复已有变更共用一个入口；初始化仅检查并委托已有正式入口。
- [x] 需求确认、实施和清理收尾三个阶段均有明确进入条件、完成条件和停止条件。
- [x] 无真实并行时使用单一功能分支和工作树；有真实并行时才使用集成分支和票据工作树。
- [x] 子代理使用遵循 Pi 子代理策略，且并行数量由主 Agent（代理）判断。
- [x] 功能、缺陷和集成行为使用测试驱动开发；验证按风险使用目标检查、快速验证和真实入口冒烟。
- [x] 关键任务与整体代码审查均限定实际差异和必要上下文，修复后只定向复核。
- [x] 正式规格只在整体审查和验证完成后固化，交付必须经过独立授权。
- [x] PR（拉取请求）合并、目标分支同步、安全清理及用户级本地安装验证完成后，流程才报告全部完成。
- [x] 仓库规则不再无条件要求完整端到端回归，并保留安全、数据完整性和明确验收路径的验证要求。
- [x] Build and Verify（构建与验证）快速检查通过。

## 已知风险

- 纯 Skill（技能）只能通过指令编排流程，不能像运行时状态机或 Hook（钩子）一样强制阻断越门禁行为。
- 第三方仓库缺少正式初始化入口时，流程只能报告阻塞并停止。
