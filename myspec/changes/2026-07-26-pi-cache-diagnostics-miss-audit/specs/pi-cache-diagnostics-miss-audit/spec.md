# pi-cache-diagnostics-miss-audit（缓存未命中审计）

## 目标行为

`pi-cache-diagnostics`（Pi 缓存诊断插件）只负责捕获 Pi（编码代理）原生认定的缓存 Miss（未命中）事件，并为每个事件保存客户端可观测范围内可供事后分析的完整证据链。大模型差异分析和归因不属于插件职责。

## 缓存 Miss（未命中）事件

- 唯一判定来源是 Pi（编码代理）内部 `detectCacheMiss`（缓存未命中检测）的返回结果。
- 插件直接复用该实现，不复制算法、不维护容差、不维护上一提示词数量或缓存活动状态。
- 模型切换、压缩、分支摘要、恢复会话和其他边界完全继承 Pi（编码代理）原生语义。
- 删除大型 Miss（大型未命中）分类；所有原生 Miss（未命中）事件使用相同证据流程。

## 支持范围

- 仅审计 `openai-codex`（OpenAI Codex 模型服务）。
- 其他模型服务属于明确技术债，不提前建设通用抽象。
- 未来扩展其他模型服务时仍必须复用 Pi（编码代理）原生检测，并分别适配其证据格式。

## 证据采集

### 请求窗口

插件为当前会话维护滚动请求窗口。窗口从上一次有效请求及响应开始，包含其后全部关键完成态事件、本轮可观测请求与响应，直到当前最终助手消息结束。

未触发 Miss（未命中）时，插件只保留当前有效请求及响应作为下一窗口的基准。触发 Miss（未命中）时，窗口被固化为永久证据包，随后仍以当前有效请求及响应建立下一窗口。

### 请求检查点

- 每个会话保留一个最新请求检查点，以支持重新加载、退出后恢复和会话切换。
- 活动检查点可使用未压缩格式；会话退出或切换时压缩保存。
- 新的有效请求完成后覆盖旧检查点，不累计保存全部正常请求。
- 任意历史分支跳转可能无法恢复目标节点当时的完整模型服务载荷。该位置是证据边界；此后的第一次相关证据必须标记 `evidenceIncomplete: true`，不得声称完整。

### 关键事件

记录以下完成态事件及可用原始内容：

- 会话开始、关闭、压缩和分支切换；
- 用户输入；
- Agent（代理）开始、结束和轮次边界；
- 完整系统指令和上下文；
- 工具执行开始与结束，包括工具名称、调用标识、参数、结果和错误状态；
- 模型和思考级别切换；
- `before_provider_request`（发送前请求）处观测到的完整载荷；
- 过滤后的请求头；
- HTTP（网络请求协议）状态和过滤后的响应头；
- 最终助手消息、服务端用量及 Pi（编码代理）原生 Miss（未命中）结果；
- 原始 OpenAI Codex（模型服务）传输统计快照；
- 审计写入、压缩、恢复和完整性状态。

不记录消息流式片段或工具局部更新。

### 可观测边界

- 在 `before_provider_request`（发送前请求）处理器位置捕获的载荷命名为 `observedProviderPayload`（观测到的模型服务载荷）。后续扩展可能继续修改载荷，因此不得称其为最终网络请求。
- 每次该事件生成一个 `providerRequestId`（模型服务请求标识）。OpenAI Codex（模型服务）内部可能执行不可逐次观测的 WebSocket（网络长连接）重试或 SSE（服务端事件流）回退；插件不得伪造每次内部传输尝试的标识或关联。
- 保存请求前和响应后的完整原始传输统计快照，不预计算差值。
- 插件保证保存客户端可观测事实，以便定位首次可观测前缀变化及直接前因；不保证证明服务端内部缓存失效根因。

## 证据安全

- 缓存相关载荷、系统指令、工具定义、消息、工具参数和工具结果允许以本机明文证据保存。
- 请求头与响应头采用明确允许清单，只保存缓存、路由、模型版本、客户端版本、追踪、请求标识、重试、限流和日期等诊断字段的值。
- 认证、Cookie（会话数据）和其他凭据字段只保存字段名与已排除标记，不保存值。
- 未列入允许清单的头只保存字段名，不保存值。

## 事件标识与时间

- 每个会话使用统一、严格递增的 `eventSequence`（事件序号）确定内部顺序。
- 每个事件同时保存：
  - `timestampMs`：Unix 毫秒时间；
  - `timestampUtc`：UTC（协调世界时）ISO 8601；
  - `timestampLocal`：带本机时区偏移的 ISO 8601。
- Pi（编码代理）源事件自带时间戳时，另存为 `sourceTimestampMs`，不得覆盖采集时间。

## 永久证据包

### 组织

新证据位于 Pi（编码代理）诊断目录下的 `pi-cache-diagnostics/` 子目录：

- 活动会话使用独立临时文件；
- 永久证据按会话哈希分组；
- 每次 Miss（未命中）生成一个自包含 `.jsonl.gz` 文件；
- 相邻连续 Miss（未命中）的证据可以重复，以保证每个文件可独立分析；
- 永久证据不自动删除。

文件名包含时间、事件序号、Miss（未命中）令牌数和 `providerRequestId`（模型服务请求标识），不得包含敏感内容。

### 内容边界

每个证据包依次包含：

1. `evidence_manifest`（证据清单）；
2. 上一次有效请求的观测载荷、过滤请求头、响应与用量；
3. 上一次响应结束后的全部关键事件；
4. 本轮可观测请求、失败、取消、重试与响应事件；
5. 触发 Miss（未命中）的最终助手消息、服务端用量和原生检测结果；
6. `evidence_complete`（证据完成）事件。

证据清单包含 `schemaVersion: 1`、Miss（未命中）事实、模型、会话哈希、时间范围、事件数量和证据完整性状态。后续兼容新增字段不提升版本；破坏性格式变化必须提升版本。

### 固化与故障

- 先完成未压缩临时 JSONL（逐行 JSON 格式）文件并追加完成事件。
- 压缩到临时 Gzip（压缩格式）文件。
- 压缩成功后原子改名为最终 `.jsonl.gz`。
- Gzip（压缩格式）完整性检查已足够，不增加自定义校验算法。
- 压缩失败时保留完整未压缩文件并改名为 `.jsonl.failed`，记录原因并通知用户。
- 写入、压缩或恢复失败不阻塞、不取消模型请求；对应窗口标记为不完整。
- 同类持续错误只主动通知一次，避免刷屏；后续请求继续尝试恢复。
- 不完整证据可以保存，但必须明确标记，不得伪装为完整证据。

## 用户界面

- 正常 Miss（未命中）静默固化，不逐次通知。
- 只有写入、压缩、恢复等审计故障主动通知。
- `/cache-diagnostics`（缓存诊断命令）显示采集状态、永久证据数量、最近一次证据时间、证据目录和当前错误状态。
- 插件不提供分析命令，不调用大模型，不输出差异或归因。

## 旧日志

现有 `openai-codex-cache.jsonl` 日志保持只读，不迁移、不删除、不修改，也不计入新证据包。新格式从独立目录开始记录。

## 验收

必须从真实 Pi（编码代理）扩展入口完成端到端验证，覆盖：

- 正常命中不生成永久证据；
- 原生 Miss（未命中）生成完整可解压证据包；
- 模型切换仍按原生规则处理；
- 压缩和分支摘要按原生规则重置；
- 重新加载和恢复会话后继续比较并恢复检查点；
- 历史分支跳转后首次相关证据明确标记不完整；
- 失败、取消和自动重试进入可观测时间线且关联不被伪造；
- 请求头和响应头中的敏感值被排除；
- 压缩失败保留完整未压缩证据；
- 审计故障不影响模型请求；
- `/cache-diagnostics`（缓存诊断命令）只展示采集状态，不执行分析。
