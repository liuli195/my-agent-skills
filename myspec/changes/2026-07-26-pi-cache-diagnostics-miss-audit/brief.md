# Outcome

将 `plugins/pi-cache-diagnostics` 的缓存 Miss（未命中）审计重构为三层架构：插件直接复用 Pi（编码代理）原生检测规则捕获缓存 Miss（未命中），并保存足以供大模型事后定位客户端可观测前缀变化及直接前因的完整证据链；差异分析和归因由后续分析层负责。

# Scope

- 第一层：直接调用 Pi（编码代理）内部 `detectCacheMiss`（缓存未命中检测），以原生返回结果作为唯一的缓存 Miss（未命中）事件定义。
- 第二层：记录完成态关键事件、滚动请求窗口和每个会话的最新请求检查点。
- 每次缓存 Miss（未命中）生成一个自包含的 `.jsonl.gz` 压缩证据包。
- 仅支持 `openai-codex`（OpenAI Codex 模型服务）。
- 更新 `/cache-diagnostics`（缓存诊断命令）以显示采集状态、证据数量、最近证据、目录和错误状态。
- 保留旧日志但不迁移。

# Non-goals

- 不在插件中计算内容差异、哈希、片段或归因提示。
- 不实现大模型分析命令或分析脚本。
- 不支持其他模型服务。
- 不修改 Pi（编码代理）以增加最终网络请求或内部传输尝试观测接口。
- 不创建 `CONTEXT.md`（领域词汇表）或 ADR（架构决策记录）。
- 不迁移、删除或修改旧的 `openai-codex-cache.jsonl` 日志。

# Acceptance examples

- 正常缓存命中时，仅滚动请求检查点，不生成永久证据包。
- Pi（编码代理）原生 `detectCacheMiss` 返回结果时，生成可解压、自包含、带格式版本、证据清单和完成标记的 `.jsonl.gz` 文件。
- 模型切换、压缩和分支摘要严格遵循 Pi（编码代理）原生检测结果，插件不维护第二套规则。
- 重新加载或恢复会话后，可恢复原生比较基准和该会话的最新请求检查点。
- 任意历史分支跳转后无法恢复完整前序载荷时，首次证据明确标记 `evidenceIncomplete`（证据不完整）。
- 请求失败、取消和自动重试进入可观测时间线，但是否形成 Miss（未命中）完全服从原生规则。
- 敏感请求头和响应头的值不会写入证据。
- 压缩失败时保留完整未压缩证据；审计失败不阻塞模型请求。

# Constraints and invariants

- 缓存 Miss（未命中）检测必须复用 Pi（编码代理）原生实现，即使需要从安装目录加载内部模块；不得复制算法或自行维护比较基准。
- 插件只能保证定位客户端可观测范围内的首次前缀变化及直接前因，不能证明服务端内部缓存失效根因。
- `before_provider_request`（发送前请求）载荷命名为 `observedProviderPayload`（观测到的模型服务载荷），不得宣称它必然是最终网络请求。
- 每次模型服务请求观测生成一个 `providerRequestId`（模型服务请求标识）；不得把它描述成每次内部传输尝试的标识。
- 永久证据不得自动删除。每个历史会话只保留一个滚动请求检查点。
- 每个证据包必须独立完整；连续 Miss（未命中）允许重复相邻请求证据。
- 证据内容允许保存完整明文缓存相关内容，但必须排除认证凭据。
- 写入、压缩或恢复失败不得阻塞或取消模型请求；不完整证据不得伪装成完整证据。
- 技术债：当前只支持 `openai-codex`（OpenAI Codex 模型服务），未来扩展时复用原生检测并按模型服务定义证据适配。

# Decisions

- 采用三层职责：原生检测、证据固化、外部大模型事后分析。
- 删除 `missedTokens >= 20000` 的大型 Miss（大型未命中）分类和通知。
- 删除插件现有的差异、哈希、前缀比较和片段生成逻辑。
- 只记录完成态关键事件，不记录 `message_update`（消息流式更新）或工具局部更新。
- 关键事件包括会话生命周期、用户输入、Agent（代理）与轮次边界、完整系统指令与上下文、工具执行开始与结束、模型与思考级别切换、观测请求载荷、过滤后的请求头、网络响应、最终助手消息、服务端用量和审计状态。
- 请求头和响应头采用允许清单；认证和 Cookie（会话数据）等敏感字段只记录名称和已排除标记。
- 使用统一递增 `eventSequence`（事件序号），同时保存 `timestampMs`、`timestampUtc` 和 `timestampLocal`；源事件自带时间时另存 `sourceTimestampMs`。
- 证据包第一行为 `evidence_manifest`（证据清单），包含 `schemaVersion: 1`、Miss（未命中）事实、模型、会话哈希、时间范围和事件数量。
- 文件名包含时间、序号、Miss（未命中）令牌数和模型服务请求标识。
- 先写完整临时 JSONL（逐行 JSON 格式），追加 `evidence_complete`（证据完成）后压缩到临时 Gzip（压缩格式）文件，再原子改名为最终 `.jsonl.gz`。
- 压缩失败时保留 `.jsonl.failed` 并通知；持续错误每类只通知一次。
- 每次 Miss（未命中）静默固化；仅审计故障主动通知。
- 新日志位于 `diagnostics/pi-cache-diagnostics/`：每个活动会话一个临时文件，每次 Miss（未命中）一个永久压缩文件。
- 每个会话保留一个最新请求检查点；活动时未压缩，退出或切换时压缩，恢复后继续并在新请求成功后覆盖。
- 旧日志只读保留，新格式从零开始。
- 用户已确认本 brief 与完整目标规格准确记录共享理解，并允许进入 Build（构建）阶段。

# Open questions

无。

# Verification expectations

必须通过本仓库 `build-and-verify`（构建与验证）入口执行验证，并完成从真实 Pi（编码代理）扩展入口出发的端到端回归。回归至少覆盖正常命中、原生 Miss（未命中）、模型切换、压缩或分支摘要、重新加载与恢复、历史分支跳转、失败与重试、敏感头过滤、压缩失败和审计失败开放。未能真实触发或验证的场景必须明确记录为未验证，不得以单元测试拼接替代端到端主流程。
