# 01: 确保热修复完整验证真实、非空且通过

**What to build（交付行为）:** 维护者沿用现有热修复入口，在受管完整验证真实执行、非空且通过后才继续推送；证据异常则停止且不记成功审计。单票交付最小修复、对应技能说明和精简回归，自定义验证和其他模式保持兼容。

**Blocked by（前置依赖）:** None (can start immediately)（无前置票据；实施仍须等待门禁一授权）。

**Status（状态）:** ready-for-agent

- [ ] 逻辑入口为 build-and-verify（构建与验证工具）时先消费已有 PR_FLOW_TOOL_COMMANDS（工具命令映射）得到参数，再仅在复制的子进程环境中移除已消费变量；父环境和其他变量不变。
- [ ] 逻辑入口为 build-and-verify（构建与验证工具）的 verify（验证）且含 --full（完整模式）时，不论映射有无，都要求退出码为 0、标准输出最后 status（状态）为 passed（通过）、最后 checked（已检查项）非空、最后 full-not-run（完整验证未运行）为 false（否）；较早通过记录不覆盖最终结果。
- [ ] 空输出、缺失证据、空检查、skipped（跳过）、最终 failed（失败）和非零退出均沿用 hotfix_verify_failed（热修复验证失败），不推送、不产生成功审计；合法标准错误警告不单独导致失败。
- [ ] 自定义命令保留原退出码语义和环境；fast（快速模式）及其他工具模式不套用完整证据门禁，保留现有 Windows（操作系统）路径兼容行为。
- [ ] 保持现有验证函数接口，复用现有能力，不新增运行器、抽象、验证入口或临时启动器；分支保护、授权短语、远端复核及构建发布入口不变。
- [ ] 从现有最高层级热修复真实入口复用已确认公开测试接缝，真实调用主入口，沿用已有版本管理及子进程替换，不替换目标验证函数；精简覆盖证据与环境隔离矩阵，断言异常不推送且不记成功审计，保留自定义与跨平台兼容回归。
- [ ] 同步对应技能说明；开发获批后由云端实施及独立审查、本机沿用既有构建与验证入口执行红绿、正式验证和真实入口快速冒烟，功能分支经 GitHub（代码托管平台）同步。不运行全仓完整回归，不为覆盖断言扩大成本。
- [ ] 不将历史本机异常或后续补跑作为本次通过证据；明确历史引号处理和吞掉退出码的具体机制尚未独立复现。

需求与范围以同一变更的规格为准。用户已确认本轮需求前沿及单票粒度，但尚未授权“门禁一——开始开发”；本票状态不构成切分支、实施、测试、构建、提交或推送许可。
