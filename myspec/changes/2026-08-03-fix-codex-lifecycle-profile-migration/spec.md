# Orca 会话下的 Codex 生命周期目录与旧来源迁移

**Status（状态）：** ready-for-agent

## Problem Statement（问题说明）

Orca（开发环境）启动的 Pi（编码代理）会话会提供一个临时 Codex（代码代理）配置目录。生命周期命令直接继承该环境，把隔离会话的市场快照当作用户的持久客户端状态，导致 MySpec（自有规格）和 Build and Verify（构建与验证）的诊断、初始化或更新失败，或在错误目录中完成操作。

同时，`update`（更新）只识别当前稳定来源。目标客户端仍使用 Legacy MySpec Source（旧 MySpec 来源）时，更新可能只替换命令行软件包，却跳过客户端迁移并返回成功，用户因而无法从结果判断真实状态。

## Solution（方案）

生命周期命令通过共享的 Codex 配置目录解析规则管理客户端目标：显式的 `--codex-home`（Codex 配置目录参数）优先；当继承目录被识别为 Orca 临时配置目录时，默认选择用户 Codex 配置目录；非 Orca 的用户自定义目录继续生效；无法使用选定目录时返回明确错误，不静默改用其他目录。两个命令行程序对 Codex 子进程和配置文件使用同一个解析结果，并报告实际选择及其来源。

`update` 在任何软件包、待处理状态或客户端写入前检查三个受支持客户端的来源状态。发现需要客户端迁移的旧来源时，命令以非零结果停止，列出实际受影响客户端和精确的 `init`（初始化）命令；它不自动修改未受影响的客户端。用户完成迁移后重新执行 `update`，更新才继续刷新稳定来源并完成只读诊断。

## User Stories（用户故事）

1. 作为 Orca 用户，我希望运行生命周期诊断时不会读取失效的 Orca 临时市场快照。
2. 作为客户端维护者，我希望生命周期命令默认操作用户 Codex 配置目录，而不是隔离会话目录。
3. 作为有多个 Codex 配置的用户，我希望通过 `--codex-home` 精确选择本次操作的配置目录。
4. 作为使用自定义 Codex 配置目录的用户，我希望非 Orca 的显式配置继续被尊重。
5. 作为用户，我希望看到命令实际选择的 Codex 配置目录及选择原因。
6. 作为用户，我希望配置目录不可用时得到明确的非零错误，而不是把状态写入另一个目录。
7. 作为生命周期命令使用者，我希望 `update` 不把仍存在旧来源的状态报告为成功完成。
8. 作为用户，我希望迁移阻断信息只列出实际受影响的客户端和可直接执行的命令。
9. 作为用户，我希望迁移被阻断时软件包、客户端配置和待处理状态保持不变。
10. 作为维护者，我希望客户端迁移继续遵守既有的旧来源清理、项目级保留和无关状态保护规则。
11. 作为用户，我希望完成客户端迁移后重新运行 `update` 能刷新稳定来源并验证结果。
12. 作为 MySpec 或 Build and Verify 用户，我希望两个命令行程序遵守相同的目录选择和迁移阻断语义。

## Implementation Decisions（实现决定）

- 复用现有共享生命周期实现，不在 MySpec 和 Build and Verify 中分别实现 Codex 配置目录规则。
- `--codex-home` 是本次操作的显式目录覆盖；未提供时，解析器区分 Orca 临时配置目录、非 Orca 自定义目录和用户默认目录。
- `doctor`（诊断）、`init --codex`、`init --all` 和 `update`（更新）支持该目录选择；内部更新重启必须继续传递同一选择。
- 解析出的目录同时用于 Codex 子进程和 Codex 配置文件读写。解析器不修改父进程环境，也不因任意自定义目录损坏而静默回退。
- 诊断结果必须使实际目录和选择来源可观察；缺少可用目录时返回可操作错误。
- 更新前置检查必须识别稳定来源、Legacy MySpec Source（旧 MySpec 来源）和无关来源，复用既有来源语义，不把旧来源当作“未安装”。
- 发现旧来源时，更新在软件包安装、待处理状态创建和客户端写入之前停止，并报告精确客户端初始化命令。
- `update` 不自动执行客户端迁移；现有 `init` 入口负责迁移，且继续按现有契约保护项目级旧来源和无关客户端状态。
- 只有完成迁移后，`update` 才能进入稳定来源刷新和最终诊断。
- 变更同时覆盖 MySpec 和 Build and Verify 两个发布包的公开命令行入口。

## Testing Decisions（测试决定）

- 最高测试接缝是打包后隔离安装的两个命令行程序；测试观察标准输出、标准错误、退出码、客户端调用和实际配置状态，不绑定私有辅助函数。
- 使用受控 Codex、Pi 和 Claude 客户端替身验证目录选择、旧来源分类、精确迁移命令和无写入阻断。
- 覆盖 Orca 临时目录、用户默认目录、显式自定义目录、显式参数覆盖和不可用目录错误。
- 覆盖仅旧来源、稳定与旧来源并存、仅部分客户端受影响、迁移失败后重试以及迁移后重新更新。
- 使用打包后的真实命令行程序分别验证 MySpec 与 Build and Verify 的结果一致。
- 外部客户端适配完成后执行一次真实 Orca 环境最小冒烟；测试前保存用户级状态，结束后恢复并比较，无法证明恢复时停止。
- 使用仓库规定的 Build and Verify 快速验证入口完成集成验证；高风险主路径还需覆盖失败、迁移和恢复结果。

## Out of Scope（范围外）

- 修改 Orca、Pi 本体或 Codex 客户端本身。
- 新增持久化的 Codex 目录配置文件。
- 让 `update` 自动执行客户端迁移。
- 改变既有 `init` 对项目级旧来源、无关插件、市场和用户文件的保护规则。
- 发布 npm（软件包管理器）包、刷新市场、安装到用户环境或执行 PR（拉取请求）交付。
- 新增完整端到端回归；仅增加本次公开行为所需的最小真实入口和受控替身覆盖。

## Further Notes（补充说明）

#270 中的 Orca 临时目录误用与 #265 的目录选择部分属于同一配置目录解析根因；#265 剩余的旧来源静默跳过属于独立的更新状态机缺陷。本变更将两者放在同一共享生命周期模块中，但保持两个独立的纵向实施票据。
