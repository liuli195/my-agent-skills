# 05 — 统一更新、安装锁和中断恢复

**What to build:** 发布模式用户能够通过一次 `myspec update` 将 CLI（命令行程序）和所有已安装 Agent Plugin（代理插件）升级到同一 npm 最新版本；并发或中断操作能够被诊断并通过重复命令继续收敛。

**Blocked by:** 03 — 让 Claude 使用统一软件包自带市场；04 — 让 Codex 使用统一软件包自带市场.

**Status:** ready-for-agent

- [ ] `myspec update` 只在发布模式运行，并在修改前预检 npm、Pi、Claude、Codex 的适用状态。
- [ ] 更新全局 npm 包后使用新 CLI（命令行程序）继续流程，刷新所有已安装插件并运行只读诊断。
- [ ] 开发模式调用 `update` 明确失败，并要求先显式切换回发布模式，不隐式修改模式。
- [ ] `init` 与 `update` 共用用户级安装锁；活跃锁阻止并发操作，锁信息包含进程、开始时间和命令。
- [ ] 锁不因超时自动清理，只有确认记录进程不存在时才允许回收。
- [ ] 每个外部修改步骤完成后记录恢复进度；失败立即停止、保留原始错误且不宣称整体成功。
- [ ] 重复原命令能够跳过已确认完成的步骤并最终收敛，不执行跨客户端自动回滚。
- [ ] `doctor` 只读报告部分更新、版本失配和锁状态，不修改任何安装状态。
