# Outcome

新增一个 Pi（编码代理）专用扩展，在状态栏显示 Codex（代码代理）订阅的 7 天额度剩余百分比和重置倒计时。

# Scope

- 新增名称以 `pi-` 开头的扩展。
- 状态文本格式为 `Codex：85%/6D21H`。
- 该状态位于 MCP（模型上下文协议）之后、yolo（免确认模式）之前。
- 百分比表示 7 天额度剩余比例；倒计时表示距离该额度窗口重置的剩余整天和整小时。

# Non-goals

- 不展示其他时间窗口或其他订阅产品的额度。
- 不修改或安装用户环境中的扩展。
- 不新增外部依赖。

# Acceptance examples

- 7 天额度剩余 85%，距离重置还有 6 天 21 小时时，状态栏显示 `Codex：85%/6D21H`。
- 状态项视觉顺序为 MCP（模型上下文协议）→ Codex（代码代理）→ yolo（免确认模式）。
- 倒计时随时间推进更新到当前剩余整天和整小时。

# Constraints and invariants

- 扩展名称必须以 `pi-` 开头。
- 使用 Pi（编码代理）公开扩展接口与现有状态栏机制。
- 不泄露 Codex（代码代理）认证信息。

# Decisions

- 仅展示 7 天额度窗口。
- 使用用户指定的中文全角冒号、百分号、`D` 与 `H` 格式。
- 尚未取得 7 天额度数据或读取失败时隐藏状态项。
- 额度剩余百分比、剩余天数和剩余小时均向下取整，只显示完整单位。
- 已知重置时间到达后、尚未取得新窗口数据时显示 `Codex：--%/0D0H`。
- 取得过有效数据后，即使当前模型不是 Codex（代码代理）也继续显示订阅状态。
- 取得有效额度后，临时刷新失败时继续显示上次百分比并推进倒计时；到重置时间后显示 `Codex：--%/0D0H`。
- 每 15 秒通过 Codex API（应用程序接口）重新获取额度与重置倒计时，并同时更新百分比和倒计时两个显示值。
- 允许用户覆盖刷新间隔，未配置时为 15 秒。
- 用户通过 Pi（编码代理）全局 `settings.json`（设置文件）的 `codexUsageStatus.refreshSeconds` 配置刷新间隔。
- 刷新间隔配置无效时静默回退到 15 秒。
- 用户已确认本 brief（需求摘要）与完整目标规格，可进入实现。

# Open questions

- 无。

# Verification expectations

- 覆盖额度百分比和倒计时格式化的可运行检查。
- 从 Pi（编码代理）扩展加载入口验证状态项的更新与清理。
- 以实际状态栏渲染验证 MCP（模型上下文协议）→ Codex（代码代理）→ yolo（免确认模式）的顺序。
