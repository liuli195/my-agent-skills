# 02 — 等待完整规则集收敛并同步完成合并

**What to build:** 让已通过必需检查的 PR（拉取请求）在规则集状态传播期间有界重试普通合并，并且只有确认合并成功后才报告完成和执行清理。

**Blocked by:** 01 — 观测检查从尚未报告到终态。

**Status:** completed

## 技术设计架构

### Module、Interface 与 Seam（模块、接口与接缝）

- 复用票据 01 的“合并门禁观测” Module（模块），不保留独立的规则集等待器；规则集恢复只消费统一观测 Interface（接口）的结果。
- 普通 `gh pr merge --match-head-commit` 是完整规则集的最终裁决 Seam（接缝）。必需检查通过只证明合并的必要条件，不能替代 GitHub 对 CodeQL（代码扫描）、审查和其他规则的最终判断。
- `complete` 和 `tweak`（小改）继续共用生命周期；两者只在审查门禁是否跳过上保持现有差异，不建立第二套合并流程。

### 合并状态推进

```text
门禁 PASSED
  → 复核审查、源提交、目标提交
  → 普通合并
      → 成功：确认命令成功后进入清理
      → 规则集拒绝：进入规则集传播窗口
      → 其他错误：保留原错误并停止

规则集传播窗口
  → 刷新 PR
  → 复用统一门禁观测
  → 复核审查、源提交、目标提交
  → 再次普通合并
      → 成功：进入清理
      → 持续规则集拒绝且窗口耗尽：ruleset_merge_blocking
```

### 有界重试与安全条件

- 规则集传播窗口最多 60 秒，使用既有轮询间隔但单次休眠不得超过剩余时间。
- 重试不得追加 `--auto`（自动合并）或 `--admin`（管理员绕过），不得创建空提交。
- 如果统一观测返回等待、失败、取消或不可用，立即返回对应检查停止状态，不继续尝试合并。
- 每次合并前必须重新读取 PR，并确认源提交和目标提交仍等于最初通过门禁的快照；审查要求也必须重新检查。
- 持续规则集拒绝时，最终详情保留首次和最后一次平台错误、重试次数及可复制的恢复命令。

### 清理后置条件

- 只有普通合并命令成功后才能输出 `merge_complete` 并调用现有清理流程。
- 删除自动合并建议识别、自动合并参数和围绕自动合并的第二次重试分支，避免“已排队”被解释为“已合并”。
- 清理行为本身不在本票据重构；继续使用现有清理后置条件和恢复动作。

## 验收标准

- [x] 普通合并仍是完整规则集的最终裁决，规则集拒绝后复用票据 01 的观测结果并在 60 秒内有界重试。
- [x] 每次重试前复核源提交、目标提交和审查状态，任一变化时停止。
- [x] 持续规则集阻塞保留 `ruleset_merge_blocking`、首次与最终平台错误及重试证据。
- [x] 删除 `--auto`（自动合并）恢复路径；只有普通合并成功后才输出 `merge_complete` 并清理。
- [x] 公开命令回归先证明当前实现会进入自动合并路径，再覆盖规则集传播后成功、持续阻塞和提交变化。
- [x] Pi `pr_flow` 工具的发布形态冒烟重放创建后立即 `complete` 的完整序列；GitHub 真实 PR 在 Gate 3 交付时再次观察规则集传播与实际合并清理。

## Behavior evidence（行为证据）

- Red（失败）：基线测试明确要求规则集提示后追加 `--auto`（自动合并），与同步完成设计冲突。
- Green（通过）：公开命令回归覆盖普通合并多次重试后成功、60 秒持续阻塞、检查退回等待、提交变化和审查变化。
- Green（通过）：PR Flow 相关公开命令、插件包和 Pi 扩展测试结果 `313 passed`。
- Smoke（冒烟）：从打包后的 Pi `pr_flow` 工具真实执行 `complete`，经独立进程和 GitHub CLI（命令行工具）Adapter（适配器）重放后确认普通合并及清理完成；GitHub 真实 PR 留待 Gate 3 交付。
- Review（审查）：总体审查发现合并前使用旧 PR 快照；修复后门禁观测返回最新快照，并在每次合并前再次读取 PR、复核检查、提交和审查。
- Risk（风险）：真实 GitHub 规则集传播时间仍需在交付 PR 上观察，持续阻塞会安全停止而不启用自动合并。
