# 子代理策略与用户级提示词对齐

## Problem Statement

当前 `subagent-policy`（子代理策略）技能、四个居民代理配置和正式 MySpec（自有规格）需要保持一致。架构师的本地默认配置已调整为 `gpt-5.6-sol` 与 `medium`（中），但用户明确指定时的网页 ChatGPT 路径、具名代理优先级、通用代理回退和权限失败处理需要在策略中明确。引入网页 ChatGPT 时同时写入 Codex（代码代理）与 Claude Code（Claude 代码代理）用户级提示词的整段协作说明，现在已经不再需要。

## Solution

保持现有纯 Skill（技能）结构和四个固定角色：架构师默认使用本地具名代理，用户明确指定时按宿主提供的 `awehitch` 技能路径使用网页 ChatGPT；不可用时回退到本地具名架构师，再按统一规则回退到通用代理。其他角色优先使用宿主已配置的具名代理；宿主不支持具名代理时才使用通用代理。模型或思考强度不可用时使用宿主默认值，但保留角色职责和读写边界；实际权限无法满足只读边界时，保留具名代理继续执行只读任务，并声明“只读边界回退”和实际权限，不得扩大写入范围。发生回退时声明回退，不把回退配置描述为指定配置。

同时从 Codex 用户级 `AGENTS.md` 和 Claude Code 用户级 `CLAUDE.md` 删除网页 ChatGPT 协作提示词，只保留原有语言输出规则；不删除网页 ChatGPT 技能、备份文件或其他配置。

## User Stories

1. 作为主 Agent（代理），我希望在明确指定时让架构师走网页 ChatGPT 路径，以便按需获得独立的架构视角。
2. 作为主 Agent（代理），我希望网页 ChatGPT 不可用时明确回退到本地具名架构师，以便回退行为可追踪。
3. 作为主 Agent（代理），我希望四个角色默认使用宿主已配置的具名代理，以便复用已定义的模型和读写边界。
4. 作为跨宿主使用者，我希望没有具名代理时仍能使用通用代理承载同一角色，以便策略保持通用。
5. 作为审查者，我希望模型或思考强度回退时看到实际配置，以便不会把宿主默认配置误认为指定配置。
6. 作为安全边界维护者，我希望只读角色无法获得实际只读权限时保留具名代理身份，声明只读边界回退，并继续遵守不写入限制。
7. 作为实施者，我希望 Implementer（实施者）仍是唯一可以在明确授权范围内写入的角色。
8. 作为技能维护者，我希望网页 ChatGPT 的技能入口在策略中可定位，但不把策略写死为某个宿主的绝对路径。
9. 作为用户，我希望 Codex 和 Claude Code 的用户级提示词不再自动推荐网页 ChatGPT，以便删除不再需要的全局协作规则。
10. 作为用户，我希望删除提示词时保留其他语言规则、网页 ChatGPT 技能和本地代理配置。
11. 作为维护者，我希望技能、正式规格、契约测试和四个居民代理配置的模型与边界保持一致。
12. 作为交付审查者，我希望本次变更不检查网页 ChatGPT 当前是否可用，也不改变主会话权限。
13. 作为使用具名只读代理的人，我希望只读边界被父会话覆盖时仍使用原具名代理，并明确报告边界回退，而不是被误报为通用代理回退。

## Implementation Decisions

- 继续使用现有 `subagent-policy` 单文件 Skill（技能）作为策略契约，不新增调度脚本或生成器。
- 本地角色表将 Architect（架构师）固定为 `gpt-5.6-sol` 与 `medium`（中）；其他三个角色沿用已确认配置。
- Architect（架构师）的网页 ChatGPT 路径仅在用户明确指定时启用，入口以宿主提供的 `awehitch/SKILL.md` 表示。
- 具名代理回退和模型/思考强度回退分别表达，但通用代理回退只保留一条统一规则；实际权限不能回退放宽。
- 只读边界被宿主或父会话覆盖时，保留具名代理身份继续执行只读任务，报告“只读边界回退”和实际权限；该情况不归类为通用代理回退，主代理必须核对无写入。
- 四个用户级代理配置已经按角色表对齐；本次交付只记录和复核其状态，不将用户目录文件伪装成仓库文件。
- 从 Codex 用户级 `AGENTS.md` 与 Claude Code 用户级 `CLAUDE.md` 删除网页 ChatGPT 协作段落，保留原有语言规则。
- 正式 `myspec/specs/subagent-policy/spec.md` 只在门禁二授权后通过 `my-spec-add`（新增自有规格）应用同步。

## Testing Decisions

- 最高测试接缝继续使用现有 `subagent_policy.test.mjs`，通过宿主资源加载器真实加载技能，并检查角色表、网页路径、回退声明、边界和宿主中立性。
- 使用仓库规定的 `build-and-verify verify --project .` 快速验证；不新增验证入口。
- 对四个用户级代理配置执行静态字段复核，确认模型、思考强度、沙箱边界和边界保护提示与技能一致。
- 对只读居民代理复核边界回退提示，确认边界未收窄时仍保留具名代理身份并显式报告“只读边界回退”。
- 对两份用户级提示词执行文本复核，确认网页 ChatGPT、`awehitch`、C2C 和 Cloudflare 相关内容均已移除，语言规则仍存在。
- 本轮不检查网页 ChatGPT 当前可用性，不修改连接器或其他用户配置。

## Out of Scope

- 不删除或修改 `awehitch` 技能、连接器、备份文件和其他用户配置。
- 不改变主会话权限，不改变四个角色的职责名称，不新增通用角色。
- 不把四个用户级代理配置迁移进仓库，不新增生成器或同步工具。
- 不修改工作区之外的其他客户端提示词。
- 不在实施阶段修改正式 `myspec/specs/`。

## Further Notes

- 本次使用 Fast（快速）流程是用户明确选择的流程等级；按仓库规则，权限和跨宿主变化通常会触发 Full（完整），该例外将在门禁一证据中记录。
- 本次规格使用 `CONTEXT.md` 的 `Explorer（探索者）`；现有技能保留兼容用词 `Explorer（调查者）`，本次不改名。
