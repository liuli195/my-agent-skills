# 02 — 统一工具生命周期与身份

**What to build（构建内容）：** Build and Verify（构建与验证）成为独立 npm（软件包管理器）CLI（命令行程序），与 MySpec（自有规格）各自支持一致的发布版／源码版生命周期、三端 Agent（代理）初始化、诊断和更新；两者都能输出 PR Flow（拉取请求流程）所需的稳定工具身份。

**Blocked by（前置项）：** 01 — 移除派发票据状态门禁。

**Status:** completed

- [x] 两个包独立安装、独立版本演进，且都可从其 CLI（命令行程序）管理 Pi、Claude、Codex 的受管资源。
- [x] 发布版和源码版身份均可由只读 `doctor`（诊断）机器读取；源码模式切换校验官方远端、完整公开可检出的提交和干净工作树，失败时 `doctor` 不得输出受信任来源身份；成功身份包含官方来源、完整提交和固定包目录。既有生命周期测试使用受控的干净受信任源码替身覆盖后续切换路径，不得为了旧测试放宽这些校验。
- [x] 生命周期实现只有一个共享源码，两个包各自仅声明身份 profile（配置），共享实现自行读取 profile（配置），不依赖渲染器或生成器。受控打包模块只接受固定包名和原工作树外的输出目录；它在打包前校验固定包目录和清单包名、在打包后校验 Tarball（npm 包文件）清单包名，只在临时目录注入该实现，并以 `npm pack --ignore-scripts`（忽略脚本的打包）生成候选包；它拒绝未知包和仓库内输出目录，且其命令执行不得产生字节码缓存，完成后不写入包括忽略文件在内的原工作树。Tarball（npm 包文件）的公开 `doctor`（诊断）入口必须在脱离源码工作树时通过，是该模块的验证接缝。不得复制 MySpec（自有规格）管理模块、在原工作树生成运行时代码、添加 `prepack`（打包前）脚本或保留 `_myspec`（MySpec 私有）标识。
- [x] Build and Verify 的原有构建与验证语义保持不变，不合并到 MySpec（自有规格）或新增运行时依赖。
- [x] 安装与更新具备现有 MySpec（自有规格）同等的锁、恢复和诊断边界。
- [x] 候选 npm Tarball（npm 包文件）隔离安装后的 CLI（命令行程序）快速冒烟通过。
