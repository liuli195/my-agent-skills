# 06 — 发布选中 npm 包与首次发布准备

**What to build（构建内容）：** Release Flow（发布流程）保持现有单一发布版本和 `bumpPlugins`（提升插件列表）选择语义，并将 MySpec（自有规格）专用 npm（软件包管理器）发布最小泛化为对本次选中 npm 包的候选验证、完整性核对和发布；首次发布在远端操作前进入人工准备停止点。

**Blocked by（前置项）：** 02 — 统一工具生命周期与身份；04 — 将仓库自动化改用 Build and Verify CLI。

**Status:** ready-for-agent

- [ ] 本次选中的插件及其 npm（软件包管理器）包统一使用发布版本；未选中的包保留远端版本且不发布。
- [ ] 每个选中包从当前发布提交通过受控打包模块在临时目录打包、隔离快速验证，并只发布已验证候选的对应 Tarball（npm 包文件）。
- [ ] 每个包独立完成完整性核对及 `repository`（仓库）元数据／provenance（来源证明）预检。
- [ ] 若任一选中包尚未完成首次发布准备，工作流只验证并上传候选包，不发布、建标签、创建 GitHub Release（GitHub 发布）或更新市场。
- [ ] 正常发布在人工完成 npm 登录、双重验证和 Trusted Publisher（可信发布者）准备后恢复；不新增 OIDC（开放身份认证）端到端发布验证。
