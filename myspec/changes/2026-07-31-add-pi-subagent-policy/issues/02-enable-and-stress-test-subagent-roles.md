# 02 — 启用三个持久化角色并完成压力验收

**What to build:** 在获得用户级配置和安装授权后，通过现有 Pi Subagents（Pi 子代理）扩展持久化 Explorer（探索者）、Implementer（实施者）和 Reviewer（审查者），关闭并移除其他角色，直接从本地目录安装策略 package（包），再通过真实 Pi（编码代理）会话证明策略会稳定加载并选择正确角色。

**Blocked by:** 01 — 发布可诊断配置的 Pi 子代理策略

**Status:** ready-for-agent

- [x] 修改前保存并核对现有用户级 Pi（编码代理）与子代理配置；只处理已确认的旧角色定义。
- [x] 关闭扩展内置默认角色，最终有效角色列表仅包含 Explorer、Implementer 和 Reviewer，同时保留无关的并发、轮次、界面和记录设置。
- [x] Explorer 固定为 GPT-5.6 Luna Low（低）、继承系统规则，并只提供读取、搜索、只读命令和网页搜索能力。
- [x] Implementer 固定为 GPT-5.6 Terra Medium（中）、继承系统规则，并提供代码或文档实施所需的完整工具。
- [x] Reviewer 固定为 GPT-5.6 Sol Medium（中）、继承系统规则，并只提供读取、搜索和只读命令能力。
- [x] 三个角色不固定前后台、并行、隔离、最大轮次、持久会话或上下文继承方式。
- [x] Pi（编码代理）通过本地目录 package（包）能力加载策略，不新增安装或同步脚本。
- [x] 两个探索、两个实施和两个审查独立会话均加载 Skill（技能），并使用正确角色、模型、思考强度和工具权限。
- [x] 一个诱导使用禁用角色或临时模型的独立会话仍遵守封闭角色集合。
- [x] 一个受控项目级错误覆盖场景停止调用并提示具体配置差异，不破坏真实全局配置。
- [x] 主 Agent（代理）逐项核验八个会话记录中的 Skill（技能）加载与 Agent（代理）调用证据，并记录无法验证的部分。
