# 九个自有插件分端分发

状态：ready-for-agent
日期：2026-11-05；方向更新：2026-11-06
阶段：原范围及新增初始化、完整盘点清理范围的门禁一已确认；用户已确认分开云端与本机，并由发布流程承担正式账号交付。继续既有功能分支，不合并、不正式发布；具体永久删除仍须单独确认。

## 问题陈述

七个自有插件原由共享市场分发，两个命令工具另有独立市场及软件包入口。用户希望九项由同一清单维护，避免名称特判及初始化误卸载有效市场安装。实施中的云端双对象与本机联动切换增加了来源耦合；用户最新选择是本机继续原有正式／开发双市场，dot（云端助手）固定使用云端正式版，两者独立管理。

## 当前方案

九项范围保持不变：release-flow（发布流程）、pr-flow（拉取请求流程）、dev-flow（开发流程）、subagent-policy（子代理策略）、plugin-sync（插件同步）、retro-to-issues（复盘转任务）、data-store（数据存储）、my-spec（自有规格）、build-and-verify（构建与验证）。名称、发布输入和共享依赖属于清单数据，不根据插件名称增加处理分支，不将九项合为一个插件。

- dot（云端助手）只使用每项对应的云端正式对象；不再建设或保存新的 DEV（开发）账号对象，不再提供云端与本机联动切换。
- 本机 Codex（代码代理）与 Claude（代码助手）保留原正式市场 `my-agent-skills-marketplace` 和开发市场 `my-agent-skills-marketplace-dev`，继续按完整插件加市场标识走原生安装、更新和来源切换路径。两个市场及插件名称保持原样。
- 同名云端账号来源可能出现在本机 Codex（代码代理）。使用官方完整来源标识的启用配置隔离该账号来源，不能靠短名、自动改名、卸载远端对象或联动脚本解决。本轮只记录流程，不自动写本机配置。
- release-flow（发布流程）自身负责正式账号交付及历史只读对账，沿用正式发布主路径；plugin-sync（插件同步）只负责本机检查、安装更新、原双市场及同名来源隔离，移除其中云端账号教程、发布脚本引用和已废弃的账号联动职责。
- 继续复用原完整快照、发布、两个 NPM（软件包管理器）工具、自举及持续集成入口，不新增平行发布、配置修改或安装框架。

## 本次验收顺序（2026-11-06 用户已确认）

范围、四张票据和公开测试接缝保持不变，按两个阶段验收：

1. 开发阶段完成代码、离线验证、限定独立审查与完整正式规格预览，核对02、03、04的代码及开发交付准备证据，再按既有门禁二申请规格应用和拉取请求完整交付。发布后事项未完成不再反向阻塞该申请；代码、验证、审查或预览本身未通过仍须停止。
2. 正式发布另行获准且原发布流程成功后，先按03执行正式账号交付、九项分端真实发现与资源验收、初始化映射及重复初始化验证，再按04完成全量盘点和旧入口清理。新入口、依赖或恢复证据未通过的项继续保留，具体永久删除仍须精确确认。

开发阶段通过不代表03、04整票或本次迁移全部完成。发布后验收保持未完成状态，旧开发对象、映射和未决证据继续保留。本次确认只调整顺序，不授权规格应用、合并、正式发布、账号操作或真实环境清理，也不修改通用开发技能的门禁规则。

## 领域术语

- 插件：九项中可独立识别、安装和更新的一项能力。
- 市场：本机客户端的插件清单和来源入口，不等同于账号对象。
- 云端正式对象：同一插件在账号中持续使用的正式身份，身份与内容版本分开记录。
- 开发快照：未正式发布且含完整运行资源的离线产物，不再作为云端开发对象上传输入。
- 来源切换：本机客户端改变实际市场来源并核对结果，不等于上传或正式发布。
- 完整包：一个插件运行所需的技能正文、脚本、共享代码、资源及必要依赖，不是变化文件集合。

术语只记录于本需求目录，不改仓库通用领域文档。

## 用户故事

1. 九项由同一清单驱动，新增清单项不需要新增名称分支。
2. 本机正式／开发市场独立，测试不覆盖 dot（云端助手）的正式内容。
3. 同名账号来源不干扰本机选定市场，其他插件和第三方来源不变。
4. 正式账号包可追溯至真实正式发布，不能把功能分支或脏源码当正式版。
5. 新会话能发现目标技能及脚本资源，不把保存、安装或文件可读当作实际加载成功。
6. 两个命令工具初始化或更新后仍保留有效统一市场安装，软件包与自举继续可用。
7. 只重打变化插件及受共享依赖影响的完整包，未变化产物可验证复用。
8. 部分失败时能看到真实状态及可用恢复动作，未知账号写入不会被盲目重试。
9. 初始化迁移和清理有完整盘点、替代证据及精确授权，不损失用户原有数据。

## 实施决策

### 发布流程负责正式账号交付与对账

新账号包仅支持显式 `--account-mode RELEASE --release-ref <tag>`（正式账号模式及已核对的发布标签，也接受完整标签引用）；无模式的既有离线快照入口保持原行为。拒绝新的开发账号打包及交付，不以改名生成另一套云端开发身份。

发布技能主路径先读回既有发布 CI（持续集成）成功结果、真实 GitHub Release（代码托管发布记录）、标签及发布投影提交。仅本仓库 `.github/workflows/release.yml`（发布流水线）在原 `ci-publish`（持续集成发布）成功后增加正式包构建和保留步骤，通用模板不改：从原远端取得精确正式标签并分离检出该市场投影标签，复用目标仓库的 `tool-lifecycle/pack.py`（打包入口）生成正式完整目录并封装为 `dot-release-packages.tar`（完整正式包归档），只上传该归档文件，流水线产物名称仍为 `dot-release-packages`（完整正式包），不另上传裸目录或插件压缩包。原流水线全成功后，已登录环境取得该归档，经同一交付入口处理；CI（持续集成）不持有个人凭据、不直接写账号，不另建流程或强制新的任务编号契约。打包核对正式源码工作树的既有标签提交与实际输入一致且干净，并记录 `releaseRef`（正式引用）；打包本身不联网、不创建标签。账号交付固定脚本须另行读取真实远端发布记录及标签提交，确认不是草稿或预发布且与快照来源精确相符后，才进行账号预检／保存；脚本不冒称独立关联某次 CI（持续集成），其成功结果仍由既有主路径读回。不要求最新正式版或当前市场分支尖端，历史正式版本可从已核实固定标签的干净源码，用既有入口重建完整包并封装为相同归档，经同一入口交付，不强制新的任务编号。新正式账号包的版本与发布内容对应；当前功能分支即使已提交或工作树干净，也不能自行当作正式来源。保留来源、输入、目录和压缩包摘要核对，保存绑定用户已审阅的精确内容。追溯信息不代替上传授权，不允许夹带凭据。新增可选追溯字段缺席不得单独使历史正式对象或既有创建记录失效；已有证据按原身份、版本和状态核对，不补造历史来源。

跨环境只运输上述归档，保留内部清单、压缩包、完整目录、隐藏清单及文件模式；外层产物权限归一不影响归档内部执行位。交付命令仅在明确授权的交付目录内创建私有临时子目录，用 Python（编程语言）标准归档库受限解包：仅普通文件及目录，拒绝绝对路径、穿越、全部链接、异常类型、重复路径及超预算输入，保留模式，再复用原 ZIP（压缩包）摘要、完整目录、逐文件和执行位校验。不信任构建机器绝对路径、不改内容来源或获准摘要、不新增依赖、单独压缩包恢复、手工改权限或第二交付路径。成功或确认无账号写入的失败清理本次临时目录；未知或未验证结果保留目录及映射证据，并报告 `retainedDirectory`（保留目录）。

统一入口为 `release_flow.py deliver-account`（发布流程账号交付），参数为 `--project <repo> --manifest <mapping> --bundle <dot-release-packages.tar> --delivery-dir <明确授权目录> --expected-sha256 <已审阅摘要> --plugin <key>`，获准后加 `--apply`（应用）。已审阅摘要仍绑定本次插件 ZIP（压缩包），不是外层归档。默认不写账号，但仍需授权交付目录内临时解包；正式模式固定，不提供来源或直接快照参数。`release_flow.py reconcile-account`（发布流程账号对账）无需归档或交付目录，可选 `--mode RELEASE|DEV`（正式或开发，默认正式）兼容历史恢复；默认只读，应用只修改获准的本地记录，不写账号。仅在已登录环境且用户明确授权精确内容、目的地及创建／更新后交付一个正式私有对象。已有对象更新继续要求已核对的同一真实标识及私有、空共享目标的创建请求证据；内容更新不改变分享权限。个人对象没有分享上下文时如实记录权限未独立读回，不查询或冒称不可用的工作区创建服务。

保存的成功响应标识先写入本地映射，再核对精确账号目录条目。未知、未决或后检失败保留证据并停止，不重发保存、不安装、不删除、不回滚未知对象。清单任一条目的未决或未验证记录均阻断新账号写入，不能换插件或来源绕过历史记录。已有成功响应且身份明确的未验证记录可只读对账；用户另行授权后才修正本地状态。该动作可读取历史 DEV（开发）映射，但账号写入始终为零。旧开发远端对象、映射和未决证据本轮不删除。正式发布成功但正式包构建／保留失败，分别报告已发布及包准备失败，不称流水线全成功；发布成功但账号交付失败，报告账号未完成并保留映射证据。不能因后续 dot（云端助手）阶段失败重发正式发布；账号已发送或结果未知仅按安全对账恢复，不盲重发保存。

### 本机市场与账号来源隔离

本机按已有完整 `plugin@marketplace`（插件加市场）标识执行原市场切换；Codex（代码代理）和 Claude（代码助手）分别核对，不要求联动事务。修改前记录来源、版本、启用、范围、路径和恢复信息，失败只恢复本次已知变更。Claude（代码助手）同一市场串行，保留原安装范围，不要求模型新会话测试。

Codex（代码代理）隔离账号来源前，先读取当前配置及所有相关覆盖，核对默认启用和显式条目是否影响其他插件。只在用户授权精确配置后修改。通用临时参数形式为参数数组 `['-c', 'plugins._default.enabled=true', '-c', 'plugins.<完整账号来源标识>.enabled=false']`；键内不加入字面双引号。配置文件使用正常带引号的 TOML（配置格式）表名，例如 `[plugins."<完整账号来源标识>"]`。临时覆盖的代表插件实验已通过，但不等于本机配置已写入或全部九项已验收。不把默认允许和批量禁用写入固定工具逻辑。

### 初始化、发布与清理

初始化、更新、清理和恢复继续识别统一市场中的有效安装，保留两个命令程序、依赖、来源和版本校验。独立软件包命令只管理对应工具，不接管统一市场插件启停或卸载。

云端初始化沿用逐技能原生发现映射：只对已有具体路径及资源验证证据的项停止建立旧发现链接，未映射项保留原行为，替代失效则明确失败。迁移不默认关闭全部来源，不删除防止旧入口重建所需的映射。

收尾先完整盘点受控技能及本次测试残留，包括自有、第三方和开发依赖，逐项记录来源、实际入口、依赖、替代路径、验证和可恢复性。只有新入口及运行依赖已真实验证后才按精确授权清理；没有替代的项明确阻塞。永久删除仍须具体确认；本轮不删除历史开发远端对象、映射或未决证据。

正式发布复用现有预检、输入与版本检查、投影、软件包及持续集成入口；本轮不创建正式标签、不发布、不合并主干。正式主规格仍有旧七项和命令工具退出共享市场等冲突；开发阶段先准备完整预览，仅在既有门禁二明确授权后应用。本轮不提前改 `myspec/specs/`，不自行启动主规格应用。

## 测试决策

按端分别验收，不再要求云端双对象或三端联动切换。检查覆盖完整打包、变化及依赖影响、可验证复用、拒绝开发账号模式、真实发布来源及干净状态、远端正式发布与标签提交校验、交付身份及权限边界、部分成功保留和历史只读对账。复用已有构建验证入口，不另建检查系统。

dot（云端助手）的正式对象保存与实际新会话发现、资源运行分别取证；本机 Codex（代码代理）通过原市场路径验证正式→开发→正式，并核对同名账号来源隔离、无重复技能及资源；Claude（代码助手）只核对原生安装、启停、范围、版本、源码读取及文件。配置、保存返回值和内部假体均不能替代实际加载。没有精确操作授权或真实环境时明确待验证。

两个工具从真实初始化／更新入口验证统一市场安装不被误卸载；发布兼容通过原预检及发布形态冒烟验证，不为验证而正式发布。初始化迁移在真实路径及资源可用后复查，重复初始化不重建已迁移旧入口。

失败至少覆盖打包或保存失败、来源不匹配、客户端缺少资源、本机切换及恢复失败、账号保存结果未知。未决写入保持阻断，不因列表暂缺而重试；其他端的成功不掩盖该端失败。单项预计超过十五分钟或 516 MB（兆字节）先暂停申请批准，不拆分规避。仅在用户本机处理仓库任务时，仓库外创建或删除须先取得具体授权；云端遵循自身写入范围。
