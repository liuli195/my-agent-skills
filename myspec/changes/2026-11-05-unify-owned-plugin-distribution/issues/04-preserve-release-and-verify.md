## 交付行为

## 验收

- [ ] 现有发布预检、输入变化及版本检查、市场投影生成仍可用，九项来源和产物一致。
- [ ] 两项软件包构建、既有发布流程及持续集成自举保留；正式完整产物只接入本仓库原发布流水线，不改通用模板；发布成功后取得精确市场投影标签生成完整目录，再封为 `dot-release-packages.tar`（完整正式包归档），仅上传该文件，产物名仍为 `dot-release-packages`（完整正式包）。原流水线全成功后，个人账号仅在已登录环境交付，持续集成不持有个人凭据。验证不以真实正式发布作为手段，不合并两个命令工具。
- [x] 复用既有构建验证入口完成风险匹配检查，不另建平行验证系统；名称无条件分支和三份清单一致性有证据。
- [ ] 分别记录云端正式对象和本机市场来源、版本、技能及资源；本机覆盖正式→开发→正式恢复及同名账号来源隔离。只读核对现有覆盖及其他插件影响后才可申请精确配置修改；本轮不自动写本机配置。
- [ ] 发布主路径读回既有持续集成成功结果、真实发布记录、标签及投影提交；交付脚本核对非草稿／非预发布及远端标签与精确快照，不冒称独立关联某次持续集成，不新增强制任务编号契约或最新版本／市场尖端限制。
- [ ] 汇总失败、恢复和未验证项，不将保存成功、历史双对象实验或内部假体结果当作当前真实加载证明；正式发布成功但正式包构建／保留失败，报告包阶段失败及整体流水线未通过；账号阶段失败另报账号未完成，保留映射证据。两者都不因后续失败重发正式发布；账号已发送或结果未知只安全对账，不重发保存或清除未决记录。
- [x] 单一归档经同一交付入口，在明确授权目录的新私有临时子目录中受限解包；拒绝绝对路径、穿越、全部链接、异常类型、重复路径及超预算，保留模式，再校验插件压缩包摘要、完整目录、逐文件及执行位。不新增依赖、第二路径、单独压缩包恢复或手工改权限。历史固定标签重建也使用同一归档入口，不强制新任务编号。
- [x] 成功或无账号写入失败后清理本次临时目录；未知／未验证时保留目录及映射，报告 `retainedDirectory`（保留目录），不把默认检查写成文件全程只读。

- [x] 清理废弃联动流程、冗余账号入口及仅服务废弃路径的测试；插件同步不残留账号教程或发布脚本引用，账号操作只在发布流程自身保留。
- [x] 修正本次需求文件、票据与随包说明，明确旧会话刷新、分端边界及历史开发对象保留；正式主规格仅在交付门禁后预览和应用，本轮不改 myspec/specs（正式规格目录）。
- [x] 测试数据按授权清理，保留用户原有数据；剩余物或无法恢复情况明确报告。
- [ ] 准备后续规格与交付门禁材料；不自行合并主干、推正式标签或正式发布。
