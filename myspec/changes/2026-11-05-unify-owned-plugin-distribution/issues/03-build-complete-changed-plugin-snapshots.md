# 03：按变化插件重打完整开发包

**状态：** ready-for-agent
**前置票据：** 02：九项统一市场与安装更新。
**门禁：** 门禁一待确认，且前置票据完成。

## 交付行为

维护者从同一清单生成开发快照，仅重打变化插件及其依赖影响范围中的完整包，上传对应开发对象，使客户端能够独立加载。发布对象与未变化插件的可追溯产物保持原有状态。

## 验收

- [ ] 变化由插件发布输入和依赖关系判断，共享代码或必要资源变化触发受影响插件重打，未受影响插件不重打。
- [ ] 每个产物含全部必要技能正文、脚本、共享代码、资源及依赖，可从完整包运行，不依赖旧缓存补文件。
- [ ] 复用现有打包能力；记录每项输入版本、产物标识、耗时与大小，复用未变化产物时可追溯来源。
- [ ] 只上传对应开发对象；不覆盖发布对象、不创建正式标签、不冒充文件级差量上传。
- [ ] 从统一入口更新快照后验证 dot（云端助手）、本机 Codex（代码代理）新会话及 Claude（代码助手）资源可用。
- [ ] 包构建或上传失败时保留上一可用内容，报告实际对象状态及恢复结果；不得发布半包。
- [ ] 超过十五分钟或 516 MB（兆字节）的预计单项先停止；测试产物按精确授权清理。

## 公开测试接缝

开发快照打包上传入口→完整产物检查→客户端实际更新与资源执行。覆盖单插件变化、共享依赖变化、无变化复用和上传失败；结合既有发布输入预检及真实安装形态冒烟。

## 范围

仅九项自有插件的开发快照；保留正式发布语义，不新增第三方通用迁移框架。
