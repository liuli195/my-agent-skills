## Problem Statement

Orca（代理运行平台）拒绝安装现有 ntfy（通知服务）个人插件。插件清单使用了以 `orca-` 开头的标识，而 Orca 1.4.183 将所有这类标识保留给官方插件，因此安装只显示“插件安装失败”。

## Solution

把插件清单标识改为不属于 Orca 保留范围的 `ntfy-notifications`，并把插件版本升级为 `1.0.2`。插件目录名、通知行为、权限、公共 ntfy 匿名主题方案和正式功能规格保持不变。

## User Stories

1. 作为 Orca 用户，我希望个人通知插件使用允许安装的标识，以便 Orca 能复制插件并显示权限预览。
2. 作为插件维护者，我希望测试固定非保留标识和新版本，以免以后再次发布无法安装的清单。

## Implementation Decisions

- 只修改插件清单中的插件标识和版本，以及直接验证这两个字段的现有测试。
- 插件发布者保持 `liuli195`，安装后的完整标识为 `liuli195.ntfy-notifications`。
- 保留现有源码目录名，避免与运行时插件身份无关的文件移动。
- 不修改通知正文、状态去重、重试、私密主题读取或权限声明。

## Testing Decisions

- 复用现有插件清单测试作为公开测试接缝，先让它要求新标识和 `1.0.2` 并确认失败，再修改清单使同一检查通过。
- 使用仓库统一 Build and Verify（构建与验证）入口执行固定基线后的快速验证。
- 最高层级真实用户入口为 Orca 设置中的插件安装入口；成功结果是安装完成并出现权限预览。权限批准和启用必须由用户亲自完成。

## Out of Scope

- 不修改 Orca 核心、`app.asar`（应用资源包）或 Orca 版本。
- 不修改 ntfy 通知行为、主题配置、权限或正式功能规格。
- 不在本票据中自动批准插件权限、启用插件或发送真实通知。

## Further Notes

本次失败已在 Orca 1.4.183 的真实安装入口复现；将相同文件暂存到 C 盘后仍失败，排除了源码所在磁盘和复制路径问题。官方安装规则确认非官方插件的标识不得以 `orca-` 开头。
