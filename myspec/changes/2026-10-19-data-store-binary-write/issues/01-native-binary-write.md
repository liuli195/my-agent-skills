# 01: 通过公开入口保存原生二进制字段

**What to build:** 调用者在独立安装形态通过现有 Python（编程语言）公开 write（写入）入口显式开启 binary（原生二进制方式），将通用元数据与顶层 BLOB（二进制字段）保存在同一个原子发布记录组，并由既有读取入口准确读回；原有调用保持现有行为，命令行只直接输出普通元数据。

**Blocked by:** None（无前置票；仅在完整门禁一确认后开始）。

**Status:** ready-for-agent

## Acceptance criteria（验收条件）

- [ ] 单一公开 write 入口增加默认关闭的 binary 关键字；开启时要求显式字段类型，仅顶层声明 BLOB 接收 bytes（字节串）或 None（空值）；默认路径及已有 BLOB 字符串输入不变。
- [ ] 空字节串、非文本字节、空值、多个二进制字段、纯二进制记录、混合普通字段和多行均从独立安装形态公开入口正确往返；多行普通字段与二进制内容始终一一对应。
- [ ] 普通字段保留现有 JSON（数据交换格式）/from_json_strict（严格转换函数）的合法转换及失败行为；缺字段、额外字段、非法值、嵌套字节、字段名冲突等明确失败，合法特殊字段名按名称处理。
- [ ] 沿用单一 Parquet（列式文件）、Zstd（压缩算法）、临时文件与原子替换/有限重试；转换、临时写入或发布失败不覆盖旧完整记录；逻辑表/键限制和读取安全不降低。
- [ ] Python 现有点读、多键读取、字段选择、筛选和显式表查询返回原生 bytes 且看到当次完整数据；未知字段继续报错，不另造读取适配层或隐藏全量回退。
- [ ] 接口能力版本仍确切为二，实际导入模块声明 binary-write-v1（二进制写入第一版）能力；不把未发布正式版本写成已完成。消费者能力检测和业务接入由后续调用项目票据完成，不写进通用层。
- [ ] 命令行普通写入和元数据查询继续成功；所有读取命令直接输出 BLOB 时明确拒绝并提示选择元数据或显式编码，不以字符串伪装为可无损二进制；不新增二进制输入格式。
- [ ] 通用接口与说明不出现业务专用表、字段、模型、数值库或矩阵协议，不加依赖/服务/旁路文件；调优记忆不保留字节串业务内容。
- [ ] 先从独立安装形态的公开 Python write 运行最小红灯，再实施最小修改并重跑相同检查转绿；最终冒烟使用相同入口及同一数据的命令行元数据成功/直接二进制拒绝路径。
- [ ] 复用仓库既有验证入口与公开测试先例；固定基线后的 build-and-verify（构建与验证）为 passed（通过）且 checked（已检查）非空。需 Windows（视窗系统）验证时交由本机已授权任务执行，不以云端结果冒充两端完成。
- [ ] 完成后固定本票起止提交，由独立 Reviewer（审查者）分别检查行为合同与最小架构/收益；阻塞问题解决并重跑受影响检查后才验收。

## Public test seam（公开测试接缝）

从独立复制/安装后的实际技能脚本加载模块，调用 write 开启 binary，再用既有点读/批量读取/显式表查询分批读回。同一数据从真实命令行查询普通元数据成功，直接输出 BLOB 明确失败。此为一张可独立演示的端到端纵向票，不拆成转换层、文档层或包装层票据。

## Failure and recovery（失败与恢复）

非法输入及转换失败不发布新文件；临时写入或替换失败保留原有完整数据并传播错误。缺失、明确损坏和暂时不可用保持既有区分；不自动修复业务状态、不新建模型或降级编码。需求或上述公开接缝改变时返回需求路由；门禁未确认前不得实施。

## Scope boundary（范围边界）

本票只交付通用技能能力和自身公开/安装形态验证。调用项目的实际能力加载、矩阵编码与格式校验、位级及下一次行为一致性、控制记录、迁移恢复和真实搜索测量留在其现有变更；正式合并/发布/市场同步/安装和真实迁移不由本票状态隐含授权。
