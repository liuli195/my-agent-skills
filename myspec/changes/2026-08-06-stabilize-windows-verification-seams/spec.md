# 稳定 Windows 验证接缝

## Problem Statement（问题陈述）

本仓库的 Windows（视窗系统）完整验证会因调用环境差异产生假失败。MySpec（自有规格）测试替身在已经取得真实 Git（版本管理）命令路径后，仍按特定 Git Bash（Git 命令行环境）目录布局重新推导可执行文件；当 Pi（编码代理）或 PR Flow（拉取请求流程）直接解析到 Windows `cmd` 目录中的 Git 时，测试替身会调用不存在的路径。工作树初始化测试则直接匹配 PowerShell（命令行程序）宿主渲染后的连续错误文字，不同 PowerShell 版本插入的 ANSI（终端控制码）和换行会破坏该匹配。

这些问题不代表 MySpec 开发模式或工作树初始化生产行为失败，却会阻断正式 hotfix（热修复）验证。与此同时，MySpec 验证检查没有完整声明测试实际读取的共享生命周期和仓库输入，Windows PR（拉取请求）任务也没有按固定基线运行受影响的验证检查。

## Solution（解决方案）

让测试替身保留命令解析器返回的精确 Git 路径，只根据真实文件后缀选择 Windows 调用方式，不再解释安装目录。让工作树初始化测试在真实 PowerShell `-File` 入口捕获结果后，仅规范化宿主附加的 ANSI 和空白，再验证退出码、安全后置条件和用户提示；生产脚本保持不变。

同步 MySpec 检查的触发路径与缓存输入，使其覆盖测试实际读取的共享生命周期、仓库属性、忽略规则和正式规格。Windows PR 任务继续执行真实工作树构建，并通过当前 Build and Verify（构建与验证）入口，以固定 PR 基线运行受影响的快速验证；手动触发工作流时允许运行完整验证。Linux（操作系统）完整验证和最终 `Full Verify`（完整验证）汇总门禁保持不变。

## User Stories（用户故事）

1. 作为 Windows 开发者，我希望测试使用系统实际解析到的 Git 命令，以便从 Git Bash、Pi 或 PR Flow 启动验证时得到相同行为。
2. 作为 MySpec 维护者，我希望受控 Git 替身只修改测试需要控制的远端查询，以便其他 Git 操作仍由真实命令完成。
3. 作为工作树脚本维护者，我希望测试忽略 PowerShell 宿主的颜色和换行差异，以便人类可读提示没有变化时不产生假失败。
4. 作为仓库维护者，我希望安全后置条件优先于提示文本被验证，以便显示差异不会遮蔽目录覆盖或意外安装风险。
5. 作为本地开发者，我希望 Windows 测试不依赖 Git Bash 附带的无关命令，以便原生 Windows 环境不会静默跳过验证。
6. 作为 Build and Verify 使用者，我希望 MySpec 检查声明全部实际输入，以便相关源码或仓库规则变化能够选择并正确失效该检查缓存。
7. 作为 PR 审查者，我希望 Windows 任务通过固定基线运行受影响的验证检查，以便相关缺陷在合并前暴露，同时避免每个 PR 重复全部 Windows 检查。
8. 作为 PR Flow 使用者，我希望最终 `Full Verify` 汇总名称和远端规则保持不变，以便本次修复不要求修改 Ruleset（规则集）。
9. 作为维护者，我希望手动工作流仍能执行 Windows 完整验证，以便需要时可以诊断运行环境漂移。
10. 作为当前 hotfix 的执行者，我希望验证基础设施修复与现有策略提交保持独立，以便两个交付可以分别审查和回退。

## Implementation Decisions（实施决策）

- 保留命令解析器给出的真实 Git 绝对路径；不得根据父目录层级或安装目录名称重建路径。
- Windows 命令转发只根据解析结果的真实后缀决定是否使用批处理调用方式。
- 不修改 MySpec、Tool Lifecycle（工具生命周期）或工作树初始化的生产实现。
- PowerShell 输出规范化只存在于测试实现中，仅移除 ANSI 并折叠宿主插入的空白；退出码、文字内容和文件系统结果仍需独立满足断言。
- 安全后置条件在提示文字之前验证。
- 测试自行创建只需存在的 Python 占位文件，不依赖外部 `true` 命令。
- MySpec 检查的触发路径与缓存输入覆盖其测试直接读取的共享生命周期、仓库属性、忽略规则和正式规格。
- Windows PR 验证使用当前 PR 的固定基线提交，不使用可移动分支名，也不在干净工作树中运行无基线快速验证。
- Windows 工作树构建冒烟、Linux 完整验证和最终跨平台汇总门禁保持存在。
- 不修改远端 Ruleset，不修改生成的工具链工作流，不新增验证入口。

## Testing Decisions（测试决策）

- 最高 MySpec 测试接缝是打包并隔离安装后的裸 `myspec` 命令，以受控源码执行开发模式行为；测试不得绕过候选包调用内部模块。
- 最高工作树测试接缝是真实 `powershell -File` 与 `pwsh -File` 子进程，验证非零退出、目录和标记文件安全结果以及规范化后仍存在的行动提示。
- 检查配置使用现有仓库契约测试锁定实际读取范围，不通过新建平行验证脚本维护第二份清单。
- Windows PR 入口必须通过 Build and Verify 运行固定基线快速验证，并以非空 `checked` 和 `status: passed` 作为有效通过证据。
- 实施按 TDD（测试驱动开发）先建立路径转发、输出规范化、配置输入和工作流契约红灯，再做最小实现。
- 集成后使用变更工作树固定基线快速验证；PR CI（拉取请求持续集成）负责完整自动检查和真实 Windows 工作流结果。

## Out of Scope（范围外）

- 修改工作树初始化脚本的用户输出或新增机器错误协议。
- 放宽 MySpec 开发源码、官方远端、干净工作树或可复现提交校验。
- 修改 Build and Verify 的快速或完整验证运行时语义。
- 修改远端 Ruleset、必需检查名称或 PR Flow 的检查等待逻辑。
- 修改生成的工具链同步工作流。
- 优化完整验证耗时或调整性能预算。
- 修改、推送或合并当前本地策略提交。
- 创建或更新 GitHub Issue（问题）。

## Further Notes（补充说明）

本变更不引入新的领域术语，也不需要 ADR（架构决策记录）。它修复现有验证接缝与已有规格之间的实现偏差。变更虽保持小范围，但涉及缺陷和必需 CI，因此按 Standard（标准）开发流程交付。
