# 修复运行边界快速覆盖并沉淀动态扫描配置规则

## Problem Statement（问题说明）

运行边界契约检查会扫描 Git（版本管理）可见的整个测试目录，但现有快速验证只为少数明确列出的测试文件选择该检查，缓存输入也没有完整声明扫描范围。因此，新增、删除或重命名其他测试中的真实命令路径时，白名单差异可能直到完整验证才发现。现有诊断还会先因过期白名单失败，遮挡同时存在的缺失白名单项。

构建与验证初始化、审查流程已要求检查路径和缓存输入覆盖相关测试，但没有专门指导动态扫描命令如何声明实际读取范围，也无法在静态证据不足时受控探测。

## Solution（解决方案）

1. 把运行边界契约从现有复合构建与验证检查中拆出为独立、轻量的快速验证检查。
2. 该检查对 Git 可见的 `tests/` 目录建立完整的选择和缓存依赖；它仅运行运行边界扫描测试，采用检查级并行，不启用 Pytest 并行插件。
3. 运行边界检查在一次失败中按类别完整报告过期白名单项和缺失白名单项。
4. 在构建与验证初始化、审查参考规则中沉淀通用约束：动态扫描命令的实际读取范围必须同时覆盖快速选择和缓存输入；若扩大范围会使复合检查变慢，应建议拆分专用检查。
5. 静态证据不足且探测能消除配置不确定性时，初始化和审查可在用户确认后对必要候选命令执行分组探测。探测前展示命令、总成本和可能副作用；执行前后核对 Git 可见差异。发现差异时立即停止建议和写入，保留现场且不自动清理或恢复。

## User Stories（用户故事）

1. 作为仓库维护者，我希望任一 Git 可见测试变更都会触发运行边界契约检查，从而在提交前发现白名单差异。
2. 作为仓库维护者，我希望新增、删除、重命名测试和修改共享夹具都会使该检查的缓存失效。
3. 作为仓库维护者，我希望普通测试改动只运行轻量契约检查，而不额外运行无关的复合检查。
4. 作为仓库维护者，我希望一次失败能同时看见全部过期项和缺失项，以便一次完成修复。
5. 作为配置初始化使用者，我希望动态扫描的配置范围能反映命令实际读取的文件。
6. 作为配置审查使用者，我希望范围不足和范围扩大造成的复合检查成本都能得到有证据的建议。
7. 作为配置使用者，我希望静态证据不足时可在知情并确认后进行有限探测，而不是靠猜测配置缓存范围。
8. 作为仓库维护者，我希望探测产生可见改动时流程停止并保留现场，避免意外写入混入配置变更。

## Implementation Decisions（实施决策）

- 运行边界契约检查的 Module（模块）是独立的快速验证检查；其 Interface（接口）是对测试目录变更的选择规则、完整测试目录缓存输入，以及仅运行契约扫描测试的命令。
- 原复合检查保留其既有其他测试和依赖范围，但不再承载运行边界契约扫描。
- `tests/` 目录是运行边界检查的 Git 可见输入范围；被忽略的临时文件不属于快速验证和持续集成的输入契约。
- 白名单诊断保持既有白名单规则，仅把两类差异先完整计算再汇总为一个失败结果。
- 初始化和审查只沉淀通用动态扫描规则，不加入本仓库或运行边界检查的特例。
- 候选命令探测不是默认步骤：仅在静态证据不足、成本可接受且探测可以直接消除配置不确定性时建议执行；用户可一次确认完整命令组。

## Testing Decisions（测试决策）

- 通过 Build and Verify（构建与验证）运行时的快速选择与缓存接缝，验证测试目录变更只选中独立运行边界检查，并且目录内容变化不会复用旧缓存结果。
- 保留扫描器覆盖全部 Git 可见测试源码和共享夹具的现有测试入口；新增能够同时构造过期项和缺失项的断言，验证诊断完整性。
- 通过既有构建与验证插件契约测试，验证初始化、审查参考规则包含动态扫描范围、专用检查拆分、受控分组探测及发现可见改动后的停止语义。
- 以快速验证入口作为最终用户可观察冒烟：对测试目录变更运行快速验证，确认不触发原复合检查。

## Out of Scope（范围外内容）

- 不修改 Build and Verify（构建与验证）运行时的选择、缓存或 Git 可见文件语义。
- 不修改忽略规则，不把被忽略的临时测试纳入验证输入。
- 不扩大完整验证的检查范围。
- 不自动运行候选命令、自动清理探测副作用或自动恢复仓库。
- 不安装依赖、不修改持续集成或用户级配置。

## Further Notes（补充说明）

本变更为标准级：它改变快速验证的选择和缓存配置，并更新技能的受控探测流程；不涉及发布、迁移、数据或机器级状态修改。
