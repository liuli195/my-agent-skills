# 01 — 拆分运行边界快速检查

- 状态：ready-for-agent
- 关联问题：#255
- 前置票据：无

## 用户结果

任一 Git（版本管理）可见测试或共享夹具变更都会在快速验证中运行独立、轻量的运行边界契约检查；不会额外运行原复合构建与验证检查。一次白名单失败同时展示全部过期项和缺失项。

## 实现范围

- 新增独立运行边界契约检查，并使其选择路径和缓存输入覆盖完整测试目录及测试依赖清单。
- 从原复合检查移除运行边界扫描测试，保留其余检查范围。
- 汇总两类白名单差异后再失败。
- 覆盖测试目录内容变化、缓存失效、快速选择和完整诊断的回归场景。

## 验收标准

- [x] 任一 Git 可见测试文件新增、删除、重命名或修改时，快速验证选中独立运行边界检查。
- [x] 修改共享夹具时，运行边界检查缓存失效。
- [x] 测试目录变更不再额外选中原复合构建与验证检查。
- [x] 单次失败同时报告全部过期白名单项和缺失白名单项。
- [x] 独立检查不启用 Pytest 并行插件，但允许与其他检查并行。
- [x] 通过快速验证入口完成测试目录变更场景的可观察冒烟。

## TDD（测试驱动开发）证据

- [x] 红灯：新增诊断与配置契约先因缺少汇总函数和独立检查失败。
- [x] 绿灯：280 项相关检查通过；快速验证入口仅选中 `verify.my-spec` 和 `verify.runtime-boundaries`，目录变更后不会复用旧缓存。
