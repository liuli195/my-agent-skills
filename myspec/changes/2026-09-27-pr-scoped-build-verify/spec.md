# PR 场景构建与验证

**状态：** ready-for-agent
**来源：** GitHub Issue #361

## Problem Statement

下游仓库需要本地运行全部检查，但拉取请求只运行适合远端的检查。当前构建命令总运行全部检查；验证命令在配置变化时也选中全部检查，无法稳定控制拉取请求耗时。

## Solution

在同一配置中为构建和验证检查项支持可选布尔值 `pr`，省略等同 `true`。`build --pr` 和 `verify --pr` 仅从可用于拉取请求的检查项中选择；不带该选项时行为保持不变。输出显示运行场景、已选及排除项；空选择明确为跳过。

## User Stories

1. 作为本地开发者，我可以继续构建并验证全部应运行的检查，包括 `verify --full`。
2. 作为拉取请求维护者，我可以用 `build --pr` 排除不适合远端构建的检查。
3. 作为拉取请求维护者，我可以用 `verify --pr --base <固定基线>` 按变更路径选择检查，配置变化也只选拉取请求可执行项。
4. 作为拉取请求维护者，我可以用 `verify --pr --full` 运行全部拉取请求可执行验证检查。
5. 作为配置维护者，我可以看见场景、已选与排除项，并在 `pr` 非布尔值时于调度前得到错误。
6. 作为检查结果使用者，我可以区分没有检查执行的跳过结果与有检查通过的结果。

## Implementation Decisions

- 继续使用现有命令入口、配置读取与检查调度；场景过滤发生在路径选择和配置变化全选之前，也适用于完整验证。
- `pr: false` 仅影响显式 `--pr` 场景；缓存和调度沿用已筛选的检查项。有效缓存命中仍算已检查。
- PR 场景筛选后没有选中检查项时，构建、快速验证和完整验证均报告 `skipped`；本地未传 `--pr` 的空配置行为保持现状。空的 PR 完整验证不生成性能报告，也不覆盖旧报告。
- 初始化草案保留已有 `pr` 值，并提示用户为仅本地运行的检查设置 `pr: false`；审查入口检查该字段类型与场景归属。
- 正式规格中的“配置变化全选”限定为当前运行场景下全部可执行检查。

## Testing Decisions

- 从已发布命令入口构造临时仓库，核对构建、固定基线快速验证、配置变化、完整验证、空选择、无效配置和本地默认行为；使用实际输出与执行痕迹判断结果。
- 复用现有命令入口测试及运行器测试，不新增构建或验证入口。

## Out of Scope

不修改下游 WoW Addons（魔兽世界插件）仓库，不提交构建产物或使用 Git LFS（大文件存储）。

## Further Notes

来源问题要求拉取请求在引擎代码变化后可于 60 秒内完成；本仓库负责提供可选择检查的机制，下游耗时目标由其配置和持续集成环境验证。
