## 1. 审查入口纵向切片

**Blocked by（阻塞项）：** None（无）— can start immediately（可立即开始）。

- [x] 1.1 新增 `build-and-verify-review`（构建与验证审查）入口，使用户能够授权扫描仓库并看到现有构建、验证配置与共享扫描候选之间的对比。
- [x] 1.2 审查结果必须覆盖命令来源、分组、重复关系、`paths`（受影响路径）、`inputs`（缓存输入）、副作用风险和废弃字段，并按缺失、错误、重复、缓存和风险分组展示。
- [x] 1.3 高、中、低置信度候选必须分别执行默认进入草案、等待确认和仅风险提示的策略。
- [x] 1.4 插件包和模板完整性测试必须证明新入口直接复用初始化扫描规则，且没有新增扫描程序或复制规则。

## 2. 确认式优化纵向切片

**Blocked by（阻塞项）：** 1. 审查入口纵向切片。

- [x] 2.1 用户能够逐项接受或拒绝增加、删除、重新分组、路径修正、缓存输入修正和废弃字段迁移建议。
- [x] 2.2 系统必须展示合并后的最终配置差异，并在获得整体确认前保持目标配置不变。
- [x] 2.3 最终写入必须复用现有定向依赖检查、环境检查、备份和 `init --config --overwrite`（初始化覆盖命令），不得直接覆盖配置。
- [x] 2.4 完整流程模拟必须证明用户沉默、部分选择或拒绝整体确认时不会修改目标配置。

## 3. 写入后完整验证纵向切片

**Blocked by（阻塞项）：** 2. 确认式优化纵向切片。

- [x] 3.1 配置成功写入并通过结构校验后，系统必须运行一次 `verify --full`（完整验证）。
- [x] 3.2 配置或命令问题必须产生新的修正建议；真实仓库验证失败必须保留配置并报告，不得自动回滚。
- [x] 3.3 端到端测试必须覆盖扫描、审查、确认、备份写入和完整验证这一用户主流程。
- [x] 3.4 运行聚焦插件验证、对应 MySpec（自有规格）严格校验，以及仓库 `build-and-verify`（构建与验证）完整端到端回归。
