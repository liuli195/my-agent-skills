# 02 — 每次验证复用一个 MySpec 候选包

**What to build（构建内容）：** 当贡献者运行一次非缓存 `verify.my-spec`（MySpec 验证）时，本地验证只生成一次当前检出的候选 Tarball（压缩包），并行工作进程共享该只读包，同时每个测试继续使用独立安装和运行状态；CI（持续集成）已提供候选包时不重复生成。

**Blocked by（前置票据）：** 01 — 保护隔离 MySpec 发布形态验证。

**Status（状态）：** ready-for-agent

- [ ] 本地测试控制进程在并行工作进程启动前通过官方打包 Interface（接口）准备候选包。
- [ ] 一次非缓存 `verify.my-spec` 只生成一次当前候选包，所有并行工作进程消费同一只读包。
- [ ] 每个测试的安装前缀、用户目录、MySpec 运行状态和日志保持隔离。
- [ ] 模拟其他版本、升级或故障场景的包继续独立生成，不被错误复用。
- [ ] CI 明确提供当前候选包时验证并复用该文件，不再次打包。
- [ ] Build and Verify（构建与验证）能够感知候选包准备逻辑的变化并运行 `verify.my-spec`。
- [ ] 同一机器上变更前后各三次非缓存运行的 `verify.my-spec` 耗时中位数至少下降 30%，并记录打包次数、`checked`（已检查）和最终状态。
- [ ] 票据 01 的完整隔离发布形态验证继续通过。
