# 验证并发参数同机对照试验

## 目标与范围

保持全部17组验证、8组真实角色与60秒硬预算，比较原配置与统一候选的同机耗时。外层并发保持8，真实组排在普通组之前，全部允许外层并行；16个包含 pytest（测试框架）的检查统一设置内部2个工作进程。

`verify.myspec`（规格校验）不支持测试工作进程参数，只有外层并行；`verify.local-build-contract`（构建契约）中的 Node（节点运行时）测试段保持原命令，不新增包装或测试框架。真实组中只有单个测试的组不会被自动拆分，可能只有额外启动成本，结果必须实测。

## 候选与实施边界

本目录 `config.candidate.json`（候选配置）为官方初始化命令的输入，尚未覆盖正式配置。两份现有测试契约同步候选的顺序与内部并发期望，应与候选一起应用。禁止把当前候选分支当成已完成验证的配置。

本机先独占执行原配置A，完成后使用既有官方初始化覆盖命令写入候选并保留备份，再执行B；保持相同工具来源、环境与60秒硬预算，完整运行17组。不得切换本机开发模式工具源、更新或自举升级工具、修改运行器或持续集成。无新增依赖；若本机关闭测试插件自动加载，仅在确认需要时显式加载已有并行插件。

- 云端：完成配置与独立资源只读盘点，准备候选及既有契约调整；未运行测试。

- B（候选配置）：待本机记录。
- 最终结论：待同机比较总耗时、全部检查状态与测试覆盖后决定保留或回退，不预先宣称提速。
