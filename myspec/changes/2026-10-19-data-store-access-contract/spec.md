# 数据存储接入的性能与复用约定

Status: draft
Triage: ready-for-human

## Problem Statement

调用方虽然已经使用统一数据存储接口，仍可能反复加载可复用资料、在数值列表与内存对象间转换大对象，或保存多份等价诊断。现有项目接入检查只检查技能入口，不能证明业务数据访问高效。用户要求把通用要求沉淀在插件和技能中，而不是依赖会话记忆。

## Solution

补充现有数据存储技能的接入契约与接入完成证据要求，复用既有按键、按列、批量读取和原子发布接口。数据中心自身测试留在技能仓库；业务身份、版本、缓存、恢复和实际规模的测试留在调用项目；业务数据目录不存放测试实现。

本变更不新增检查平台或运行接口，不把业务判断放入通用存储层。原有项目入口检查继续只检查连接关系，不能以其通过宣称业务性能通过。

## User Stories

1. 作为接入项目的开发者，我需要说明资料身份、可变性、有效范围和版本依据，避免按同一个文件名盲目复用。
2. 作为接入项目的开发者，我需要优先使用已有按键、按列和批量接口，避免先全量读取再提取小字段。
3. 作为接入项目的开发者，我需要在有效身份或版本未变化时复用已经取得的对象，同时在版本变化和失败后保持正确性。
4. 作为接入项目的开发者，我需要减少大对象的不必要转换、复制和重复扫描，保持数值及结构的既有查询语义。
5. 作为需要恢复任务的开发者，我需要先保存权威资料再引用，避免维护多份完整业务结果或静默补算丢失资料。
6. 作为审查者，我需要看到实际业务入口的调用次数、所取字段、结果一致性和代表规模证据，不能仅凭使用统一接口就判定接入完成。
7. 作为技能维护者，我需要区分技能仓库测试、业务项目测试和业务数据，避免把业务用例带入通用插件。
8. 作为使用者，我需要允许版本变化、缓存失效、恢复和失败确认等必要重复访问，避免不准确的一刀切限制。

## Implementation Decisions

- 仅补充现有技能说明中的通用接入规则与验证要求，复用当前公开脚本能力和验证入口。
- 不可变资料按完整身份及解释版本复用；可变资料按可信版本核验，不把同键视为永久不变。
- 访问次数和缓存生效范围由具体业务场景声明，错误、缺失和损坏继续沿用当前区分，不能为减少访问而吞错。
- 当前内存查询连接只服务单次读取，查询调优选择缓存不代表报告或模型常驻缓存；文档必须明确该事实。
- 数据存储层负责类型、点读、字段选择、原子发布；项目负责业务身份、何时复用、更新与恢复语义。
- 测试中的轻量转发计数继续执行真实接口，仅记录操作、目标和字段，不保留完整大对象参数，不冒称物理磁盘访问次数。
- 首版不新增通用调用记录器、扫描器、规则配置文件、独立命令行或新的开发门禁。
- 不修改存储接口、数值数组表示、缓存行为、发布版本或安装位置；GSE（序列模拟项目）的具体性能修复另在其现有变更中进行。
- 用户后续明确要求将技能仓库的Pytest（测试框架）升级并固定为9.1.1；只修改现有开发依赖声明，核对现有并行测试插件及依赖兼容性，并通过原有公开验证入口检查受影响范围。不安装新包、不更换验证入口或扩展为测试框架重构。

## Testing Decisions

- 最高用户入口为安装形态的数据存储技能及其现有公开脚本。读取更新后的技能能得到明确接入要求和完成证据边界。
- 复用现有安装副本、按键按列读取、同键更新、错误区分和原子写入测试；已经覆盖的行为不复制新用例。
- 通过既有构建与验证技能选择受影响的检查，不自建验证入口，不把文字检查冒称真实业务性能测试。
- 业务项目必须以现有真实入口验证调用次数、版本更新、失败恢复、资料引用及实际规模成本；具体用例不进入本技能仓库。
- 不设置未经测量的通用秒数阈值，不要求全量搜索或大量随机样本来证明一次接入正确。

## Out of Scope

GSE 产品实现、模型学习算法、常驻缓存服务、大数组编码变更、新增通用检查脚本、业务数据迁移、正式规格应用、主干合并、插件发布和本机安装。
