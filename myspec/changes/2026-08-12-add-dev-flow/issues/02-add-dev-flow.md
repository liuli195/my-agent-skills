# 02 — 提供单工作树、单功能分支开发流程

**What to build:** 提供依赖新 Subagent Policy（子代理策略）的纯 Skill（技能）Development Flow（开发流程），在调用时的同一工作树和非 `main` 功能分支中串行完成需求、实施、验证和审查，并在最终确认后通过完整 PR Flow（拉取请求流程）交付。

**Blocked by:** 01 — 提供独立的宿主无关子代理策略。

**Status:** ready-for-agent

- [ ] Pi（编码代理）从真实 Skill（技能）入口发现并调用新流程；Package（包）不包含脚本或 Extension（扩展）。
- [ ] 当前为 `main`、分离状态、工作目录无法证明、固定角色或模型不符时，流程在任何写入前明确停止。
- [ ] 开发和验证期间保持调用时的工作树和功能分支不变，Implementer（实施者）是唯一写入者且所有写入严格串行。
- [ ] 新流程只请求“开始开发”和“规格与交付”两次正式确认，确认在失败恢复期间持续有效，Completion Check（完成检查）不成为第三次授权门禁。
- [ ] Gate 1 记录本次目标产品、最高真实用户入口、可观察成功结果和必要失败或恢复路径；功能、缺陷和集成行为通过该入口执行 TDD（测试驱动开发）及最终冒烟。
- [ ] 使用固定基线进行限定审查，并只接受 `checked` 非空的 Build and Verify（构建与验证）结果。
- [ ] 最终交付允许完整 PR Flow（拉取请求流程）切换分支和安全清理。
- [ ] 委派只依赖 `subagent-policy` 的宿主校验结果；缺少已验证 Adapter（适配器）时明确停止，不在通用流程中枚举客户端或复制宿主模型细节。
- [ ] 新源码交付后的一次性本机切换通过备份、目录联接、三个新进程分发冒烟和失败恢复验证；新流程不负责安装自己。
