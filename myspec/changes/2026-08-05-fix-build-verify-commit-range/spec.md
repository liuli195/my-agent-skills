# Build and Verify 提交范围快速验证与空检查状态

## Problem Statement

Build and Verify（构建与验证）的默认快速验证只从当前验证工作树（Verification Worktree）读取未提交变更。实现票据提交后工作树通常是干净的，系统因此可能没有选中任何检查，却仍输出通过状态，形成无法证明实际验证发生的假绿证据。多个 Git（版本管理）工作树还要求验证范围明确属于当前工作树，不能受其他工作树状态或可变分支引用影响。

## Solution

为快速验证提供显式验证基线（Verification Baseline）。调用者可传入提交或引用，系统在目标验证工作树中固定该基线，并只选择该基线到当前提交之间受影响的检查。验证工作树未提交改动、无效基线和与完整验证的冲突组合明确失败。

快速验证区分“未选中检查”和“已验证通过”：没有变更或没有匹配检查时报告跳过原因；至少选中一个检查时，即使所有检查均由有效通过缓存命中，也报告通过。默认未提交文件模式保持不变。

## User Stories

1. 作为在提交后运行快速验证的维护者，我希望能指定验证基线，从而验证已提交的变更而不是只看到干净工作树。
2. 作为在多个工作树中开发的维护者，我希望验证只读取指定验证工作树的提交和状态，从而其他工作树的改动不会污染结果。
3. 作为使用分离 HEAD（当前提交）的维护者，我希望提交范围验证仍能工作，从而验证不依赖分支名称。
4. 作为基线分支在其他工作树中被检出的维护者，我希望当前验证不需要切换或锁定其他工作树，从而并行工作保持安全。
5. 作为发现基线无效的维护者，我希望命令明确失败而不是退回工作区扫描，从而不会得到误导性结果。
6. 作为在验证工作树有未提交改动的维护者，我希望显式提交范围验证被拒绝，从而不会静默漏掉本地改动。
7. 作为没有适用检查的维护者，我希望看到 `skipped`（跳过）及明确原因，而不是空检查通过。
8. 作为检查已经有有效通过缓存的维护者，我希望缓存命中仍被视为有效通过，从而快速验证不会重复执行不必要的检查。
9. 作为运行完整验证的维护者，我希望显式提交基线参数被拒绝，从而完整验证的全量语义保持清晰。
10. 作为使用旧运行时迁移路径的维护者，我希望本次变更不改动既有迁移行为；旧运行时兼容不属于本变更范围。

## Implementation Decisions

- 在现有 `verify` 命令上增加一个可选验证基线参数；不新增通用任意范围对象或工作树编号。
- 提交范围使用基线与当前验证工作树 HEAD 的 Git 三点差异语义；基线在入口解析并固定，验证过程中不重复解析可变引用。
- 验证基线模式只适用于快速验证；完整验证与该参数组合时明确失败。
- 验证基线模式要求验证工作树没有未提交改动；默认模式继续支持暂存、未暂存和未跟踪文件。
- 无效基线不得回退到默认工作区变更来源；错误必须以失败状态和非零退出码返回。
- 空变更报告 `status: skipped` 和 `reason: no_changed_files`；有变更但没有匹配检查报告 `reason: no_matching_checks`。
- 至少选中一个检查时，实际执行通过或有效通过缓存命中均可产生 `status: passed`；`checked` 为空不能证明通过。
- 不新增基线、当前提交或合并基点的输出字段；既有输出契约只扩展跳过状态和原因。
- 旧运行时迁移兼容不作额外处理，既有迁移实现保持不变。

## Testing Decisions

- 最高测试接缝是实际 `build-and-verify verify` 命令，使用目标验证工作树的绝对路径；不以私有函数测试替代入口验证。
- 真实入口回归建立主工作树和链接工作树，覆盖：验证工作树提交范围、其他工作树未提交改动隔离、基线分支在其他工作树检出、验证工作树分离 HEAD、验证工作树脏状态拒绝和无效基线失败。
- 真实入口还覆盖空提交范围、无匹配检查、至少一个检查全部缓存命中，以及未传基线时既有未提交文件选择行为。
- 选择、状态分类和缓存命中分支使用现有进程内假执行器补充测试，避免重复启动外部进程。
- Pi Development Flow（开发流程）验证契约测试必须要求提交后使用固定验证基线，并以 `status: passed` 且 `checked` 非空作为有效快速验证。
- 实施完成后通过 Build and Verify（构建与验证）快速入口验证，并执行一次真实命令冒烟。

## Out of Scope

- 不支持任意两端的通用 `--range` 参数。
- 不使用 `HEAD^` 自动推断基线，不自动选择当前分支或其他工作树的基线。
- 不查询、切换、锁定或协调其他工作树。
- 不改变完整验证的全量检查语义。
- 不扩展旧运行时迁移兼容逻辑，现有迁移行为保持不变。
- 不修改安装、客户端同步、市场刷新、发布或 PR Flow（拉取请求流程）交付动作。

## Further Notes

本变更对应 GitHub Issue #284。实现票据只记录用户可观察行为和验证证据；基线提交、分支和工作树状态由 Git 状态推导，不写入长期运行态文件。
