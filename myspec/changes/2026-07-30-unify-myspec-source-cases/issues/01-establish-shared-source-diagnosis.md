# 01 — 建立三端统一来源诊断

**What to build:** 让 MySpec（自有规格）用户在 Pi、Claude 和 Codex 中获得相同结构、相同含义的来源诊断。共享案例表首先覆盖“无来源”和“稳定来源正常启用”，三端均通过打包后的 `myspec doctor`（诊断命令）完整入口运行这些案例，同时保留现有顶层诊断字段。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 存在一份独立 JSON（数据文件）共享案例表，包含稳定标识的“无来源”和“稳定来源正常启用”案例及六项期望结果。
- [ ] Pi、Claude 和 Codex 均把同一共享案例转换为各自原生状态，并通过打包后的命令行入口验证结果，不直接调用内部判断函数。
- [ ] 三端诊断结果均公开 `sources[]`（来源列表），每项包含 `installed`（已安装）、`registered`（已注册）、`enabled`（已启用）、`effective`（实际生效）、`sourceKind`（来源类型）和 `sourceMismatch`（来源不匹配）。
- [ ] “无来源”在三端都不产生 MySpec 来源记录；无关来源不会以未知类型进入列表。
- [ ] “稳定来源正常启用”在三端都报告稳定类型，且已注册、已安装、已启用并实际生效，来源不匹配为假。
- [ ] 现有顶层诊断字段继续存在，并且不与统一来源记录矛盾。
- [ ] 对应打包端到端回归可独立运行并通过。
