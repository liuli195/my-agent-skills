# 03 — 准确诊断旧版、错误来源与宿主覆盖

**What to build:** 让 MySpec（自有规格）用户在三端都能区分可生效的旧版来源与目标标识指向错误位置，并确保 Pi 相对路径、项目覆盖及各宿主重复来源等专属行为继续遵守统一的实际生效语义。

**Blocked by:** 01 — 建立三端统一来源诊断；02 — 准确诊断禁用与安装目录缺失

**Status:** ready-for-agent

- [ ] 共享案例表增加“旧版来源正常启用”和“目标标识指向错误来源”案例，并由 Pi、Claude 和 Codex 全部运行。
- [ ] 正常启用的旧版来源在三端均报告 `sourceKind=legacy`（旧版来源），且可按真实状态报告实际生效；旧版身份本身不产生来源不匹配。
- [ ] 目标标识解析到错误来源时，三端均报告 `sourceMismatch=true`（来源不匹配），期望稳定来源不报告为实际生效。
- [ ] `effective`（实际生效）只在来源已注册、已安装、已启用且未被更高优先级来源覆盖时为真。
- [ ] Pi 的相对路径、项目覆盖、无安装目录和重复来源主流程继续通过打包端到端回归。
- [ ] Claude 和 Codex 的市场来源、禁用插件、错误来源、缺失安装目录及重复来源主流程继续通过打包端到端回归。
- [ ] 自动检查证明三端都执行了全部六个共享案例标识，不能由三份相似但独立的案例列表替代。
- [ ] 使用 Build and Verify（构建与验证）入口运行覆盖完整用户主流程的最终回归并通过。
