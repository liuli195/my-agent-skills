# 02 — 准确诊断禁用与安装目录缺失

**What to build:** 让 MySpec（自有规格）用户在三端都能区分“来源被禁用”和“配置允许加载但安装目录缺失”。共享案例表增加这两个状态，三端通过打包后的 `myspec doctor`（诊断命令）报告独立的注册、安装、启用和实际生效事实。

**Blocked by:** 01 — 建立三端统一来源诊断

**Status:** ready-for-agent

- [ ] 共享案例表增加“稳定来源被禁用”和“稳定来源目录缺失”案例，并由 Pi、Claude 和 Codex 全部运行。
- [ ] 被禁用的稳定来源在三端均报告已注册、已安装、未启用、未生效，来源类型为稳定且来源不匹配为假。
- [ ] 安装目录缺失案例保留宿主登记和配置启用状态，但报告未安装、未生效。
- [ ] `installed`（已安装）只有在宿主报告安装位置、目录实际存在且包含可识别 MySpec 包信息时才为真。
- [ ] `enabled`（已启用）表达宿主配置意图，不因目录缺失被自动改为假。
- [ ] 现有顶层诊断字段与新增来源记录保持兼容且不互相矛盾。
- [ ] 对应打包端到端回归可独立运行并通过。
