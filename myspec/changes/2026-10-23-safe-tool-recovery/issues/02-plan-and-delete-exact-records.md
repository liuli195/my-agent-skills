# 02：预演并执行精确记录组维护

**What to build（交付）:** 用户从随已安装 Data Store（数据存储）提供的公开维护入口，按逻辑表＋精确键预演删除计划，在离线维护且授权精确计划后按文件身份执行，得到真实逐项结果并可沿同计划恢复，不复制业务项目大型清理器。

**Blocked by（前置）:** None（与01技术独立；推荐串行在01验收后实施，不把排程顺序虚构为技术依赖）。

**Status（分拣）:** ready-for-human（两票实施验收完成；门禁二已确认，正式规格已应用；待PR交付、发布同步及发布后真实验收）

## Acceptance criteria（验收）

- [ ] 只接受非空明确逻辑表和精确键，复用现有名称／大小写规范并去重；无通配、全库、全表、任意路径或行级删除。
- [ ] 只读预演绑定计划身份、精确数据根、目标及文件身份，不能只凭同名路径／键判断有效；无关历史和业务数据保持不变。
- [ ] 执行要求精确计划授权和外部离线维护确认；任何删除前完整预检全部目标，逐项执行前再次核验身份，越界、重定向、缺失、权限／锁故障和内容漂移明确区分。
- [ ] 输出成功、失败、未执行及结果不确定明细，不冒称批量原子事务；保存部分结果且不伪称已回滚发生的删除。
- [ ] 同计划恢复只处理未可靠完成项，再核验原身份；不重复已完成项，不删除同键后来重建的新文件；回执失败等不确定结果不能盲目重试。
- [ ] 业务引用、保留政策及允许删除什么仍由调用项目确定；不扫描全历史推断孤儿，不删除业务锁文件，不将原项目清理器迁入技能。
- [ ] 不改变正常读写热路径、项目共用连接及接口能力版本二；保留最新固定基线 Data Store 2.5.0 已有二进制写入／BLOB（字节字段）能力及类型、错误含义。
- [ ] 最高公开CLI（命令行）及独立市场运行形态完成预演／执行／部分失败／同计划恢复的红绿和冒烟验证；新增用例纳既有统一验证，保持原公开单键／多键／字节读写回归。
- [ ] 小规模同条件交替核验维护成本与原读写无稳定退化，不新增后台监控或固定通用耗时门槛，不把接口次数冒充物理I/O（输入输出）次数。
