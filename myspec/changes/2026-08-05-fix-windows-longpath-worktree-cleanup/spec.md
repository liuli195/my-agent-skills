# 修复 Windows 长路径工作树清理

## Problem Statement（问题说明）

Windows（视窗系统）上的 PR Flow（拉取请求流程）在删除已完成流程的关联工作树时，可能因为 `.local/spec-work` 生成的深层临时文件路径超过系统路径限制而返回 `Filename too long`（文件名过长）。Git（版本管理）登记和目标工作树的内部指针可能已经移除，但实体工作树目录仍然残留，用户需要手工处理。

## Solution（方案）

在现有工作树清理入口中，为 Windows（视窗系统）的 Git 删除操作启用命令级长路径支持，使包含深层 `.local/spec-work` 生成物的干净关联工作树也能完成非强制删除。该设置只作用于本次删除命令，不写入仓库或用户配置；其他平台、短路径和现有安全删除边界保持不变。

## User Stories（用户故事）

1. 作为 Windows（视窗系统）维护者，我希望合并后的 PR（拉取请求）工作树即使包含深层 `.local/spec-work` 生成物也能被正常清理，从而不必手工删除残留目录。
2. 作为 PR Flow（拉取请求流程）使用者，我希望长路径清理仍然使用现有的非强制工作树删除行为，从而不会扩大删除权限。
3. 作为跨平台维护者，我希望短路径和非 Windows（视窗系统）环境的清理结果保持不变，从而修复不会改变无关平台行为。
4. 作为仓库维护者，我希望长路径支持只对当前删除命令生效，从而不会静默修改仓库或用户的 Git 配置。
5. 作为测试维护者，我希望真实 Windows 长路径场景被固定为回归测试，从而后续修改不会再次引入目录残留。

## Implementation Decisions（实现决定）

- 复用现有 PR Flow 工作树删除模块和公开清理入口，不新增命令、状态文件或授权状态。
- 仅在 Git 删除适配器的 Windows 路径启用命令级长路径配置；不持久化 `core.longpaths`，不改变 `.local/spec-work` 的生成位置。
- 保留现有非强制删除、主工作树保护、干净工作树检查和 Git 工作树登记校验。
- 本次针对已确认的 Git 删除路径长路径失败；Orca（工作区管理器）管理的删除路径不在本变更中扩展。

## Testing Decisions（测试决定）

- 最高测试接缝是现有 PR Flow 清理命令的真实入口，而不是私有删除函数。
- Windows（视窗系统）真实回归场景建立临时 Git 仓库和关联工作树，在被忽略的 `.local/spec-work` 下生成超过系统路径限制的深层文件，然后执行带删除工作树参数的清理。
- 回归必须验证：命令成功、目标实体目录消失、Git 工作树登记不再包含目标、主工作树未被修改，且仓库配置没有被持久写入长路径设置。
- 保留短路径、非强制参数、Orca（工作区管理器）选择和失败分支的现有检查。
- 实施后使用 Build and Verify（构建与验证）快速入口，并从真实 Windows 用户入口完成一次冒烟；不执行无关的完整回归。

## Out of Scope（范围外）

- 不新增批量清理已残留目录的命令或状态文件。
- 不引入逐层删除、强制删除、跨会话授权或新的清理确认机制。
- 不移动 `.local/spec-work`，不缩短工作树名称，不改变 MySpec（自有规格）运行状态布局。
- 不处理一般文件锁、Orca（工作区管理器）删除器自身的长路径行为或其他未复现的残留原因。
- 不修改 PR Flow 的合并、分支保护、发布、客户端同步或用户环境安装流程。

## Further Notes（补充说明）

Issue #163 的复现表明，Windows 深层生成路径可以使 Git 删除命令部分完成：登记消失但实体目录保留。本变更只修复该已确认的路径限制触发条件；其他清理残留原因应另行立项，避免把本次修复扩大为新的残留管理系统。
