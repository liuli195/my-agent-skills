# 02：插件同步支持逐插件开发／正式切换与恢复

**What to build（交付内容）：** 用户通过已有插件同步技能选择插件和来源，由两个客户端原生操作完成切换、真实状态检查与失败恢复。

**Blocked by（前置任务）：** 01。

**Status（状态）：** ready-for-agent

- [ ] 两市场长期登记，切换插件不移除市场、不改其他插件。
- [ ] 预检目标和原状态，按完整插件标识串行切换并检查实际来源、启用和内容。
- [ ] 开发修改可通过明确刷新／重新安装／会话加载步骤实际生效，恢复时明示版本。
- [ ] 对目标缺失、重复来源、安装失败、恢复失败分别提供真实结果和下一步，未生效不报成功。
- [ ] 不新增全局程序或平行持久安装清单；NPM 管理继续委托自身命令。
- [ ] 数据中心技能包含代理接入仓库的完整步骤；插件更新／切来源涉及已接入仓库时刷新其共用接入关系，未完成时明确报告，正常运行不需要代理传路径。
- [ ] 数据中心技能随包提供现成的项目接入薄层，代理仅调用；薄层从自身实际安装目录接入，支持检查与重复更新，不要求每个仓库临时编写薄层。
- [ ] 接入冲突普通目录／文件时明确拒绝；重复连接安全、更新失败保留可恢复状态，不删除真实安装目标或数据。
- [ ] 既有数据中心源码自动检查保留，薄层必要检查接入统一验证，不新增 CI 的 NPM 安装或市场代理调用要求。
- [ ] 数据中心核心与共用入口通过同环境、同数据、同工作量性能回归；覆盖冷启动、重复调用、独立命令及批量嵌套报告，不用减少工作量或逐次启动进程绕过比较。
- [ ] 真实两端往返与失败路径检查通过；独立审查通过。
