# 技能安装来源与开发／正式切换

Status: ready-for-agent
执行状态：门禁一已确认，包括数据中心性能回归；允许当前分支实施与隔离验证。正式规格应用、发布、本机迁移和清理仍待门禁二。

## Problem Statement（问题）

个人技能存在共享市场、NPM（软件包管理器）和直接目录链接三条安装途径，部分产品在共享市场与 NPM 重复提供，使用者难以判断当前来源，也无法一致地在两个客户端选择开发版或正式版。

## Solution（方案）

只保留市场和 NPM 两条发行途径。有独立命令行工具的自有规格与构建与验证继续由 NPM 提供命令、技能和客户端登记；另外七项通过市场提供。正式市场与本地开发市场长期共存，每个插件独立选择一个生效来源。

## User Stories（使用要求）

1. 用户在 Codex（代码助手）与 Claude Code（克劳德代码助手）都能安装同一组七项市场插件。
2. 用户能通过正式市场名称 my-agent-skills-marketplace 与开发市场名称 my-agent-skills-marketplace-dev 区分来源，开发显示名称包含 DEV（开发版）。
3. 用户在切换任何插件时仍能浏览两个市场，其他插件、第三方市场和无关设置保持不变。
4. 用户能单独让一个插件使用开发源码，其他插件继续使用正式版。
5. 用户修改开发源码后，按明确的刷新、重装与会话重新加载步骤让实际技能使用新内容；不承诺即时加载。
6. 用户能切回原正式来源，并知道实际恢复的来源与版本；若只能取得较新版本须明示，不得声称固定版本已恢复。
7. 用户在安装失败或部分迁移时知道已完成步骤、当前状态、原始错误和可用恢复动作，不得到虚假的成功报告。
8. 自有规格和构建与验证在共享市场移除自身后仍能进入开发模式；它们各自包内的市场登记、技能、命令和源码身份校验继续有效。
9. 用户不会同时启用同一市场插件的两种来源，已发现的其他来源须报告，不能静默删除。
10. 数据中心从旧链接迁移之后，代理从技能入口为仓库建立一次共用接入关系，所有已对接工具和命令都能使用；Sim2GSE（模拟搜索工具）为首个验收样本。正常运行无需用户填路径、启动方传路径或额外定位工具。
11. 最终验收通过后只删除本次确认的旧技能一级链接和本次临时材料，不删除源码、用户数据及第三方技能。

## Implementation Decisions（实施决定）

- 市场七项：release-flow（发布流程）、pr-flow（拉取请求流程）、dev-flow（开发流程）、subagent-policy（子代理策略）、plugin-sync（插件同步）、retro-to-issues（复盘转任务）、data-store（数据中心）。插件本身保持原名称，由所属市场区分开发与正式来源。
- 保留现有发布流程、插件注册表和市场生成规则，补齐市场包装及双方一致的七项清单；两项 NPM 产品不再出现在任何共享市场入口，但各自包内登记保持。
- 插件同步使用客户端原生查询与安装管理命令，逐插件保存本次操作前的真实来源及版本、预检目标、移除旧来源、安装新来源并核验。不新建全局命令行程序、长期安装清单或缓存路径规则。
- 安装前发现冲突或目标不可用时停止；安装中断或失败后报告真实状态，按原生入口恢复旧来源，不能掩盖恢复失败。两个客户端逐个处理，不承诺跨客户端原子切换。
- 实际源码核查发现：共享开发模式校验要求根市场含自身，与共享市场去重冲突。建议最小调整为验证包内自身登记，继续保留官方源码身份、远端、干净状态等校验。此调整涉及共享 NPM 实现，超出此前“完全不动 NPM”的判断，须在门禁一明确确认；交付时依照发布前检查更新受影响两包的版本，不修改包名或命令契约。
- 本机最终使用来源保持迁移前意图：原源码链接迁入开发市场，原正式市场插件保持正式来源；往返验收完成后恢复该选择。
- 两个仓库均沿用当前工作树，以独立功能分支交付。数据中心消费位置适配先于删除旧链接，存储格式、逻辑表契约、搜索策略及现有性能优化保持。
- 数据中心保持市场发行；技能新增代理初次接入与重复接入、唯一来源核验、本机项目稳定目录入口、依赖核验和更新／切来源重接入说明。优先用一级目录联接表达项目连接，不另建 JSON 安装清单；此入口不是第三条插件发行渠道，运行工具不查客户端，不同工具共用已安装核心实现，不另装定位程序、不复制实现、不将本机路径提交到共享源码。
- 用户已确认接入薄层作为数据中心技能内现成资源分发。代理只运行其接入／检查／更新操作，不为每仓库生成加载或定位实现。薄层依据自身所在的已安装技能目录建立项目稳定入口，仓库原消费者只需一次适配共用入口；不修改存储核心语义。
- 接入薄层不覆盖同名普通文件或目录，只更新已核验的连接；先校验目标，重复接入幂等，失败保留原连接并报告。目录链接删除只删除链接，保留技能安装目标与用户数据。
- 不把数据中心作为 CI（自动检查流程）需安装的 NPM 工具，不新增 CI 市场安装或代理接入要求；已有数据中心源码测试及发布包装检查保留，新增接入薄层的必要测试接入既有统一检查。
- 用户明确的发行理由：自有规格与构建验证自身要在 CI 执行标准流程并自举、自检查，沿用 NPM；数据中心没有这种业务角色，通过市场技能在代理接入时建立关系。源码自动测试与工具在 CI 自举是不同事项。
- 接入薄层从自身技能目录确定目标，不要求代理另传插件位置；只需项目位置及更新时预期旧目标。已运行进程保持首次加载的实现，更新后须重新启动才采用新实现；不在每次读写轮询安装目录或强制热加载。
- 不新增单独架构决策文件。本次术语和取舍在本需求中留证，正式规格在交付门禁预览后再更新。

## Testing Decisions（验证决定）

- 最高用户入口是两个真实客户端的市场命令与新会话中的实际技能入口；内部测试和安装清单不能替代实际使用。
- 先沿用隔离配置中的真实正式→开发→正式往返试验，覆盖同名插件来源正确、两市场保留、其他插件未变；再逐项验证七项真实插件、开发内容更新及恢复。
- 沿用打包后工具入口验证两个 NPM 包的开发／正式切换和客户端发现，覆盖去掉根共享市场自身入口后仍可切换；不得使用宿主预装包代替候选包。
- 模拟或隔离的失败试验覆盖目标缺失、移除后安装失败、恢复失败和重复来源；真实安装行为完成后立即检查该端实际加载。
- Sim2GSE 通过已有公开入口验证无旧链接情况下的数据中心可用性、逻辑表写入／查询、缺失或冲突来源明确拒绝；不需要重跑十分钟性能实验或实际游戏验收。
- 临时机制试验五项通过：原脚本进程内写入、另一读取入口、独立命令无运行时路径参数、连接改到另一安装位置后原命令可用、失效位置明确拒绝。临时材料已清理；此试验不等同于正式接入功能、两端安装及全部消费者验收。
- 随后最低成本原生项目目录联接试验五项通过，覆盖多工具共用、独立命令、重接新来源、旧安装目标保留和失效不回退；无需安装器或 JSON 解析层，临时链接及目录已删除。正式两端市场接入与任务完整使用仍待验收。
- 本轮核对现有 CI 的完整验证会运行数据中心源码检查，区别于把它作为全局 NPM 插件安装使用；本需求不删除已有测试，也不扩大业务运行依赖。
- 常规检查通过既有构建与验证入口执行，使用两个干净功能分支提交与固定基线；新增必要检查接入现有入口，跳过、缺依赖和失败分别报告。
- 用户追加性能回归硬门槛：以本次改动前已交付实现为基线，使用同一机器、解释器、DuckDB 版本、线程选择与冻结的真实仓库数据，交替重复测量前后相同工作量。分别记录首次加载／冷启动、重复进程内调用和独立命令总耗时，不以减少调用、批次数、字段、输出记录或改线程设置制造提速。
- 性能范围包括写入与同键替换，单键完整／指定字段／筛选，多键完整／指定字段／筛选，通用查询与聚合／多表查询，嵌套完整报告和大量平坦记录。重点保留12份嵌套报告场景；每项核对实际工作量、返回内容与类型。
- 输出改前／改后耗时、中位数、离散范围、变化比例、重复次数和数据规模；任何超过重复测量正常波动的稳定退化须查因、修复和重测，不允许用其他场景收益抵消或在未解决时交付。数据中心核心与仓库共用入口两条调用路径都须覆盖，不增加每次读写进程启动、客户端查询或文件定位开销。
- 最终清理核对准确目标、原始数据不变、第三方安装不变及临时目录不存在。

## Out of Scope（范围外）

- 重写 NPM 生命周期、另发带 -dev 名称的 NPM 包、自动修改 NPM 当前模式、迁移第三方插件。

- 门禁一前生产修改；门禁二前正式规格应用、合并、外部发布与最终本机清理。
