# 统一测试运行时守卫与显式迁移

**Status:** ready-for-human

第一阶段01／02票已完成交付：拉取请求389合并，主干提交为 `05987c3f96c95ce9285085f9fa4e0c6e6792aa0b`，版本2.7.0已发布；本机固定基线快速验证、两平台持续集成及代码扫描通过。03票整体迁移方案已获批准，当前收敛第二阶段门禁一；尚未实施，配置最终写入确认尚未取得，不能将本变更整体标为完成。

## Problem Statement

普通测试仍能通过导入、准备、辅助函数或清理启动外部进程、联网及写真实文件。现有静态扫描和逐测试真实执行名单既不能完整约束运行行为，也让重复安装、命令启动和临时仓库准备持续增多。只删除慢测试又会丢失必要的真实安装、命令、锁、超时与回滚覆盖。

用户已有三个仓库使用构建与验证插件，升级不能立即改变旧配置的运行限制或使现有验证全部失效。本次分两阶段：先交付01／02票插件能力与配套测试，发布新唯一版本并定向更新实际执行器；再从交付后的最新远端主干新建功能分支并固定新基线，只迁移技能仓库。另两个仓库保持原样，留给用户逐仓迁移。

## Solution

复用统一构建与验证入口。新初始化的项目采用新规则；旧配置升级后仍按旧规则执行，明确提示尚未保护，不阻断旧验证，也不冒充新规则通过。既有项目只有显式迁移后才启用新规则。

新规则通过项目显式配置的真实检查标识清单登记集成／冒烟检查。纯内存项目可显式配置空清单；有真实场景时按需配置一项或多项，各项必须对应实际存在的验证检查且不得重复。每项真实检查可包含多个场景函数，适用时继续共享必要准备；未登记的普通测试默认以真实运行时守卫禁止业务外部进程、联网和真实文件写入，保留必要代码、配置及数据读取。守卫覆盖导入、准备、执行、清理、辅助函数和线程，且保留外层检查并行与内层测试框架工作进程并行。所有检查仍经统一构建与验证总入口调度，并共享项目总预算。三个仓库的现有命令与副作用形态用于核对适配契约，不表示另外两个仓库已经迁移或验证通过。

## User Stories

1. 作为已有项目维护者，我希望升级插件后旧配置仍能验证，以便自己安排迁移时间。
2. 作为三个仓库的使用者，我希望只迁移本次批准的技能仓库，以免其他仓库被连带修改。
3. 作为新项目维护者，我希望初始化默认采用新规则，以免继续积累重型普通测试。
4. 作为迁移者，我希望配置先备份且可以明确回退，以便恢复旧验证而不丢失原配置。
5. 作为报告使用者，我希望区分旧模式与已保护的新模式，以免把旧证据当作新策略验收。
6. 作为测试作者，我希望普通测试不能启动业务外部进程，以便逻辑测试保持进程内执行。
7. 作为测试作者，我希望普通测试不能联网或写真实文件，以免辅助函数悄悄引入副作用。
8. 作为测试作者，我希望导入、准备、清理及线程也受同样约束，以免测试正文以外形成漏洞。
9. 作为测试作者，我希望必要读取仍可用，以便测试真实业务主函数，而非只能返回预设成功。
10. 作为维护者，我希望按场景显式配置所需的多项真实集成／冒烟检查，并复用必要准备，以兼顾灵活性、覆盖和成本；纯内存项目不必配置真实检查。
11. 作为并行验证使用者，我希望外层检查和内层工作进程继续同时运行，以免靠降并发掩盖守卫问题。
12. 作为维护者，我希望控制进程中的项目回调同样受保护，以免框架控制端成为放权通道。
13. 作为维护者，我希望新建及重启工作进程在项目加载前受保护，以免并行启动绕过守卫。
14. 作为维护者，我希望捕获违规异常也不能把检查变为通过，以免违规被业务代码吞掉。
15. 作为缓存使用者，我希望旧、新模式及不同守卫身份的结果不混用，以免出现错误缓存命中。
16. 作为命令使用者，我希望原有字符串、列表、组合命令及包管理／环境工具链保留，以免迁移迫使我改掉正常工作方式。
17. 作为跨平台使用者，我希望视窗系统和 Linux（开源操作系统）都保留真实验证，以免只在云端一种平台成立。
18. 作为维护者，我希望超时、取消、崩溃和保护缺失真实失败且回收本次后代进程，以免后台遗留或假成功。
19. 作为性能验收者，我希望本机完整验证仍低于60秒且不提高预算，以便获得真实可用的收益。
20. 作为维护者，我希望删减重复测试但保留必要真实安装、命令、锁、事务回滚和不确定结果处理，以免速度改善换来安全回归。

## Implementation Decisions

- 目标产品是构建与验证插件；随后应用到技能仓库的整套已配置验证，不是只治理几个慢文件。复用现有入口、配置、检查选择、调度、缓存、报告、进程管理及初始化备份能力，不新建公开总入口或调度器。
- 术语：普通测试指未登记为真实检查、禁止业务外部副作用且允许必要读取的逻辑测试；真实入口指显式清单登记的项目验证检查，可按场景配置多项，每项可包含多个场景函数；统一总入口仍指既有构建与验证命令，不为真实检查另建调度入口。受控工作进程指框架为既定工作单元启动的内部执行单元，不等于业务可启动任意程序。
- 使用既有配置版本表达显式的新旧模式；新模式显式声明项目真实检查 ID（标识）清单，纯内存项目允许空清单，各项必须无歧义地对应实际存在的验证检查且不得重复。缺少清单或清单无效在检查启动前明确失败；未登记检查默认保护。清单仅声明角色，不改变快速／完整／差异／拉取请求及手动／跳过项的既有选择语义；不增逐测试、逐模块豁免或额外复杂权限矩阵。
- 旧配置及旧命令保持原语义，包括任意字符串或列表、组合命令、npm（软件包管理器）、pnpm（包管理器）、yarn（包管理器）、tox（Python 环境工具）及 nox（Python 自动化工具）等既有工具链；新模式不擅自缩减这些命令形态，也不猜测封装命令安全。未登记检查中不能识别或不能证明保护的测试段必须明确标为未覆盖并报错，不得无保护执行、自动退回旧模式或把整组未知命令登记为真实检查来绕过。
- 新初始化默认新规则；旧项目必须逐仓显式迁移。迁移先备份旧配置，完成结构校验并展示保护状态；失败不得静默退回旧模式报成功。用户明确选择恢复备份时可回到旧模式，但必须继续标明未保护。
- Python（编程语言）与 Node.js（节点运行时）仅作为现有统一验证内部的两个实际适配器，共用保护语义、违规结果及缓存身份，不建立通用沙箱或假想扩展平台。
- Python 适配同时覆盖 pytest（测试框架）收集 unittest（标准测试框架）及直接运行 Python 脚本；Node.js 适配同时覆盖直接脚本与 `node --test`（原生测试命令）。保留视窗系统环境赋值、`&&`（成功后继续）、引号、路径及测试参数；混合语言命令逐段保护，并保留退出码与短路语义。关闭插件自动加载时仍须显式加载守卫；不统一禁用 JIT（即时编译），不丢失显式加载的并行插件或其工作进程参数。
- 项目代码加载前启动守卫，覆盖控制进程及全部工作进程；框架只经固定、受限的启动通道创建既定工作单元。不得按调用栈或整个控制进程放行，不得为业务提供可调用的暂停守卫接口；重启也须重新受保护。
- 普通测试禁止业务启动外部进程、联网和真实文件变更，包括临时目录、准备、清理和线程中的写入。必要代码与配置读取保留；框架必要的内部记账、通信及受控工作进程启动须与业务权限分开，不能扩大为通用豁免。
- 守卫不是针对恶意本地代码的安全沙箱，不声称防止原生扩展或蓄意篡改；也不能用静态扫描、调用图分析或原有假执行器代替运行时保护。
- 2026-10-23 原生行为边界补充采用用户批准的方案A：继续保护 Python／Node 常规接口，SQLite（标准数据库）只补官方原生授权回调可覆盖的小范围文件行为，保留纯内存查询及业务自己的授权回调。DuckDB（分析数据库）相关场景单独登记为显式真实检查，包括纯内存场景；仍真实运行并保留并行，但本期不享普通无副作用保证，报告不能算作已保护通过。普通模式遇到 DuckDB 必须明确未覆盖并失败，不自动整组放行或自动写真实清单。不扩展任意原生库适配；新发现的正常原生漏拦需先报告，不能用“不是恶意沙箱”忽略。
- 2026-10-23 用户另行批准 SQLite（标准数据库）文件型 WAL（预写日志）窄限制：两语言普通模式均在原生打开前读取文件头识别并明确未覆盖拒绝，吞异常仍失败；这类读取须由项目显式登记真实检查。保留内存与静态非 WAL（预写日志）必要只读，不自动改清单、日志模式或添加不可变参数，不增加虚拟文件系统或并发状态处理；不声称对其它进程在检查后替换文件、切换模式提供原子保证。
- 违规独立记账并由外层判失败，即使异常被捕获、工作进程重启或业务返回成功也不清除。守卫未加载、工作进程失联、崩溃或必要保护结果不完整均失败；普通性能报告写入失败仍保留既有警告语义，不等同于保护记录可缺失。
- 已配置的外层检查并行、pytest-xdist（Python 并行测试插件）及 Node.js 原生内层并行必须保持；多项真实检查与普通测试复用既有调度、每项超时和一次运行的项目总截止，准备也计入总预算，不因真实入口增多而增加或重复分配项目总预算。显式串行检查保留既有语义；不以关闭任一已配置并行层、缩平台、扩大预算或静默无保护回退换取通过。
- 保留快速／完整／固定基线差异验证、拉取请求过滤、通过／失败／跳过、诊断、单项超时、总截止、取消与拥有进程树回收。不得影响无关进程；超时、取消、违规、未完成及诊断结果不得写正式成功缓存。
- 缓存键与证据包含新旧策略、适配器及每项检查的普通／真实角色和清单策略身份；同一检查移出或加入真实清单后不能混用旧证据，原无守卫的真实成功不得供普通模式复用，旧模式证据不能证明新策略通过，新模式失败不能复用旧成功结果。完整验证仍运行全部配置检查，不靠缓存跳过。
- 整仓普通测试迁为内存逻辑测试；按场景显式登记的真实检查保留少量代表性安装、公开命令、锁、超时回收及回滚场景，适用时复用成功且完整的只读准备，不强制每项重新准备。不以模拟替代必须真实证明的安装、命令、锁、权限、删除不确定结果或事务恢复行为。
- 迁移按真实副作用叶行为分类，不因使用 pytest、unittest 或 Numba（数值编译工具）就整组豁免或整组转为集成；DuckDB（分析数据库）仅按上述已批准方案A单独划出相关场景。必要真实外部行为归显式登记的相应检查；其名称与场景范围纳入门禁审阅，不自动把整组未知命令列入清单。已覆盖的纯内存数据库与计算可留普通测试。构建及其 make（构建工具）／Git（版本管理）产物与测试保护分开；不新增 Lua（脚本语言）、通用命令解释器或原生程序安全沙箱，原有手动／跳过项不得自动改为默认执行。
- 本次开发优先在云端完成，不修改另外两个仓库或用户全局安装、开发源码绑定。若后续确需本机硬件性能证明，只在准确授权范围内执行，插件开发来源不得切换为发布来源。
- 本机60秒预算、既有更窄插件性能目标和两平台要求均不变。若实现需要额外功能退化、明显新增成本或超出最小方案的复杂度，先单独展示原因、收益、成本及影响并取得批准，不由实施者代为取舍。

## Testing Decisions

- 最高层级真实验收通过官方打包、隔离安装后的统一构建与验证总命令，覆盖初始化、构建及验证；使用现有打包与成功安装模板，不安装到用户全局环境。红灯、绿灯和最终冒烟沿用同一公开总入口。
- 重复逻辑分支沿用现有主函数入口、可注入执行器、受控时钟和精确响应替身；测试真实可观察契约，不断言内部拦截函数实现，也不让未知命令默认成功充当守卫。
- 以普通内存逻辑测试加显式登记真实检查中的少量代表场景证明保护，不新增逐测试重型预检或大规模重复进程启动矩阵。
- Python 与 Node.js 分别证明导入／准备／正文／清理／辅助函数／线程中的业务进程、网络、文件变更被拒绝；异常被吞仍失败，必要读取及纯内存计算成功。
- 真实证明外层与内层确有并发，控制端项目回调和新建／重启工作进程在项目加载前受保护；受限启动通道不能启动任意业务程序。
- 兼容验收覆盖旧配置不自动迁移、明确未保护提示、字符串／列表及工具链命令形态、新初始化默认、显式迁移、备份恢复、无保护失败、无静默回退及策略缓存隔离；最少代表覆盖显式空清单、一项与多项真实检查、缺失／不存在／重复标识失败，以及真实检查和未登记普通测试并行时保护互不放宽、总预算不增加。
- 用三仓已核实的命令形态构造最少代表契约：技能仓库的 Python／Node.js 复合命令；Wow 的视窗系统虚拟环境、unittest 收集及两语言直接脚本；Quant 的环境赋值、复杂引号／测试定位与筛选参数、关闭插件自动加载下的显式守卫、保留 JIT 及显式四工作进程。样例证明的是适配契约，不等于 Wow 或 Quant 整仓通过；不为本票实际迁移或运行另两仓。
- 保留真实锁、超时后代回收、无关进程存活、安装不完整不复用、失败／跳过、回滚及不确定结果处理代表；不得把这些全部换成模拟。
- 整仓16个 Python 测试文件与3个 Node.js 测试文件均须纳入盘点及处置；记录每项既有行为保留于普通测试还是显式登记的哪项真实检查，不能仅删除原真实执行名单。
- 通过既有统一入口执行固定基线快速验证，已检查项必须非空；完整验证不读成功缓存，并记录优化前后同口径计时及主要耗时。云端结果不冒充本机低于60秒证明，单平台结果不冒充跨平台通过。
- 验证需要视窗系统与 Linux（开源操作系统）对应证据，并保留现有跨平台汇总门禁；本机60秒及更窄目标未证明时明确列为未验收，不靠改预算或少跑检查结案。

## Out of Scope

- 自动迁移另外两个仓库，升级即强制启用新限制，或旧模式假装受保护。
- 通用安全沙箱、Lua／通用命令解释器／原生程序安全沙箱、恶意代码隔离、静态调用图治理、逐测试豁免名单、独立公开总入口及重复重型预检。
- 缩减平台或正常命令兼容、取消并行层、提高预算、删除必要真实覆盖。
- 当前需求准备阶段的实施、测试执行、安装、分支操作、提交、推送、发布及主干合并；交付动作另依后续门禁。
