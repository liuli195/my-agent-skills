# 02: Node.js 保护闭环

**What to build:** 新规则项目中的 Node.js（节点运行时）普通测试从原有命令和原生并行测试入口执行，遵守与 Python（编程语言）相同的副作用、迁移、失败与缓存契约；按场景显式登记的真实检查仍可完成必要集成／冒烟场景，均由既有统一总入口调度。

**Blocked by:** 01：兼容迁移与 Python 保护闭环。

**Status:** ready-for-agent

- [ ] 沿用01票的配置版本、项目显式真实检查 ID（标识）清单、违规结果、策略身份、报告与缓存契约；允许空清单及按场景一项或多项，各项必须实际存在且不得重复，未登记普通测试默认保护，不新增逐测试放权字段、逐项复杂权限矩阵或独立调度器。
- [ ] 同时覆盖直接 Node.js 脚本与 `node --test`（原生测试命令），从项目代码加载前保护控制端与所有原生测试工作进程；项目导入、准备、执行、清理、辅助函数及线程中的业务进程、联网、真实文件变更被拒绝，必要读取和纯内存逻辑成功。
- [ ] 原生工作进程只能通过固定、受限的框架通道启动；启动及重启均先安装保护，不把整个控制端、工作线程或业务可用启动函数放行。
- [ ] 原有命令字符串／列表／组合形态和 npm（软件包管理器）、pnpm（包管理器）、yarn（包管理器）等工具链保留；Python 的 tox（环境工具）、nox（自动化工具）及既有封装形态不回归。不以不能识别命令为由静默无保护执行或自动登记整组未知命令。
- [ ] 以技能仓库 `python -m pytest … && node --test`（两语言复合命令）和 Wow 非 `--test` 直接脚本作代表契约；未登记检查的每个测试段均受对应守卫保护，前段失败不得继续后段，退出码、引号、环境和参数不变。未知封装或未保护段明确列未覆盖并报错，不整体改为真实集成、不自动降级；代表样例不等于消费仓库整仓通过。
- [ ] 实证外层多个检查与 Node.js 原生内层工作进程均能并发运行；混合语言项目可在同一显式清单中按场景登记多项真实检查，与普通测试共用既有调度、每项超时和项目总预算，真实入口增多不增加项目预算，且不放宽其他普通测试保护、不关闭已配置的任一并行层。
- [ ] 吞违规异常、业务返回成功、工作进程重启仍失败；保护缺失、子进程失联／崩溃或结果不完整失败，且不会写入成功缓存或使用旧模式证据。
- [ ] 保留单项超时、总截止、取消与后代回收、无关进程存活及失败／跳过／诊断语义；普通报告警告不能掩盖保护失败。
- [ ] 复用现有主函数、执行器和精确响应替身完成主要内存分支；在现有官方打包／隔离安装命令接缝增加少量真实代表，证明合法并行、控制端回调保护、重启保护与吞异常仍失败。
- [ ] 不提前迁移技能仓库或其他消费者；完成与01票共享契约的回归并独立审查，不把 Node.js 成功代替 Python 或两平台证据。

公开测试接缝：官方打包、隔离安装后的同一验证命令及现有主函数接缝。失败恢复接缝：受保护重启、明确失败不降级、取消回收和策略缓存隔离。不能保留兼容、平台或并行时停止报审，不自行缩减。
