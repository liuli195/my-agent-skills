# 03: 技能仓库迁移与整仓验收

**What to build:** 只将技能仓库显式迁移到新规则：整仓普通测试保持内存逻辑执行，按场景显式登记的真实集成／冒烟检查覆盖必要真实行为并复用适用准备；在不削弱兼容、两层并行或覆盖的前提下，完成统一总入口的功能与性能验收。

**Blocked by:** 01：兼容迁移与 Python 保护闭环；02：Node.js 保护闭环。

**Status:** ready-for-agent

- [ ] 先盘点全部16个 Python（编程语言）测试文件与3个 Node.js（节点运行时）测试文件及共享准备，逐项标明行为保留于普通内存测试还是显式登记的哪项真实检查；拟登记检查的名称和场景范围须在修订后的门禁一展示审阅，不只处理原名单中的少数慢文件。
- [ ] 核对实施分支 `codex/unified-test-runtime-guard` 已依门禁一批准，从真实远端主干 `de7871a339018155aca365600e58f9b5ac164543` 在同一工作树建立；不从云端旧本地主干、旧功能分支或 `v2.6.0`（发布标签）起步。当前仅更新需求，不执行分支操作。
- [ ] 通过已完成插件的显式迁移与备份机制更新技能仓库配置，按获批场景登记项目真实检查 ID（标识）清单，各项必须实际存在且不得重复；产品允许纯内存项目空清单及按需一项或多项，本仓按必要真实覆盖登记，不增逐项复杂权限矩阵。未登记普通测试默认保护；另两个消费仓库不变，旧配置备份可明确恢复且恢复后标记未保护。
- [ ] 根据规格三仓盘点核对01／02票的代表适配证据，区分“命令契约通过”“尚未覆盖”“整仓验收通过”；仅本仓2项构建、10项验证实际迁移与整仓验收，Wow 的2项构建／37项验证、Quant 的18项验证只盘点，不修改配置或宣称全仓通过。
- [ ] 普通测试不再通过导入、准备、辅助函数、线程或清理启动业务外部进程、联网或写真实文件；继续调用真实业务主函数，使用已有内存／可注入执行器接缝，不把顶层返回模拟成功。
- [ ] 去除以静态扫描、调用图及逐测试名单代替运行约束的旧治理；新守卫实际执行且违规能导致统一入口失败，不以删名单或改测试名称完成迁移。
- [ ] 显式登记的真实检查按场景保留多个必要场景函数，适用时在检查内或检查间复用完整成功的只读准备，不强制每项重新准备；保留官方打包、隔离安装、裸命令、真实 Git（版本管理）状态、锁／互斥、权限路径、超时回收、事务回滚和删除不确定结果处理等必要代表，不以模拟全替。
- [ ] 控制端预打包、临时仓库、真实安装及命令等外部叶行为明确归显式登记的相应检查，不把整个 pytest（测试框架）组豁免，不自动把整组未知命令列入清单。纯内存数据库／计算不因所用库而整组转集成；构建及 make（构建工具）／Git 产物与测试保护分开，原手动／跳过项不自动纳入默认执行；不借三仓适配新增 Lua（脚本语言）或通用命令解释器／原生程序安全沙箱。
- [ ] 失败或半成品安装不复用；准备和回滚异常报告真实失败，保留首次失败；清理不扩大到无关路径，不留下本次拥有的后台进程。
