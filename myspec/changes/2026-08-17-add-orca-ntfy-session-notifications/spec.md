## 问题陈述

Orca（代理运行平台）手机端连接断开时，代理状态通知可能无法到达用户。用户需要一个不依赖 Orca 手机端连接、直接从 Orca 插件工作进程向 ntfy（通知服务）发送会话状态通知的个人插件。

## 解决方案

新增一个使用官方 `orca-plugin.json`（插件清单）的 Orca 个人插件，订阅 `agent.status.changed`（代理状态变化事件），只处理 `blocked`（阻塞）、`waiting`（等待输入）和 `done`（完成）。插件以 `worktreeId + paneKey`（工作区和终端标识）作为状态去重键，仅在该键的状态变化时发送一次通知。

通知直接通过 Node（运行环境）的内置 `fetch` 使用 HTTPS POST（安全网页请求）发送到公共 `https://ntfy.sh`。主题使用安装者提供的随机主题，令牌使用专用 ntfy 令牌；令牌和主题从 Orca `secrets`（私密存储）读取，源码、清单和日志不得保存或输出令牌。

通知标题在无法取得 Agent（代理）类型时固定为 `orca agent`。当前 Orca 事件载荷没有 Agent 类型字段，因此不从终端标识猜测 `Codex Cloud` 等名称。通知正文只发送一句状态文案：

- `waiting`：`会话已完成，等待回复`
- `blocked`：`会话阻塞，等待处理`
- `done`：`会话已经彻底完成`

`blocked` 和 `waiting` 使用高优先级，`done` 使用普通优先级；每种状态使用对应标签。网络错误至少执行三次重试，间隔为 1 秒、5 秒、30 秒。重试全部失败后保留已记录的状态，避免同一状态事件重复通知。

## 用户故事

1. 作为 Orca 用户，我希望代理进入阻塞状态时收到手机通知，以便及时处理阻塞。
2. 作为 Orca 用户，我希望代理等待输入时收到手机通知，以便继续会话。
3. 作为 Orca 用户，我希望代理完成会话时收到手机通知，以便知道工作已结束。
4. 作为 Orca 用户，我希望相同工作区和终端的相同状态只通知一次，以免手机被重复消息打扰。
5. 作为 Orca 用户，我希望同一工作区和终端从一个已处理状态变为另一个受支持状态时再次收到通知。
6. 作为 Orca 用户，我希望通知正文只包含简短会话状态，不包含完整工作区路径、代理输出、分支名或凭据。
7. 作为 Orca 用户，我希望 ntfy 令牌只从 Orca 私密存储读取，以免令牌进入源码、清单或日志。
8. 作为 Orca 用户，我希望网络暂时失败时插件自动重试，以减少瞬时网络波动造成的通知丢失。
9. 作为插件维护者，我希望插件只依赖 Orca 官方插件能力和 Node 内置网络请求，以便保持个人插件的最小依赖面。
10. 作为插件维护者，我希望文档明确说明 `net:fetch`（网络请求权限）尚未正式存在，因此该实现只适合作为本机个人插件，不包装成通用市场插件。

## 实施决策

- 使用官方清单格式、`pluginApi: 1`、`events:subscribe` 和 `secrets` 能力；只声明实际使用的事件与私密存储能力。
- 使用 Orca 插件工作进程的默认导出作为最高公开测试接缝；事件处理、状态去重、文案映射和 ntfy 适配集中在该插件实现中。
- 只订阅 `agent.status.changed`，只接受三个精确状态；其他状态直接忽略且不发起网络请求。
- 去重键由 `worktreeId` 和 `paneKey` 组成。由于官方事件允许 `worktreeId` 为空，空值作为该键的明确值处理，不把完整路径作为替代键。
- 在发起网络请求前记录新状态，以避免并发重复事件造成重复通知；网络失败只触发本次发送的重试。
- 重试使用初次发送加三次重试，等待时间依次为 1 秒、5 秒、30 秒。可判定为配置或授权错误的响应不无限重试；所有失败都不得记录令牌或响应中的敏感内容。
- ntfy 服务地址固定为公共 `https://ntfy.sh`，不实现自建服务地址、服务切换或本地中继。
- 主题和令牌由用户在 Orca 私密存储中预置；插件不生成、写入或打印私密值。文档建议使用随机主题和专用令牌。
- 通知只使用固定标题、固定一句正文、优先级和状态标签；不把 `worktreeId`、`paneKey`、完整路径、代理输出或时间戳放入通知正文。
- 文档明确：Orca 只提供已接入状态钩子链的代理事件，未接入的终端不会产生状态；插件事件没有回放机制，插件重启期间发生的状态可能丢失。
- 文档明确：直接使用 Node 内置 `fetch` 是个人插件工作进程的可接受实现，但由于 Orca 当前没有正式 `net:fetch` 能力，不宣称为通用市场插件接口。

## 测试决策

- 清单测试验证 JSON（数据格式）可解析，声明 `pluginApi: 1`、主入口、目标事件以及 `events:subscribe`、`secrets` 能力，并不声明未实现的网络能力。
- 事件处理测试通过 Orca 工作进程入口注册真实事件回调，验证三个状态的文案、标题、优先级和标签映射；未知状态不发送。
- 去重测试验证相同 `worktreeId + paneKey + state` 不重复发送，状态变化会发送，两个不同键互不影响，空 `worktreeId` 仍能稳定去重。
- 私密存储测试验证令牌只通过 `secrets` 读取，缺少令牌时不发送，并且日志和错误信息不含令牌、完整路径或代理输出。
- 重试测试验证网络失败后的 1 秒、5 秒、30 秒顺序和最多三次重试，并验证最终失败不会因同一状态重复事件再次发送。
- 最小真实入口冒烟测试直接加载插件工作进程默认导出，模拟 Orca 事件和私密存储，并通过受控 HTTPS 请求接缝验证至少一条状态通知可以发出；不安装插件、不修改 Orca 配置、不向真实用户主题发送测试消息。
- 使用仓库现有验证入口和 Node 内置测试能力，不新增测试框架或运行时依赖。

## 范围外

- 不实现本地中继、后台守护进程、消息队列或持久化事件回放。
- 不修改 Orca 核心、`app.asar`（应用资源包）或 Orca 手机端。
- 不兼容自建 ntfy、其他通知服务、服务地址切换或 iOS（苹果手机系统）上游转发配置。
- 不保证未接入 Orca 状态钩子链的终端具有状态通知。
- 不把插件自动安装到 Orca 用户环境，不修改用户配置，不启动服务，不提交真实 ntfy 令牌或主题。
- 不发送完整工作区路径、分支、代理输出、原始事件对象或其他敏感信息。

## 补充说明

公共 ntfy 主题本质上可能被猜测或订阅，因此使用随机主题和专用令牌。公共 `ntfy.sh` 的手机推送由其服务端负责；本版本不覆盖自建 ntfy 的 iOS 上游推送转发配置。
