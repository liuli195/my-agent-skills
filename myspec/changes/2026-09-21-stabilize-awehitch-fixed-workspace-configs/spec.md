## Problem Statement

三个长期使用的仓库虽然都在各自主分支保存了 awehitch 项目级 Codex（代码代理）配置，但配置缺少 `--harness codex` 和三会话槽位值，导致 Codex 控制面与连接器重建共同使用 `default` 浏览器配置，并且第三个并发会话无法启动。现有补丁 4 只按表头判断项目配置是否存在，不能发现缺参数、错误工作区或不兼容字段；Skill（技能）又在正常任务入口无条件运行 `up`，扩大了连接器修复与现有会话并发发生的机会。授权选择器覆盖和观测日志目前还只是本机状态或未完成草稿，升级后不可审查、不可可靠重放。

## Solution

保留三个仓库各自固定的项目级 Codex 配置，不恢复用户级 awehitch 活动指针。三份配置固定各自工作区，加入 `--harness codex`，并直接把最大并发槽位 `3` 写入项目配置环境，避免新增 Windows 用户环境状态。现有补丁脚本继续作为唯一补丁入口：强化补丁 4 的语义检查；把 Skill 改为状态优先、仅按需运行 `up`；安全托管授权按钮选择器覆盖；选择性移植不泄露敏感信息的授权阶段日志。源码、隔离测试和审查完成后，分别通过三个仓库的 PR（拉取请求）交付配置，再执行一次本机部署和真实三工作区验收。

## User Stories

1. 作为三个仓库的使用者，我希望进入任一仓库即可直接启动 Codex，而无需为了切换工作区运行 `up`。
2. 作为并发使用者，我希望三个 Codex 会话可以同时使用各自独立的浏览器配置档。
3. 作为连接器维护者，我希望连接器重建继续使用 `default` 配置档，不与存活的 Codex 会话争用同一浏览器锁。
4. 作为配置维护者，我希望 `doctor` 能发现错误工作区、缺少 harness、缺少槽位值和不兼容字段，而不是只看表头。
5. 作为升级维护者，我希望 `up` 不会向用户级 Codex 配置写入 awehitch 条目。
6. 作为日常使用者，我希望正常任务先检查全机服务状态，服务健康时不重复运行 `up`。
7. 作为故障排查者，我希望授权失败日志能指出选择器加载、连接点击、登录按钮、授权页和最终授权验证分别停在哪一步。
8. 作为安全维护者，我希望授权日志不记录配对码、令牌、页面内容或带参数地址。
9. 作为本机配置维护者，我希望授权选择器缺失时可以恢复，相同时保持不动，出现人工差异或损坏文件时停止而不是覆盖。
10. 作为仓库维护者，我希望所有本地补丁均通过一个幂等脚本安装，并能在干净 0.3.2 上隔离验证。
11. 作为发布维护者，我希望三个仓库的配置修改分别从各自主分支通过 PR 交付，不混入其他功能分支。
12. 作为使用者，我希望全机服务只需在重启或明确故障后启动一次，之后三个仓库均可直接使用。

## Implementation Decisions

- 项目级 Codex 配置是工作区绑定的运行时 Seam（接缝）；三份配置只在工作区路径上不同。
- 每份配置同时包含 `--harness codex`、`AWEHITCH_CONTROL_PLANE=1` 和 `AWEHITCH_MAX_PARALLEL_SESSIONS=3`。槽位值直接受版本控制，不新增 Windows 用户环境变量。
- 用户级 Codex 配置保持没有 awehitch 条目；补丁 4 继续禁止官方适配器写入该条目。
- 补丁 4 的状态 Interface（接口）验证完整语义，不再仅验证表头存在。
- 本地补丁脚本保持唯一补丁 Module（模块），不新增第二套安装脚本。
- Skill 的正常入口先读取全机状态；仅在服务未运行、工作区未登记或只读诊断明确要求时运行 `up` 或连接器修复。
- 授权选择器托管只拥有 `connector.signInButton`；保留所有其他字段。人工差异和损坏 JSON（数据文件）均停止并报告。
- 授权日志只记录阶段、候选数量、是否可见、是否成功和错误类型；不记录原始错误文本、页面内容、令牌、配对码或带参数地址。
- 未完成 stash（暂存）只作为参考，选择性移植；不得整体应用或删除。
- 不直接编辑全局安装包；本机部署只能运行通过验证的补丁脚本。

## Testing Decisions

- 最高公开接缝一：在三个仓库分别运行真实 `codex mcp get awehitch --json`，观察各自工作区、harness 和三槽环境值。
- 最高公开接缝二：在隔离的用户目录和应用状态目录运行补丁脚本两次，观察首次安装、重复幂等、用户级配置不变、选择器合并和漂移保护。
- 最高公开接缝三：运行 `awehitch doctor -w <仓库> --no-fix --json`，观察项目配置是否被语义识别。
- Skill 渲染测试观察正常快速问答和开发流程不再无条件执行 `up`。
- 授权观测测试检查所需阶段均存在，并对禁止记录的敏感字段做负向断言。
- 最终真实入口验证：全机只启动一次，三个仓库不再运行 `up` 分别发消息，三个会话领取 `codex`、`codex-s1`、`codex-s2`，存活会话期间连接器重建使用 `default`。
- 测试优先在公开 Interface 上断言；只有错误工作区、缺 harness、缺槽位值等负例允许直接调用适配器状态 Interface。

## Out of Scope

- 不恢复单份用户级 awehitch 活动工作区配置。
- 不修改 awehitch 上游仓库源码或等待上游 Issue #7 修复后才交付本地方案。
- 不修改三个仓库除 `.codex/config.toml` 外的业务文件。
- 不自动删除连接器、令牌、隧道或存活会话。
- 不新增槽位查看或单槽位释放命令。
- 不整体应用或删除现有 stash。
