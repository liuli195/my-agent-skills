# 共享工作树依赖

## 背景

新建 Git worktree（工作树）不会包含被 Git（版本管理）忽略的 Node.js（运行时）依赖。当前 `plugins/pi-tool-display/node_modules` 约占 409 MB，独立工作树既无法直接构建，也不应重复安装或通过临时链接增加清理风险。

本变更落实 GitHub Issue（问题）#230，并采用仓库级共享依赖：大型依赖实体只保留在主仓库根目录，各工作树通过目录链接使用同一依赖。

## 用户结果

开发者在主仓库根目录完成一次 Node.js（运行时）依赖安装后，可以初始化 `.worktrees/` 中的任意工作树并直接运行 Build and Verify（构建与验证），无需再次下载或复制大型依赖。

## 需求

1. 仓库根目录是唯一 npm workspace（npm 工作区）和 Node.js（运行时）开发依赖根。
2. 根目录保存唯一 `package-lock.json` 和 `node_modules`；`plugins/pi-tool-display` 不再拥有独立锁文件或独立大型依赖目录。
3. 现有插件继续保留各自的 `package.json`、包边界和构建命令。
4. `scripts/setup-worktree.ps1` 在主仓库根目录运行时准备根目录依赖。
5. 该脚本在链接工作树内运行时，只把工作树根级 `node_modules` 链接到主仓库根目录的 `node_modules`。
6. 共享依赖不存在时，工作树初始化必须停止，并提示先在主仓库根目录初始化；不得跨工作树修改主仓库依赖。
7. 工作树与主仓库的依赖清单不一致时必须停止，不得静默复用或修改共享依赖。
8. Build and Verify（构建与验证）仍只负责构建和验证，不负责安装依赖。
9. `.worktrees/` 名称和位置保持不变。

## 验证边界

- 从公开入口 `scripts/setup-worktree.ps1` 验证主仓库初始化、工作树链接、缺失依赖停止和清单不一致停止。
- 从 Build and Verify（构建与验证）入口验证通过共享链接完成真实构建主流程。
- 先保留因目标行为缺失而失败的检查，再实现使同一检查通过。

## 非目标

- 不新增 Python（脚本语言）虚拟环境。
- 不引入新的依赖管理工具。
- 不让工作树自动更新主仓库共享依赖。
- 不修改 `.worktrees/` 的名称。
