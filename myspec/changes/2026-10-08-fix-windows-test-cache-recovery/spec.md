# 修复本机测试缓存失败恢复

**Status:** ready-for-human

## Problem Statement

本机验证遇到未完成的测试模板时，需要删除旧目录并重新准备。模板中的 Git（版本管理）对象可以正常带只读属性；目前的删除过程未处理这种情况，在 Windows（操作系统）上报拒绝访问，阻断发布流程和拉取请求流程的测试。

构建与验证的测试安装模板在打包前就登记为可复用缓存。打包或安装失败后，后续测试仍会引用未生成的安装目录，产生缺路径错误，掩盖首次失败原因。

## Solution

让测试模板的删除和重新准备能够处理只读文件，同时继续如实报告其他失败。仅在测试工具完成打包、安装且必要文件存在后，才允许后续测试复用安装模板；准备失败后的下一次调用应重新准备。

## User Stories

1. 作为运行本机验证的维护者，我希望未完成模板中的只读版本对象能够被安全清理，以便恢复测试准备。
2. 作为维护者，我希望复制模板前清理旧目标时使用同样的处理，以免相同问题在另一个调用位置出现。
3. 作为维护者，我希望非只读删除失败继续报告原错误，以免验证掩盖真实环境问题。
4. 作为维护者，我希望打包或安装失败后不会留下可复用的无效缓存，以便后续调用重新准备而不是报告连锁缺路径错误。
5. 作为维护者，我希望缺少压缩包、命令入口或已安装包清单的模板不被复用，以便缓存代表完整可用的测试安装。
6. 作为维护者，我希望成功准备的安装模板仍可复用，以免增加重复打包安装成本。
7. 作为维护者，我希望验证继续覆盖真实用户入口，并保留既有失败报告、预算和打包路径限制。

## Implementation Decisions

- 在现有共享测试模板辅助文件中集中目录删除处理，供复制模板、发布流程测试模板重建和拉取请求流程测试模板重建复用；不新增独立模块或框架。
- 仅当 Windows（操作系统）删除文件失败、错误为权限错误且该文件明确带只读属性时，清除该文件的只读属性并重试原删除操作。其他错误及重试失败继续抛出；不修改访问控制规则，不忽略错误，不扩大清理目标。
- 安装模板先保存在本次调用的局部对象中。打包与安装均成功，且压缩包、命令入口和已安装工具包清单存在后，再登记为共享缓存。
- 准备失败不得发布候选缓存；下一次调用重新准备。已有成功缓存的复用方式保持不变。
- 两项修复各自可以观察和验证，无前置依赖；为避免同一工作树中的验证与提交相互影响，推荐串行实施。
- 沿用现有领域术语，无需新建词汇表或架构决策文档。主规格仅在后续规格与交付门禁确认后更新。

## Testing Decisions

- 目标产品入口是已安装的 Build and Verify（构建与验证）命令；红灯、绿灯及最终冒烟均从其公开验证入口执行选中的仓库检查。
- 优先扩展现有不完整模板恢复测试，并为发布流程对应恢复路径补最小覆盖。使用测试自有目录中的只读文件，验证旧模板删除、重新准备和后续可用结果。
- 检查非只读权限错误及重试仍失败的路径保留失败，不使用权限规则修改或错误忽略来获得通过。
- 使用现有安装模板函数的进程内测试接缝，以受控打包与安装结果覆盖首次失败、缺少必要文件、再次准备成功和成功缓存复用；不增加重复真实打包安装测试。
- 保留现有真实打包、隔离安装及公开命令入口覆盖。正式验收使用固定基线的快速验证，要求实际检查非空且结果通过；保持仓库既有 60 秒预算。
- 验证沿用已明确批准的既有系统临时目录、测试目录保留清理与软件包缓存机制；不新建总目录，不重定向临时目录，不主动清空缓存。日志留在仓库内，既有测试机制按原行为维护其产物。

## Out of Scope

- 已交付的子代理模型调整及再次热修复推送。
- 产品发布、拉取请求或验证工具的业务行为、配置、调度和预算。
- 打包输出不得位于仓库内的保护规则。
- 安装依赖、更新插件缓存、更改用户配置或访问控制规则。
- 调查缺乏历史证据的首次模板中断起因，以及新增复杂缓存协调机制。
