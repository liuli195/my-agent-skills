# 01 — 修复 MySpec 多工作树源码绑定

**关联问题：** #283

**What to build（构建内容）：** 让开发模式的裸 `myspec` CLI（命令行程序）在源码工作树与目标规格工作树不一致时安全阻断规格写入，并为多工作树开发者提供可验证的手工切换路径。

**Blocked by（前置项）：** None — can start immediately（无，可立即开始）

**Status（状态）：** ready-for-agent

- [ ] `doctor` 报告实际源码工作树、源码提交、目标工作树、目标提交和匹配结果。
- [ ] 源码工作树与目标规格工作树不一致时，`apply-delta` 在任何预览、备份或主规格替换前返回稳定错误，且目标文件字节不变。
- [ ] 通过 `myspec init --dev --source <目标工作树>` 重新绑定后，目标工作树的预览、原子应用和重复应用成功。
- [ ] 回归测试通过真实裸 CLI 覆盖两个隔离工作树，并覆盖混合 `LF`/`CRLF` 规格库的非目标文件字节保持。
- [ ] 公共 MySpec 技能文档说明绑定切换、诊断检查和开发模式串行应用限制。
- [ ] 正式变更规格与实现行为一致，未扩大到自动动态绑定或并行开发运行时。
