# 02 — 补齐安全决策与失败恢复

**What to build:** 当 `/spec-add` 遇到冲突、删除或低可信候选，用户可以逐条作出决定；运行被中断后能够安全继续，主规格在外部变化或应用失败时不会被旧结果覆盖或损坏。

**Blocked by:** 01 — 完成 `/spec-add` 基础闭环。

**Status:** ready-for-agent

- [ ] 冲突、删除和低可信候选每次只展示一条，并同时展示证据、原因和推荐答案。
- [ ] 禁止批量采用建议，存在未决冲突时不得进入应用阶段。
- [ ] 当前决定和冲突游标可在中断后继续使用，但不会形成主规格之外的长期事实源。
- [ ] 同一仓库同时只允许一个写入运行，遗留锁不会仅因超时而自动删除。
- [ ] 继续运行前检查主规格指纹；主规格变化后旧 Delta（增量规格）和预览必须重新生成。
- [ ] 应用失败或最终校验失败时完整恢复原主规格，不触碰规格目录之外的内容。
- [ ] 端到端回归覆盖逐条决策、中断恢复、外部变化拒绝和应用失败回滚。
