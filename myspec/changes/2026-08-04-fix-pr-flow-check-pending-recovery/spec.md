# PR Flow 检查等待与规则集恢复

## Problem Statement

用户在提交刚推送、GitHub 检查仍在运行时执行 PR Flow `complete`（收尾）。流程可能把“检查等待”报告为检查或审查阻塞，不能在同一次命令中等待检查完成；即使流程停止，终端也没有直接展示等待和重试动作。检查刚完成但合并规则集尚未刷新时，流程还可能把暂时性门禁延迟误解为真实规则集问题。

## Solution

让 PR Flow 按检查的可观察状态而不是命令退出码判断恢复路径：检查等待进入现有有界等待；检查失败或取消进入修复路径；合并策略拒绝时先复核检查并进行一次有界刷新重试，仍然阻塞才报告真实规则集阻塞。所有可恢复停止状态都在终端直接给出下一步动作和可复制的重试命令。

## User Stories

1. 作为运行 `complete` 的维护者，我希望检查仍在运行时流程继续等待，而不是被误报为检查或审查阻塞，以便一次命令能够完成正常合并。
2. 作为等待超时的维护者，我希望看到明确的“等待检查完成后重试”说明和命令，以便无需自行推断恢复步骤。
3. 作为遇到失败或取消检查的维护者，我希望流程直接说明需要修复或重新触发检查，而不是无限等待或尝试合并。
4. 作为遇到合并策略拒绝的维护者，我希望流程先区分检查等待、检查失败和真实规则集阻塞，以便停止状态对应真实原因。
5. 作为遇到检查刚完成的维护者，我希望流程在合并状态传播的短暂窗口内进行一次有界刷新和重试，以便避免机械地重新运行整个命令。
6. 作为遇到真实规则集阻塞的维护者，我希望流程保留 `ruleset_merge_blocking`（规则集阻塞合并）和原始平台错误，以便继续处理权限、审核或规则配置。
7. 作为运行 `diagnose`（诊断）的维护者，我希望检查等待和检查阻塞使用与 `complete` 一致的恢复说明，以便两个入口不会给出相互矛盾的建议。
8. 作为仓库维护者，我希望现有提交复核、匹配头提交和安全停止行为保持不变，以便修复不会扩大合并风险。
9. 作为仓库维护者，我不希望流程通过空提交、管理员绕过或无限重试来恢复检查，以便保留可审计的人工控制边界。

## Implementation Decisions

- 复用现有的检查读取模块作为外部 GitHub CLI（命令行工具）适配器和测试接缝。该接口先验证可读的检查数据，再解释命令退出状态；“检查等待”由检查数据决定，不由单独的退出码决定。
- 只把平台明确表示“检查等待”且同时提供有效检查数据的结果纳入等待路径。无效数据、无法读取数据和不明错误继续失败关闭；空的必需检查结果不得被当作通过。
- `complete` 和 `diagnose` 继续使用现有停止状态名称；本次只补齐状态分类、恢复动作和终端可见性，不新增后台任务、长期状态机或配置字段。
- 规则集拒绝后的恢复最多进行一次有界刷新和合并重试；每次重试前继续复核源提交和目标提交，仍被拒绝时保留 `ruleset_merge_blocking`。
- 保留现有 `--match-head-commit`（匹配头提交）和 GitHub CLI 明确建议 `--auto`（自动合并）时的既有处理；本变更不新增自动合并、管理员绕过或空提交恢复。
- 终端输出与停止状态详情使用同一恢复动作，至少覆盖等待检查、修复失败/取消检查和处理真实规则集阻塞三类场景。

## Testing Decisions

- 最高测试接缝是 `complete` 和 `diagnose` 的公开命令入口；测试通过现有 GitHub CLI 命令替身提供返回码、结构化检查数据和合并结果，并断言终端输出及持久化停止状态。
- 最小回归场景必须模拟：待处理检查的特殊退出状态、等待后通过、检查失败、检查取消、规则集刷新竞争、真正持续的规则集阻塞。
- 现有检查读取函数的单元测试只作为解析边界补充，不能替代完整生命周期测试。
- 实施后使用 Build and Verify（构建与验证）快速验证，并从真实 PR 用户入口执行一次“提交后立即运行 complete”的冒烟；真实规则集阻塞只验证停止状态，不修改远端规则。

## Out of Scope

- 不修改 GitHub Rulesets（规则集）、分支保护、CodeQL（代码扫描）或仓库权限配置。
- 不自动创建空提交、不自动重跑无法由 GitHub CLI 直接重跑的动态 CodeQL 检查。
- 不引入 GitHub SDK、后台守护进程、并发等待器或新的配置项。
- 不重构 PR Flow 的工作树隔离、清理、热修复或发布流程。
- 不把所有平台策略拒绝都改写为检查等待。

## Further Notes

本变更修正 Issue #107 的近期复现路径，并澄清既有规则集恢复设计中对平台退出状态和终端恢复提示的遗漏。实现完成后，需求规格、票据和行为证据应与该变更一起保留，便于后续 PR Flow 复现和回归。
