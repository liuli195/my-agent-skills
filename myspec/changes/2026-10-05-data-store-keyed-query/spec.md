# 数据存储逻辑键点读

Status: completed

## Problem Statement

调用者已经知道写入记录键，却只能通过全部逻辑分片的通用查询取回记录。在真实嵌套模拟报告中，单键查询执行约 39 秒，无法作为反复使用结果的读取入口。

## Solution

在现有最小数据存储技能中提供逻辑表与写入键的点读接口，只打开对应已完成分片；保留原有通用只读查询、类型、内部 Zstd 和同键原子替换契约。调用者不需要物理路径。

## User Stories

1. 作为调用者，我希望用写入时的表和键读回记录组，不扫描无关历史文件。
2. 作为分析使用者，我希望原有稳定逻辑表、参数查询和游标分批读取不受影响。
3. 作为调用者，我希望区分目标缺失、明确内容损坏和存储执行故障，避免把暂时故障当作数据无效。
4. 作为技能使用者，我希望安装后的最小运行目录即可使用接口，不依赖开发仓库路径或新增服务。

## Implementation Decisions

- 复用现有逻辑名称校验、大小写规则和每键完整分片，不新增键体系或索引数据库。
- 推荐最小 Interface 为 read_key(root, table, key)，返回原生可分批消费的结果；不改写调用方 SQL，不让业务拼物理文件路径。
- 通用 query 保持原来多表与完整逻辑表语义；点读只处理目标分片，无关损坏分片不应阻塞它。
- 保留可查询的嵌套类型、同键原子替换和资源关闭。已明确识别的目标缺失或格式损坏与权限、锁、磁盘、依赖等执行故障分开；不依据宽泛 RuntimeError 将所有故障归为内容损坏。
- 不增加常驻连接服务、自动恢复平台、额外依赖、历史迁移、DuckLake 正式后端或完整报告副本。

## Testing Decisions

- 从独立安装形态的技能入口调用 write 与点读，复用现有公开测试接缝和已覆盖的名称、类型、替换与关闭规则。
- 只增加目标点读隔离和缺失/损坏/执行失败区别等必要小样本，不另建庞大测试矩阵；测试仍放仓库统一测试目录。
- 在消费仓库的真实数据对照验证性能，不把特定机器秒数硬编码进便携单元测试。

## Out of Scope

数据治理、保留期、清理、备份、恢复服务、全部文件合并、schema 平台、并行同键协调、生产后端迁移和市场发布。

## 2026-10-06 补充：目标键批量读取与指定字段

### Problem Statement

相同十二份真实报告的对照中，文件方案逐键建立连接，指定字段仍先读取完整报告；原生数据库则一次查询全部目标且只取指定字段。此差异不能作为选择存储后端的充分依据。

### Solution

保留文件存储，提供按多个已知逻辑键一次连接读取的能力，并允许只读取指定顶层字段。先消除读取方式不一致的开销，再按相同条件比较；不承诺文件和数据库完全等速。

### User Stories

1. 调用者可一次读取多份已知报告，不反复建立连接，不枚举无关历史文件。
2. 调用者可直接读取所需字段，不先取回整份嵌套报告。
3. 现有单键完整读取和通用查询继续可用，原数据及类型不变。
4. 目标缺失、明确损坏和暂时读取失败仍分别报告，不静默跳过目标。
5. 使用者能看到同样数据、字段和计时范围下的原始结果，再决定是否迁移。

### Implementation Decisions

- 新增最小批量逻辑键入口，复用单键名称规则、目标文件检查、只读连接限制和分批消费；旧单键调用保留兼容。
- 指定字段仅接受顶层字段名，不接受任意表达式或物理路径。未指定字段时返回完整记录。
- 批量仅打开明确指定的目标文件；一次建立连接，一次执行读取。不增加常驻连接、额外依赖、后台服务或持久数据库。
- 重复逻辑键不重复读取；跨键记录顺序不作保证，调用者按业务身份核对。跨键写入事务和并发写入协调仍不在范围内。
- 空键列表、空字段列表、重复字段（含仅大小写不同）和非法名称明确拒绝；未知字段明确报错。正常和异常路径均须释放资源。

### Testing Decisions

- 原始十二份真实报告保持只读；A 和 C 对完整报告及相同三个顶层字段各至少测三次，轮换测量顺序，包含初始化、目标检查、执行、获取、核对与关闭的总耗时。
- 逐项核对记录身份、完整嵌套值、字段值和类型；不以单纯行数作为一致性证明。不将机器耗时阈值硬编码进便携测试。
- 保留原始测试结果，新增补测记录；不覆盖旧测量。单条完整读取仍补测以检查是否退步。

## 2026-10-06 实测后的综合优化

### Solution

批量键和字段入口与通用查询一起优化。通用查询减少重复绑定文件的准备开销；仅对小规模复杂字段读取内部减少工作线程，其余读取保留当前引擎默认。调用者不需要提供调优参数。

### Implementation Decisions

- 通用查询仍注册、检查全部合法逻辑表；无关表损坏仍报告错误。不可按业务查询条件、文件名或固定业务表缩减通用表内容。
- 使用查询引擎原生临时逻辑视图，保持多表、参数、异构字段合并、嵌套字段、只读及逐批消费契约。
- 从读取计划与源字段类型判断小规模复杂读取；准备仍使用默认线程，识别可靠时执行采用一个线程，其余及未知计划保留引擎实际默认，不写死本机默认值。
- 只保留最多128条配置选择。身份包含数据根、查询、参数和文件变更信息；每次重新建连接、登记表、检查文件和读取数据，不保存完整报告或常驻连接。同键覆盖、新增或删除文件后重新判定。
- 不更改写入、原始数据、业务搜索算法；不采用全历史加载、关闭异构字段合并、通用查询跳过无关表、永久数据库或调用者传线程参数。
- 顶层字段名与嵌套访问要区分；名称重合、无法可靠识别来源时保持默认，不能错误解释为固定业务模型。

### Testing Decisions

- 独立复制技能运行目录后，从公开命令行验证多键与字段；公开编程入口验证游标、各类错误、同键覆盖和通用参数、多表、嵌套、特殊字段名。
- 原有十三种读取方式全部复测；原始文件、参数、结果值与类型、计时范围一致；新实现首次与重复调用分别记录，至少三轮轮换顺序。
- 写入契约回归、全部逻辑表检查、已知键目标隔离、无持久数据库及数据新鲜性必须通过。不以秒数或私有函数作为便携功能测试的断言。
