# Data Store（数据存储）最小技能

## Problem Statement

调用方需要统一保存、写入和查询结构化结果，不再散落物理文件路径，也不需要一套数据治理平台。旧数据工具已经移除；此变更从干净主干开始，不复活其能力或历史格式。

## Solution

在 my-agent-skills（个人技能仓库）新增一个独立 Data Store（数据存储）插件、一个同名技能。只提供写入和只读查询两个公开操作，以 Parquet（列式文件）内部 Zstd（压缩算法）作为唯一持久数据，以 DuckDB（分析查询引擎）内存视图提供稳定逻辑表名。

## User Stories

1. 作为调用者，我希望按逻辑表名写入有类型的记录，使物理文件布局由技能处理。
2. 作为调用者，我希望用同一根目录和逻辑表名查询，使后续物理存储调整不改变查询契约。
3. 作为使用者，我希望安装后的技能独立运行，不依赖原源码仓库位置。
4. 作为使用者，我希望只引入必要的 DuckDB 依赖，不安装额外数据框架。
5. 作为调用者，我希望未完成写入不替代已有完整数据，错误清晰返回。

## Implementation Decisions

- 范围严格为存储、写入、查询；只有一个实际存储实现，不增加后端接口层、服务、常驻进程或调度。
- 公开接口为 write(root, table, key, rows) 和 query(root, sql, parameters)。root（数据根目录）由调用方在项目级集中配置一次，同一项目的全部运行共用，不从单次任务输出目录派生；table（逻辑表名）和 key（记录分片键）是逻辑身份，不是任意路径。write 写入或替换同一键的完整记录组；query 只读，返回支持 DuckDB 原生 fetchmany（分批获取）的结果游标，调用方可限定每批行数，不强制一次加载完整结果列表。
- 每个数据集的逻辑表名、字段及类型由调用方定义；通用技能不硬编码 Sim2GSE 的表名或业务模型。记录保留数值、文本、布尔、空值及适用的 LIST/STRUCT（列表/结构体）类型。完整业务结果不得伪装成单个不透明 JSON（数据交换格式）文本或二进制字段。原本就是文本的输入与导出可用文本列保存。
- 每次只处理已经生成的一组记录；使用 DuckDB 原生 Parquet 写入和 Zstd 压缩、临时文件及原子替换。失败时既有完整分片保持可读；不增加归档、恢复或扫描治理流程。
- 查询使用内存连接和 read_parquet（读取列式文件）视图，物理路径只在技能内部解析；不生成持久 DuckDB 数据库或第二套结果副本。
- 单个技能目录包含说明、运行脚本与必要依赖声明；插件保留 Codex/Claude（代理客户端）必需清单，源码仓库测试和开发临时产物不随技能分发。两客户端现有市场和投影登记只增加此插件，不进行整市场发布。
- DuckDB 是唯一新增直接运行依赖；确认开发后在隔离云端测试环境准备并锁定实际验证版本。无自动安装器，不自动修改用户环境，不引入 PyArrow/Pandas（数据处理库）依赖。
- 参考 Quant-Research-Lab（量化研究仓库）已核实的临时写入、Zstd、原子发布和内存视图小段实现；不复制金融领域契约、清单栈或全套依赖。

## Testing Decisions

- 最高公开测试接缝为独立复制后的技能命令入口：写入有类型的小样本，再通过同一发布形态按逻辑表查询；来源仓库不可访问时仍成功。
- 一条纵向票据同时完成最小写入、查询、包装和验证。覆盖调用方自定义数据集字段与类型、Zstd、数值/列表/结构体查询、原生游标分批消费、同键替换、失败不损坏旧数据、非法身份拒绝、只读查询和缺依赖提示；不添加训练框架。
- 所有测试进入仓库统一测试与 build-and-verify（构建与验证）；真实子进程冒烟遵循仓库现有逐测试白名单，不新建验证入口。
- 云端先红后绿并运行固定基线快速验证；完整远端检查遵循现有交付流程。

## Out of Scope

预览、备份、归档/恢复、解压恢复、迁移、保留期、定时清理、容量治理、租约、写后哈希回验、版本平台、额外诊断；npm（软件包管理器）包装和整市场升级发布；修改其他插件；自动部署至用户环境。新增能力须先获用户明确批准。
