# 03 强制子代理运行在目标工作树

- 状态：ready-for-agent
- 关联问题：#246
- 前置票据：无

## 用户结果

当主 Agent（代理）选择委派可写票据时，Implementer（实施者）的真实工作目录由工具强制绑定到指定已有工作树；无法证明工作树和分支时，子代理不会启动，主工作区不会因提示式目录切换失败而被写入。

## 实现范围

- 先诊断并解决真实测试中子代理返回完成结果后外层 Pi（编码代理）进程未退出的问题。
- 提供最小 Pi Extension（Pi 扩展）包装入口，复用 `subagents:rpc:spawn`（子代理跨扩展调用）而不实现新的子代理运行器。
- 通过 `options.cwd`（工作目录选项）传入目标工作树的规范绝对路径，并使用现有 Implementer 角色配置。
- 以 isolated（隔离）模式启动子代理，只保留内置工具，避免子会话扩展或 MCP（模型上下文协议）资源阻止外层 Pi 进程退出。
- 派发前确认目标路径是当前仓库登记的已有 Git worktree（Git 工作树），并确认当前分支等于调用方声明的预期分支。
- RPC（跨扩展调用）不可用、工作树不唯一、分支不匹配或无法强制工作目录时，在派发前失败并给出交接方法。
- 不依赖提示中的 `cd`（切换目录），不自动创建工作树，也不以 Orca（代理开发环境）作为后备路径。

## 验收标准

- [x] 子代理报告的真实工作目录和分支与目标已有工作树一致。
- [x] 子代理的编辑、目标检查、缓存和已知运行产物只落在目标工作树。
- [x] 主工作区的 Git 可见内容及预先记录的已知副作用目录在派发前后保持不变。
- [x] 非工作树路径、歧义工作树和分支不匹配在子代理启动前失败。
- [x] 无法使用 RPC 强制目标目录时，流程停止并提供从目标工作树交接 Pi 会话的方法。
- [x] 子代理完成并返回结果后，外层 Pi 进程在限定时间内退出且没有属于本次测试的残留进程。
- [x] 顺序票据可复用同一个已有功能工作树；包装入口不会额外创建工作树。
- [x] Build and Verify（构建与验证）对应检查通过。

## TDD（测试驱动开发）证据

- [x] 红灯：包加载和工作树派发检查因包装扩展不存在而失败。
- [x] 绿灯：同一检查验证准确工作树和分支派发成功，并在错误分支和主工作树输入时失败。

## 验证证据

- [x] 真实 Pi 新进程通过 RPC 在已有 `feature` 工作树启动 Implementer，目标文件只出现在目标工作树，主工作区保持干净。
- [x] 非隔离子会话在完成后未退出；差分测试确认仅启用 isolated（隔离）子代理后，同一路径在 20 秒内以退出码 0 结束且无残留进程。
- [x] Build and Verify 快速验证通过。
