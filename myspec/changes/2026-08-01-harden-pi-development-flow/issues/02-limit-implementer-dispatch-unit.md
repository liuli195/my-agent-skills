# 02 约束 Implementer（实施者）委派单位

- 状态：ready-for-agent
- 关联问题：#245
- 前置票据：无

## 用户结果

主 Agent（代理）可以在功能工作树中逐票直接实施顺序任务，也可以选择委派；只有选择委派时才要求一次 Implementer（实施者）调用只绑定一张已发布票据，禁止通过一次调用合并多张独立票据。

## 实现范围

- 在实际实施和派发位置定义“主 Agent 可直接实施，委派时一票一次调用”的边界。
- 直接实施和委派都必须逐票完成实现、检查和验收，再进入下一张顺序票据。
- 一次 Implementer 调用只能引用一张已发布实施票据及其直接上下文。
- 派发前发现提示包含多张独立实施票据时拒绝派发。
- 无法独立实施或验证的票据返回 `to-tickets`（拆分票据）重新设计，不在派发时临时合并。
- 允许全部直接实施、全部委派或混合实施；是否委派由主 Agent 按 `pi-subagent-policy`（Pi 子代理策略）决定。

## 验收标准

- [x] 三张顺序票据全部由主 Agent 直接实施时允许零次子代理调用，并保留三个独立验收节点。
- [x] 三张顺序票据全部委派时产生三次独立 Implementer 调用和三个验收节点。
- [x] 混合实施时只为被委派票据产生调用，且该调用只绑定对应票据。
- [x] 一次调用同时包含多张独立票据时，流程在派发前拒绝。
- [x] 上一张顺序票据未验收时，不直接实施或派发下一张。
- [x] Build and Verify（构建与验证）对应检查通过。
