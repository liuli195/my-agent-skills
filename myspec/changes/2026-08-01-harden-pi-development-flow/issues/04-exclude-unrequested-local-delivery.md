# 04 默认排除未请求的本地交付和发布

- 状态：ready-for-agent
- 关联问题：#248
- 前置票据：无

## 用户结果

Development Flow（开发流程）默认在 PR（拉取请求）交付、目标分支同步和安全清理完成后结束；没有明确请求时，不询问、不列出也不执行本地安装、客户端同步、市场刷新或 Release Flow（发布流程）。

## 实现范围

- 从默认流程和完成条件中排除所有未请求的本地安装、客户端同步、市场刷新和发布操作。
- 不主动展示这些动作供用户选择，也不把它们记录为默认后续任务。
- 只有用户明确提出具体目标和动作时才执行并验证该项，不扩大到其他客户端或发布。
- 把“继续收尾”“完成剩余流程”等一般表达限定为恢复当前已经授权的步骤。
- 明确市场内容尚未发布时，不得自动进入发布，也不得阻塞已经完成的 Development Flow。
- 同步修正正式 MySpec（自有规格）中本地交付默认属于完成条件的含义。

## 验收标准

- [x] 用户未提出本地动作时，流程不询问、不列出也不执行安装、同步、市场刷新或发布。
- [x] 用户明确请求某一个具体动作时，只执行并验证该动作。
- [x] “继续收尾”不产生新的本地安装、客户端同步或发布授权。
- [x] PR 已合并、主干已同步且安全清理完成时，Codex/Claude（代码代理）市场仍为旧版本不会阻塞开发完成。
- [x] 明确请求的客户端同步依赖未授权发布时，流程不自动发布，并将该请求与开发流程完成状态分开报告。
- [ ] 正式 MySpec 的完成场景与新的默认排除边界一致。
- [x] Build and Verify（构建与验证）对应检查通过。
