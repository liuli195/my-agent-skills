# 统一云端开发环境初始化

状态：ready-for-agent

## Problem Statement
三个仓库的云端工具和技能安装缺少统一可重建入口，旧安装有重复来源与失效链接，Windows 初始化不能直接供 Linux 使用。

## Solution
技能仓库承载一个公共初始化和更新入口，复用三个项目已有准备流程；安装已发布工具与顶层技能，记录解析版本并复用；完成授权范围内的旧环境迁移与去重。

## User Stories
1. 用户可以从仓库配置恢复云端环境，而不依赖某一台机器永久存在。
2. 用户可以初始化任一已支持仓库，并复用相同版本的公共工具。
3. 用户可以修改声明版本后同步环境，而不自动升级未指定依赖。
4. 用户可以显式升级指定工具或技能到最新正式发布版。
5. data-store 尚未发布不阻塞基础初始化，发布后可通过同一更新入口补装。
6. Git 原生工作区创建后显式调用同一初始化入口，不复制整套虚拟环境。
7. 迁移后每项技能只有一个有效安装来源，保留无关平台技能及用户配置。

## Implementation Decisions
- Module（模块）：公共环境准备入口；Interface（接口）：初始化、update（同步声明）、update --latest（显式升级纳管发布项），确切参数在实现中保持简洁。
- Seam（接缝）：公开初始化和更新命令入口；Adapter（适配）：复用的项目准备脚本与官方安装命令。
- 公共工具与项目虚拟环境分开；共享环境必须先验证声明一致，不从链接工作树修改主环境。
- 最新正式发布版首次解析后记录，普通重跑不得隐式追新。项目锁文件不被更新入口擅自修改。
- 仅修补实际影响更新的嵌套依赖输入识别和旧下载缓存失效问题。运行时版本变化不能冒充普通包同步成功。
- 沿用仓库领域词汇与正式规格更新流程。此文件是变更需求，不直接改正式规格。
- 外部创建/删除路径须列明并获批；MCP 不属于本轮。

## Testing Decisions
- 最高公开入口：统一命令行入口，以及 Git 工作区创建后的显式调用。
- 最小检查覆盖首次准备、重复复用、声明版本变化、显式升级、未发布可选技能、安装失败退出。
- 测试逻辑使用最小内存替身，实际安装在获批云端位置做一次入口冒烟；不把下载或大规模安装加入每次仓库验证。
- Windows 只验证确实依赖本机的适配，按现有本机快验预算；CI 不继承本机总预算。
- Linux 与 Windows 平台结果分开记录，不声称已接入 Codex 自动触发。

## Out of Scope
MCP 安装与连接；自动升级所有项目依赖；自建包管理器；开发版冒充发行版；账号凭据迁移；无关目录清理；未经批准的仓库外写入。

## Further Notes
用户已确认整体方向及通用更新方案；仓库要求的门禁一待完整展示后确认。新功能分支、开发方式和审查方式随门禁一确认；正式发布与合并按门禁二执行。
