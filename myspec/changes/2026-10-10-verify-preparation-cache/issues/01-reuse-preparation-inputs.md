# 01: 验证准备复用相同输入且保留执行前新鲜读取

**What to build:** 让一次统一验证在任何检查启动前减少相同输入的重复内容读取和 Git（版本管理）清单查询，同时保留原缓存键、安全与错误语义，以及检查执行前独立重新读取。

**Blocked by:** None (can start immediately after Gate 1 confirmation).

**Status:** ready-for-agent

- [ ] 仅在一次验证的串行准备阶段以局部字典复用相同规范输入摘要和相同 Git 可见清单；不用修改时间、不跨调用、不持久化、不扩为任意文件缓存层。
- [ ] 稳定输入与固定基线缓存键完全等值，准备重复读取和清单查询减少；全部身份字段和完整内容摘要保持。
- [ ] 第二次验证能发现同尺寸且保留修改时间的内容变化；未命中检查在执行前独立重新计算缓存键，准备之后的变化进入最终成功缓存身份。
- [ ] 通配符新增、删除、忽略文件、显式路径、缺失、越界和读取错误保留原行为。
- [ ] 预算到期仍停止，失败、超时与未启动检查不写成功缓存。
- [ ] 复用现有缓存测试、同一统一验证命令真实入口及固定基线快速验证，保存最小红绿、计数、键等值和计时证据；不增加验证入口或框架。
- [ ] 云端单实施者串行实施，最后由独立审查者审固定差异；交付仅候选提交及证据，不合入主干、不发布、不更新安装副本。

**Approved boundary:** 用户已知准备首次读取快照非原子，验证期间不同时修改工作区。门禁一待完整展示并确认。

**Public seam:** 现有 `build-and-verify verify`（统一验证命令）；现有 `run_verify`（验证调用）进程内入口用于内容/文件系统/Git边界证据。
