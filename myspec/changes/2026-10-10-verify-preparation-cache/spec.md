# 验证准备阶段复用相同输入

**状态：** ready-for-agent
**来源：** 2026-10-10 用户批准的最小验证准备优化方案；门禁一待确认

## Problem Statement

统一验证在启动检查前反复读取相同目录、计算完整内容摘要并查询相同的 Git（版本管理）可见文件清单。Windows（操作系统）只读计时中，37 个缓存键准备耗时 9.203 秒，总准备耗时 9.359 秒；229 项输入产生 5066 次文件读取、568 MB 内容读取和 71 次 Git 查询。核心业务检查已独立通过，但统一入口准备成本仍影响现有 60 秒预算。

## Solution

仅在一次验证、任何检查启动前的串行准备阶段，以局部字典复用相同规范输入的完整内容摘要及相同 Git 可见清单。准备结束即结束这批复用状态的使用；每个缓存未命中的检查在执行前仍独立重新计算缓存键。验证期间工作区保持稳定。

## User Stories

1. 作为运行验证的开发者，我希望相同输入在准备阶段只读取一次，减少重复工作。
2. 作为缓存结果使用者，我希望稳定输入产生与原实现相同的缓存键，保留全部缓存身份字段。
3. 作为开发者，我希望下一次验证能发现同尺寸且保留修改时间的内容变化。
4. 作为开发者，我希望准备结束后、检查执行前的变化仍被执行阶段的新鲜读取发现。
5. 作为开发者，我希望通配符文件增删、忽略文件、显式路径、缺失、读取错误和越界保护保持原语义。
6. 作为本机验证使用者，我希望预算到期仍停止剩余检查，超时、失败和未启动项不写成功缓存。

## Implementation Decisions

- 复用现有运行器、输入散列和 Git 可见清单接缝，不引入外部使用契约、命令、依赖、服务或通用缓存框架。
- 相同规范输入指整体输入的原有规范路径；不扩大为不同输入之间任意重叠文件的字节摘要缓存。
- 保留检查标识、命令、配置、运行身份、Python（实现语言）版本、框架版本、缓存版本及输入路径/类型/完整 SHA-256（内容摘要）字段。
- 输入路径仍经过现有安全检查；仅成功的整体摘要被复用，读取错误不改成缺失或成功结果。相同 Git 查询的结果仅在本次准备使用。
- 不把准备复用状态传进检查执行或线程，不跨调用、持久化，也不用修改时间代替完整内容摘要。
- 准备首次读取快照不是原子快照；用户已批准验证期间不同时修改工作区的边界。已缓存检查的准备选择依赖该稳定工作区约束；未命中检查保留执行前新鲜读取。
- 本票只优化现有 `run_verify`（验证调用）的串行准备阶段；云端/持续集成旧调度路径保持原流程，不新增准备阶段。

## Testing Decisions

- 最高层真实用户入口是现有 `build-and-verify verify`（统一验证命令）。最终从候选源码提供的同一命令入口做成功、失败与超时冒烟，不覆盖正式安装。
- 复用现有缓存测试的 `run_verify`（验证调用）进程内入口；在文件系统和 Git 进程边界记录准备读取次数，比较固定基线与候选的稳定输入缓存键及读取成本，不新增测试框架。
- 最少验证：稳定输入新旧缓存键等值且重复读取减少；第二次调用的同尺寸/保留修改时间内容变化仍失效；准备后修改在执行前重新读取；现有通配符增删、忽略、显式路径、安全越界和读错保护；预算到期停止且不写失败缓存。
- 正式仓库验证复用既有固定基线快速验证，必须 `passed`（通过）且检查项非空；云端证据不能替代下游 Windows 的 60 秒验收。

## Out of Scope

不修改主规格、不发布、不合入主干、不更新安装副本；不修改下游魔兽仓库或现有检查清单、引擎依赖、60 秒预算；不涉及暂停的数据中心任务；不修复既有文档输入未覆盖测试说明的问题。
