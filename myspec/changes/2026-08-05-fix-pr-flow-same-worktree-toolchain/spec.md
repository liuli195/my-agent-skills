# PR Flow 同工作树工具链阻断

## Problem Statement

开发模式下，工具链身份使用源码工作树的当前提交。若 PR Flow（拉取请求流程）的目标工作树就是该源码工作树，PR Flow 自动提交工具链记录后会改变源码提交；下一轮身份读取又得到新的提交，最终同步失败并可能反复生成工具链同步提交。失败发生前，用户无法从公开停止结果得知必须使用隔离工作树。

## Solution

PR Flow 在工具链身份读取阶段识别工具链工作树冲突：当开发工具的源码工作树与目标工作树相同时，在任何受管文件写入、暂存、提交或 PR 操作前安全停止，并输出稳定的停止原因、相关工作树信息和可执行的隔离恢复路径。目标工作树不同时继续使用现有工具链同步行为。

## User Stories

1. 作为在开发模式下运行 PR Flow 的维护者，我希望同一工作树被明确识别为工具链工作树冲突，以便流程不会进入自引用同步循环。
2. 作为遇到工具链工作树冲突的维护者，我希望看到源码工作树、目标工作树和隔离恢复提示，以便能直接选择正确的工作路径。
3. 作为运行 `init`（初始化）的维护者，我希望冲突在创建或更新受管文件前被发现，以便初始化不会留下无法稳定同步的工具链记录。
4. 作为运行 `complete`（收尾）或 `tweak`（小改）的维护者，我希望冲突在提交工具链记录、创建或同步 PR（拉取请求）前被发现，以便现有工作区和远端状态保持不变。
5. 作为使用隔离目标工作树的开发模式维护者，我希望工具链记录仍能固定当前受信任源码身份，以便现有 PR Flow 行为保持兼容。
6. 作为使用发布版工具的维护者，我希望本次冲突检查不改变发布版工具链行为，以便正常的版本固定和 CI（持续集成）验证继续工作。
7. 作为维护旧 PR Flow 仓库的维护者，我希望未显式初始化工具链的仓库继续获得原有升级提示，而不是被隐式迁移。
8. 作为仓库维护者，我希望公开命令测试证明停止路径没有文件、暂存区、提交历史或 GitHub（代码托管平台）PR 副作用，以便该安全边界可回归验证。

## Implementation Decisions

- 工具链身份读取模块接收目标工作树，并以该目录作为两个工具 `doctor`（诊断）的执行目录；不得依赖调用进程当前目录推断目标。
- 对开发模式身份先读取诊断结果中的开发源码绑定关系，再进行完整身份字段校验；即使源码提交尚未发布且诊断身份字段不完整，也必须优先报告工具链工作树冲突。
- 工具链工作树冲突使用专用停止原因 `toolchain_same_worktree_unsupported`，复用现有停止状态、持久化状态和恢复命令输出机制。
- `init`、`complete` 和 `tweak` 复用同一身份读取接缝；冲突检查必须位于任何受管工具链文件写入或提交之前。
- 不修改 MySpec（自有规格）和 Build and Verify（构建与验证）的 `doctor` 规则，不改变工具身份记录格式，不尝试在同一工作树中定义新的身份收敛规则。
- 隔离工作树、发布模式、旧仓库升级提示及现有工具链同步提交行为保持不变。
- 用户文档明确说明：开发模式工具源码工作树不能直接作为 PR Flow 目标工作树；恢复方式是使用隔离目标工作树或切换到发布版工具。

## Testing Decisions

- 最高测试接缝是 `init`、`complete` 和 `tweak` 的公开命令入口，继续复用现有 Git、工具诊断和 GitHub CLI（命令行程序）替身。
- 回归测试必须覆盖：同一工作树冲突、隔离工作树、发布模式、`--project` 与调用进程目录不同，以及源码提交尚未发布但绑定关系仍可读取的场景。
- 同一工作树场景必须断言专用停止原因、恢复信息、受管文件字节、暂存区、提交数量和 GitHub 调用均未发生变化。
- 现有工具链版本变化的有界同步测试必须继续通过；不以私有辅助函数测试替代公开命令测试。
- 实施后先运行针对 PR Flow 的快速回归，再使用 Build and Verify（构建与验证）快速验证，并从真实 PR Flow 用户入口执行同工作树停止和隔离工作树继续的最小冒烟。

## Out of Scope

- 不支持在同一工作树中继续完成 PR Flow。
- 不重新定义工具身份为“最近一次修改工具源码的提交”，不引入辅助工作树、临时提交或跳过工具链记录的例外路径。
- 不修改工具生命周期、工具 `doctor`、npm（软件包管理器）安装模式、GitHub 规则集或远端权限。
- 不改变 PR Flow 的多工作树清理、合并、热修复和发布流程。
- 不自动创建、推送或删除任何用于恢复的分支或工作树。

## Further Notes

本变更修复 GitHub Issue #286。当前根因是工具身份与同一工作树自动提交之间不存在稳定收敛点；本变更选择安全阻断，而不是扩大身份模型。
