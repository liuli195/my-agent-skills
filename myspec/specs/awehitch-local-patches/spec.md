# awehitch-local-patches Specification

## Purpose

让本机安装的第三方包 awehitch 在 `npm update` 或重装冲掉全部本地改动之后，仍能通过一条幂等命令恢复全部必要修复；并让每一处修复各自的外部可观察行为有据可查、有检查可依。

## Requirements

### Requirement: 本地补丁可通过一条幂等命令重放

系统 MUST 提供 `scripts/awehitch-local-patches.ps1`（本地补丁重放脚本），使本机对第三方包 awehitch 的本地补丁在丢失后能够重放。该脚本 MUST 逐项报告每处补丁的自检结论，MUST 幂等（重复运行不产生多余写入），且 MUST 在无法确认某处补丁是否可安全应用时停止对该处的改动。

#### Scenario: 升级后重放

- **WHEN** 开发者升级或重装第三方包 awehitch，本地补丁全部丢失，随后运行该脚本
- **THEN** 脚本 MUST 重新打上全部补丁
- **THEN** 脚本 MUST 逐项报告每处补丁的结论

#### Scenario: 重复运行不产生多余写入

- **WHEN** 全部补丁均已存在时再次运行该脚本
- **THEN** 脚本 MUST NOT 改写任何已打过补丁的文件
- **THEN** 脚本 MUST 逐项报告该处已存在并跳过

#### Scenario: 无法确认时不动手

- **WHEN** 某处补丁的定位锚点无法唯一命中，或所需文件缺失
- **THEN** 脚本 MUST NOT 修改该文件
- **THEN** 脚本 MUST 列出该项要求人工确认，并以非零退出码结束
### Requirement: 补丁前保留可还原的原件

系统 MUST 在改动第三方包文件之前，把原件备份为同目录下的 `.orig` 文件；已存在的备份 MUST NOT 被覆盖，以保证重放始终从原件出发。

#### Scenario: 多次重放后原件仍可还原

- **WHEN** 脚本被多次重放
- **THEN** 各处 `.orig` 备份 MUST 保持首次备份时的原件内容
### Requirement: 渲染出的客户端技能与模板保持一致

系统 MUST 在每次重放时，把模板的渲染结果与已安装的两份客户端技能逐一对比：不一致时重写，一致时 MUST NOT 写入。任一处模板补丁未能应用时，系统 MUST NOT 执行重渲染。

#### Scenario: 模板已变

- **WHEN** 模板内容与已安装技能不一致
- **THEN** 系统 MUST 用渲染结果重写该技能

#### Scenario: 已一致

- **WHEN** 模板内容与已安装技能一致
- **THEN** 系统 MUST NOT 写入

#### Scenario: 模板补丁未能应用

- **WHEN** 任一处作用于模板的补丁被判为无法应用
- **THEN** 系统 MUST NOT 重渲染，以免用未打全补丁的模板覆盖已装好的能力
### Requirement: 浏览器自动化的点击在本机缩放异常下仍然生效

系统 MUST 在浏览器启动参数中固定缩放因子，使 ChatGPT 页面上的输入框与连接器表单可被点击。

#### Scenario: 本机浏览器报告异常缩放

- **WHEN** 本机浏览器在 ChatGPT 页面上报告出不等于 1 的设备像素比
- **THEN** 页面上的输入框与连接器表单的点击 MUST 生效
### Requirement: 技能指引按工作区取连接器名

渲染出的客户端技能 MUST 包含「按当前工作区取连接器名」的指引，说明该名字随工作区而异，并给出获取它的命令。技能 MUST NOT 让读者依赖渲染时写死的名字。

#### Scenario: 同一账号下存在多个连接器

- **WHEN** 渲染后的技能在一个与渲染时不同的工作区被阅读
- **THEN** 技能 MUST 指引先获取当前工作区的连接器名，再替换正文中出现的名字
### Requirement: 长消息的发送回读不被页面折叠标签干扰

系统 MUST 让被页面折叠的长消息在发送后仍能通过读回比对，MUST NOT 因为折叠标签混入读回内容而报告发送失败。

#### Scenario: 发送会被折叠的长消息

- **WHEN** 发送一条长到会被页面折叠的控制消息
- **THEN** 读回比对 MUST 通过，系统 MUST 报告发送成功
### Requirement: 升级与重连不改动客户端的用户级配置

系统 MUST NOT 向 Codex 的用户级配置写入 awehitch 条目。客户端的接入状态 MUST 依据该工作区的项目级配置判定。

#### Scenario: 重连不改动用户级配置

- **WHEN** 开发者执行 `awehitch up`（重连）
- **THEN** 用户级 Codex 配置文件 MUST 逐字节不变

#### Scenario: 已有项目级配置的工作区仍被识别为已接入

- **WHEN** 目标工作区已有包含 awehitch 条目的项目级配置
- **THEN** 诊断 MUST 报告该客户端已接入
### Requirement: 陈旧的运行记录不阻塞重新连接

系统 MUST 在运行记录所记进程已不存在时，把该记录判为失效并视为「未运行」，MUST NOT 因为该记录所记端口被其他实例占用而判为「状态不明」；当所记进程仍存在、而该端口上的服务不属于本工作区时，系统 MUST 仍判为「状态不明」并拒绝据此启动。

#### Scenario: 进程已死且端口被其他实例占用

- **WHEN** 本工作区的运行记录所记进程已不存在，而该记录所记端口上响应的服务属于另一个实例
- **THEN** 状态查询 MUST 报告该服务未运行
- **THEN** 重连 MUST NOT 因该记录被拒绝

#### Scenario: 进程仍在但端口服务不属于本工作区

- **WHEN** 运行记录所记进程仍然存在，而该端口上的服务不属于本工作区
- **THEN** 状态查询 MUST 报告「状态不明」
- **THEN** 系统 MUST NOT 据此启动新的服务实例
### Requirement: 技能中的重新连接流程与真实可用链路一致

渲染出的客户端技能 MUST 给出可执行的重新连接流程：先做一次最小往返探测；探测成功即视为已连接；失败则运行连接器重建命令后重试。该流程 MUST NOT 以修复标志位作为触发条件，MUST NOT 保留以「本地状态全绿」为前提的门禁。

#### Scenario: 阅读渲染后的重新连接一节

- **WHEN** 阅读渲染后的技能中的重新连接一节
- **THEN** 该节 MUST 含上述三步流程
- **THEN** 该节 MUST NOT 引用修复标志位，也 MUST NOT 以本地状态门禁作为前置条件
### Requirement: 发往 ChatGPT 的文本能通过发送通道

系统 MUST 保证技能中所有需要发送的文本块以 `[C2C]` 开头，且在按最长连接器名渲染后不超过 1024 字节。引导词 MUST 保留当前工作区的连接器名。

#### Scenario: 按最长连接器名渲染

- **WHEN** 按允许的最长连接器名渲染技能
- **THEN** 每一个需要发送的文本块 MUST 以 `[C2C]` 开头
- **THEN** 每一个需要发送的文本块 MUST 不超过 1024 字节
- **THEN** 引导词 MUST 含该连接器名
