# Cloud Development Environment

## Purpose

通过统一入口重建和更新云端公共工具、技能与项目依赖，复用三个仓库的初始化能力。

## Requirements

### Requirement: 云端公共环境统一初始化
系统 MUST 通过同一初始化入口安装声明的通用 NPM 包和已发布技能，并记录实际版本。依赖客户端市场的技能在云端使用已发布内容与目录链接；同一技能仅保留一个运行来源。

#### Scenario: 首次安装及重复初始化
- **WHEN** 用户在已批准的安装根运行初始化
- **THEN** 系统按显式版本或首次解析的最新正式发布版安装，并在重复调用时复用已记录版本；只采用正式发布版本，不回退到开发分支或源码 HEAD

#### Scenario: 未发布可选技能及安装冲突
- **WHEN** data-store 尚未发布，或目标技能位置已有其他安装
- **THEN** 未发布的可选技能记录为待补装且不阻塞基础初始化；冲突位置停止且不覆盖用户内容
### Requirement: 云端公共环境通用更新
系统 MUST 提供通用更新入口以同步声明，并仅在用户显式选择来源时升级至其最新发布版本，不擅自改动项目依赖锁文件。

#### Scenario: 同步声明或升级指定来源
- **WHEN** 用户运行 update，或运行 update --latest --only 指定来源
- **THEN** 普通更新遵循声明并复用未改变的版本；显式升级仅更新指定来源，已发布的可选技能可通过同一入口补装
### Requirement: 云端项目初始化复用既有能力
系统 MUST 支持技能、魔兽插件和量化仓库的项目初始化，Windows 调用既有准备入口，Linux 准备 Python 3.12 与声明的 Node 依赖，不将 Linux 准备声明为完整 Windows 游戏工具链。

#### Scenario: Git 链接工作树准备环境
- **WHEN** 用户通过 Git 创建工作树后显式调用初始化
- **THEN** 依赖及运行时声明一致且主环境有效时复用共享环境；缺失、过期或不一致时失败退出，不从链接工作树修改主环境
### Requirement: 云端初始化尊重操作边界
系统 MUST 将 Git 工作树生命周期与初始化显式衔接，安装失败返回非零状态；MCP、账号凭据迁移和未获准的外部目录清理不属于初始化职责。

#### Scenario: 已有内容和失效链接
- **WHEN** 初始化遇到冲突安装或失效的受管技能链接
- **THEN** 系统报告具体位置并停止成功状态，保留现场，外部创建和删除必须先获得相应授权
