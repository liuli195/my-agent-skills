# Cloud Development Environment

## Purpose

通过统一入口准备和同步已声明项目环境，复用原有Windows和Linux项目依赖准备；插件生命周期与数据接入由各自现有公开能力承担。

## Requirements

### Requirement: 云端公共环境统一初始化

统一初始化入口 MUST 仅准备清单中已声明项目的环境，使用 Python 3.12，保留 init 操作、必填的 --project 与可选的 --manifest；未指定项目不得报告成功。入口 MUST 不下载插件、不安装受控全局软件包、不导出技能发现链接，不从旧安装记录恢复插件来源、运行资源或发现状态，也不以提供全套插件运行包作为准备项目环境的前提。

#### Scenario: 首次和重复项目初始化

- **WHEN** 用户显式指定已声明项目，首次或重复执行 init
- **THEN** 系统调用该项目原有环境准备能力；正常完成时只报告项目环境准备就绪，不重新下载退役来源、生成旧安装状态或重新导出历史技能链接，也不将此结果称为插件或业务运行验收完成

#### Scenario: 旧输入或未知项目

- **WHEN** 用户未指定项目，传入已移除的公共目录、运行包、发现或选择升级参数，清单含退役来源、公共软件包、可选技能、发现、运行资源或绑定键（即使为空），或项目未声明、配置含未知键或结构错误
- **THEN** 系统明确返回非零错误，在执行项目环境准备和产生准备写入之前停止，不静默忽略旧输入后报告成功
### Requirement: 云端公共环境通用更新

统一入口 MUST 保留 update 操作，并仅同步已声明项目依赖；init 和 update 均不表示升级所有依赖至最新版本。项目依赖和锁文件变化 MUST 沿用原有准备与复用行为，项目级软件包安装保留。插件上传、安装、更新及发现 MUST 使用原生插件能力和插件同步的现有流程，而非由项目环境初始化承担；旧历史记录不能成为更新指令或运行来源。

#### Scenario: 项目环境同步与复用

- **WHEN** 用户对已声明项目执行 update
- **THEN** 系统调用原项目依赖准备能力，依赖未变且现有环境有效时复用；依赖变化时按原声明同步，不解析公共来源或插件的最新版本，不恢复旧安装状态
### Requirement: 云端项目初始化复用既有能力

系统 MUST 支持技能、魔兽插件和量化仓库的项目初始化，保留项目声明的依赖文件、项目级 npm 开关和 Windows 既有准备命令。Windows MUST 调用既有准备入口，Linux MUST 复用既有项目环境能力准备 Python 3.12 与声明的 Node 依赖，不新增安装器，也不将 Linux 准备声明为完整 Windows 游戏工具链或 Windows 原生验收。

#### Scenario: Git 链接工作树准备环境

- **WHEN** 用户通过 Git 创建工作树后显式调用初始化
- **THEN** 依赖及运行时声明一致且主环境有效时复用共享环境；缺失、过期或不一致时失败退出，不从链接工作树修改主环境，也不复制整套虚拟环境
### Requirement: 云端初始化尊重操作边界

系统 MUST 将 Git 工作树生命周期与初始化显式衔接；MCP、账号凭据迁移、真实业务数据迁移和未获准的外部目录清理不属于初始化职责。项目准备失败 MUST 返回非零且不报告就绪，允许保留安装中产生的真实部分状态，不承诺回滚。初始化 MUST 不因历史目录或失效技能链接仍存在就自动导入、恢复、替换或清理；历史资产清理由独立精确授权承担。

#### Scenario: 项目安装失败

- **WHEN** 项目依赖安装或原准备命令失败
- **THEN** 系统返回非零并报告失败，不报告环境就绪；保留真实部分状态而不虚构全局回滚成功

#### Scenario: 已有内容和失效链接

- **WHEN** 环境中仍存在历史安装目录、旧安装记录或失效的受管技能链接
- **THEN** 初始化不把它们纳入当前插件运行或发现，不隐式替换或删除；任何独立清理及外部创建和删除仍须取得相应授权
### Requirement: 云端项目数据接入与环境准备分离

系统 MUST 将数据接入与环境准备分离；初始化不自动建立数据存储绑定，不迁移业务数据，不将任务临时资源变成永久项目链接。稳定绑定或显式运行目录接入由当前数据存储技能的公开能力单独承担。

#### Scenario: 仅准备项目环境

- **WHEN** 用户初始化或同步已声明项目环境
- **THEN** 系统只准备依赖，不执行数据连接或迁移，也不将环境成功报告为数据接入成功
