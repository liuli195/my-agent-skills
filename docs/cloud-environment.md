# 云端项目环境准备

统一入口只准备项目已声明的开发依赖，复用原有 Windows（视窗系统）准备脚本和 Linux（开源系统）项目环境模块。不安装系统运行时，不处理登录凭据，不修改命令解释器配置。

## 初始化及更新

使用 Python（编程语言）3.12，在 `scripts/cloud-environment.json` 已声明的项目上运行：

```sh
python scripts/cloud_bootstrap.py init --project <项目目录>
python scripts/cloud_bootstrap.py update --project <同一项目目录>
```

`--project` 必填。可用 `--manifest <项目环境清单.json>` 指定其他清单；省略时读取脚本旁的生产清单。项目按 Git（版本管理）远端 origin（来源）地址匹配，未知项目明确失败，不执行准备。

`init`（初始化）与 `update`（同步）都只同步已声明依赖，不表示升级到最新版本。Windows 继续运行项目原有准备命令；Linux 复用 `project_environment.py`，根据依赖及锁文件内容复用或同步项目虚拟环境和项目级 npm（软件包管理器）依赖。原有共享工作树环境规则不变。

## 清单及退役接口

清单只接受顶层 `projects`（项目）对象；每个项目只接受 `requirements`（依赖文件列表）、`npm`（是否准备项目级软件包，布尔值）和 `windows_setup`（原有 Windows 准备命令列表）。生产清单保留三个项目的依赖及准备命令，不再声明自动数据绑定。

旧 `--root`、`--runtime-manifest`、`--latest`、`--only`、`--skills-dir` 参数已移除，传入即由参数解析器拒绝。旧来源、公共软件包、可选技能、发现、运行包及绑定配置，即使为空也明确拒绝；未知配置键和结构错误同样在任何准备之前失败，不静默忽略。

初始化不下载插件、不安装受控全局软件包、不导出技能发现链接，不读取或恢复旧 `installed.json`（安装状态文件）。首次初始化、重复初始化及同步都不会重新安装退役来源，也不清理历史目录和链接。插件内容上传、安装、更新及发现使用原生插件能力和插件同步的现有流程；旧资产仅按独立精确清理授权移除。

## 项目数据接入

环境准备不自动绑定数据存储，也不迁移业务数据。需要稳定绑定或显式运行目录时，按当前数据存储技能的公开能力单独执行。任务临时资源不能成为永久项目链接；项目桥接及真实迁移仍须各自的范围和授权。

## 失败与验证

缺少项目、旧参数、旧配置、未知配置或未知项目等前置错误不执行环境准备。安装阶段失败返回非零，不报告 `ready`（就绪）；可能保留真实部分状态，不承诺回滚。成功只表示项目环境准备成功，不表示插件安装、客户端发现、数据接入或业务运行已验收。

沿用现有构建验证入口、检查标识、并发和60秒预算。既有单条真实初始化主线在无依赖下载的受控项目上验证首次准备、再次初始化与同步复用，且保留业务哨兵；数据存储由其独立公开入口测试承担。Windows 分派检查不替代 Windows 原生准备验收。
