# Codex（代码代理）子代理能力与 subagent-policy（子代理策略）差异调研

> 调研日期：2026-08-16  
> 范围：Codex（代码代理）本地客户端的直接子代理调用、Custom Agent（自定义代理）配置，以及当前 `subagent-policy`（子代理策略）的契约差异。  
> 结论基准：OpenAI 官方文档、当前会话实际能力和本仓库 Skill（技能）源码。
>
> 后续决定：同日已授权把策略改为固定四个角色、模型、思考强度和读写边界的通用契约，并把宿主差异放入每次委派提示词。下文保留变更前契约的差异分析作为决策依据。

## 1. 结论

Codex（代码代理）有两种相关能力：

1. 主 Agent（代理）可以为一次具体任务直接创建通用子代理，指定任务、模型和思考强度，再等待、追问或中断。
2. Codex（代码代理）可以通过个人或项目 TOML（配置文件）预先定义具名 Custom Agent（自定义代理），固定角色说明、模型、思考强度、沙箱和部分资源配置。

第二种能力可以覆盖 `subagent-policy`（子代理策略）的大部分角色配置，但不能原样满足全部契约。当前环境也尚未创建任何 Codex Custom Agent（Codex 自定义代理）文件，因此现在只有第一种通用直接调用可以使用；按现行策略，固定角色委派仍应停止。

## 2. 官方能力

### 2.1 主 Agent（代理）直接调用子代理

OpenAI 官方文档说明：

- 当前 Codex（代码代理）版本默认启用子代理工作流。
- 用户可以直接要求 Codex（代码代理）委派；适用的 `AGENTS.md` 或 Skill（技能）也可以要求委派。
- 主 Agent（代理）负责创建、追加指令、等待、汇总和关闭子代理。
- 适合彼此独立、边界明确的调查、审查和实现任务；共享可写资源的并行任务容易冲突。
- 子代理默认继承父会话的权限状态；父会话中的实时权限调整会再次作用到子代理。

来源：[OpenAI 官方 Codex 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[OpenAI 官方 Multi-agent（多代理）说明](https://developers.openai.com/api/docs/guides/responses-multi-agent)。

本次会话提供的直接调用入口可以设置：

- 任务名称和任务说明；
- 传入多少轮主会话上下文；
- 模型和思考强度；
- 后续追加任务、中断、等待和查看状态。

本次会话没有在直接调用入口中提供：

- 具名固定角色选择字段；
- 每次调用独立设置只读或可写权限的字段；
- 精确工具白名单；
- Extension（扩展）开关；
- Skill（技能）预加载字段。

因此，直接调用适合临时并行任务，但不能仅靠一次提示词证明固定角色契约。

### 2.2 固定 Custom Agent（自定义代理）

Codex（代码代理）官方支持两处配置目录：

```text
~/.codex/agents/       # 个人 Custom Agent（自定义代理）
.codex/agents/         # 项目 Custom Agent（自定义代理）
```

每个 TOML（配置文件）必须包含：

- `name`（名称）；
- `description`（使用说明）；
- `developer_instructions`（开发者指令）。

还可以设置：

- `model`（模型）；
- `model_reasoning_effort`（思考强度）；
- `sandbox_mode`（沙箱模式）；
- `mcp_servers`（模型上下文协议服务）；
- `skills.config`（技能配置）。

模型和思考强度写在 Custom Agent（自定义代理）文件中时优先于临时调用值。未配置的内容从全局子代理配置或父会话继承。

Codex（代码代理）还自带 `default`（默认）、`worker`（工作者）和 `explorer`（调查者）三个角色。自定义同名角色可以覆盖内置角色，但官方文档没有提供“只允许某四个角色”或“逐个禁用其他内置角色”的配置。

来源：[OpenAI 官方 Codex 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。

### 2.3 固定配置不等于固定决策

Custom Agent（自定义代理）的 `description`（使用说明）用于告诉 Codex（代码代理）何时选择该角色，但这仍是模型根据任务作出的选择，不是确定性的路由表。

若流程必须固定选择某个角色，最可靠的现有方式是由 `AGENTS.md`、Skill（技能）或用户指令明确点名该 Custom Agent（自定义代理）。官方配置没有单独的“任务类型到角色”固定决策表，也没有角色选择优先级规则。

## 3. 与 subagent-policy（子代理策略）的逐项对照

现行契约见 [`plugins/subagent-policy/skills/subagent-policy/SKILL.md`](../../plugins/subagent-policy/skills/subagent-policy/SKILL.md)。

| 策略要求 | 直接调用 | Custom Agent（自定义代理） | 评估 |
| --- | --- | --- | --- |
| 四个固定角色及描述 | 只能临时写入任务说明 | `name`、`description`、`developer_instructions` 可固定 | Custom Agent（自定义代理）基本满足 |
| 固定模型 | 每次调用可指定，但可被调用者改变 | 文件中的 `model` 优先 | 满足，但 Pi（编码代理）模型名需要映射为 Codex（代码代理）模型名 |
| 固定思考强度 | 每次调用可指定 | 文件中的 `model_reasoning_effort` 优先 | 满足 |
| 调查、审查和架构角色只读 | 直接入口不能单独设置 | 可使用 `sandbox_mode = "read-only"` | 部分满足；父会话实时权限可能覆盖静态默认值 |
| 精确工具和资源范围 | 继承当前会话工具 | 可配置部分 MCP（模型上下文协议）服务与 Skill（技能） | 部分满足；官方文档未给出完整内置工具白名单 |
| `prompt_mode: append`（追加提示词模式） | 无对应字段 | 使用 `developer_instructions`（开发者指令）配置层 | 语义接近，但没有同名且可核验的精确字段 |
| Implementer（实施者）禁用 Extension（扩展） | 无对应字段 | 官方 Custom Agent（自定义代理）结构未提供 `extensions` 字段 | 不满足 |
| Implementer（实施者）预加载 TDD（测试驱动开发） | 无预加载字段 | 支持 `skills.config`（技能配置），但官方文档没有承诺强制预加载或强制调用 | 部分满足 |
| 默认代理禁用、只保留四个角色 | 无角色注册表 | 有内置 `default`、`worker`、`explorer`，只能同名覆盖 | 不满足 |
| 固定角色决策 | 主 Agent（代理）临时决定 | 可用角色说明辅助选择，也可在指令中点名 | 只有点名调用接近固定决策 |
| 子代理结果验收 | 主 Agent（代理）可检查返回结果和共享工作区 | 同左 | 能力支持，但仍需主 Agent（代理）执行验证 |

## 5. 主要差异

### 5.1 策略混入了 Pi（编码代理）专有字段

`openai-codex/...` 模型前缀、`prompt_mode`（提示词模式）、`extensions`（扩展开关）和 `skills: tdd`（技能预加载）属于现行 Pi（编码代理）契约表达。Codex（代码代理）使用不同的配置字段，不能做逐字匹配。

### 5.2 Codex（代码代理）固定的是角色配置，不是选择结果

Codex（代码代理）可以固定角色文件，但默认仍由模型参考角色说明选择。若需要流程级确定性，调用方必须明确点名角色；不能仅依赖 `description`（使用说明）。

### 5.3 Codex（代码代理）的权限继承比策略假设更强

Custom Agent（自定义代理）可以声明只读沙箱，但子代理同时继承父会话权限，父会话的实时权限调整优先。策略若要求“无论父会话如何都必须只读”，还需要额外的运行时检查，不能只检查静态文件。

### 5.4 官方角色集合不能收窄为恰好四个

Codex（代码代理）内置三个角色。当前官方配置能覆盖同名角色，却没有内置角色允许清单。因此“默认代理已禁用、没有未登记角色、只启用四个角色”无法按原文证明。

## 6. 满足程度

- 直接调用路径：满足临时任务委派、模型、思考强度、并行编排和结果回收；不满足固定角色身份、固定权限和固定资源。
- Custom Agent（自定义代理）路径：满足角色名称、描述、提示词、模型、思考强度和基础沙箱；部分满足资源与 Skill（技能）配置；不满足原样的 Pi（编码代理）字段、角色允许清单和确定性自动选角。
- 当前环境：尚未配置 Custom Agent（自定义代理），因此现行 `subagent-policy`（子代理策略）应继续在固定角色委派前停止。

## 7. 若要适配，最少还缺什么

1. 为 Codex（代码代理）定义独立 Adapter（适配器），明确 Pi（编码代理）字段到 Codex（代码代理）字段的映射，不直接修改原含义。
2. 在个人或项目 `.codex/agents/` 下配置四个具名 Custom Agent（自定义代理）。
3. 让调用 Skill（技能）明确点名角色，避免依赖模型自行选择。
4. 在每次委派前读取实际角色文件和父会话实时权限，尤其验证只读角色没有被父权限覆盖。
5. 决定三项无法精确映射的要求如何处理：`prompt_mode: append`（追加提示词模式）、`extensions: false`（禁用扩展）、“只启用四个角色”。这是规则语义变更，必须单独获得授权。
6. 对 Implementer（实施者）增加可核验的 TDD（测试驱动开发）加载与实际调用证据；仅让 TDD（测试驱动开发）Skill（技能）可见还不够。
